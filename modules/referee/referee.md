# 裁判接收快照与 UI 接入

本文说明裁判接收初始化、只读快照、分组期限和可选 UI 的调用关系。协议唯一基线为官方 RoboMaster 2026 高校系列赛通信协议 V2.0.0（2026-06-26）；字段页码、PDF 指纹和本轮验证记录见 [MC02-0094 任务记录](../../docs/workflow/tickets/MC02-0094.md)。任务状态只在 [TODO](../../.Doc/TODO.md) 维护。

## 接收初始化和快照读取

先调用一次 `RefereeInit(&huart, config)` 注册UART并启动接收。`config == NULL` 使用默认期限；自定义配置须将四组期限设为1～`INT32_MAX`毫秒。初始化会复制配置，后续修改调用者的配置结构不影响运行中的期限。资源或配置失败会返回明确状态；UI是否可用不影响接收初始化。

接收解析只发布本工程支持的21个命令。读者使用 `RefereeGetSnapshot(&copy)` 一次复制所有命令数据、接收时间、年龄、接收计数、线上序号和链路诊断。复制读取不消费数据，也不续期。未初始化时接口清零输出并返回错误；空输出返回参数错误。

每条命令的数据状态为：

| 状态 | 含义 | 调用约定 |
|---|---|---|
| `REFEREE_DATA_UNSEEN` | 尚未收到合法帧 | 不读取数值作为当前值 |
| `REFEREE_DATA_FRESH` | 周期命令在独立期限内 | 可按本模块调用方策略读取 |
| `REFEREE_DATA_EXPIRED` | 已有记录，但来源时间超过本组期限 | 数值保留供诊断，不代表当前值 |
| `REFEREE_DATA_EVENT_RECORDED` | 事件型命令有最近记录 | 只读记录与年龄，不当作持续许可或待执行动作 |

10Hz组 `0x0201/0x0202/0x0208` 默认300ms；3Hz组 `0x0003/0x0204/0x0209/0x020A` 默认1000ms；1Hz组 `0x0001/0x0101/0x0104/0x0105/0x0203/0x020B/0x020C/0x020D/0x020E` 默认3000ms；小地图 `0x0303` 默认3000ms。最近记录 `0x0002/0x0206/0x0207/0x0301` 不声明持续有效。整体链路在线只作300ms诊断，不能代替任何一组状态。

来源时间是组成完整帧的首个UART块所带原始RxEvent毫秒时间，0合法；它不是裁判服务器生成时间，也不是操作手触发时间。候选帧最多128字节，首字节后50ms边界内完成；连续性中断或超时会丢弃残帧。损坏帧、未知命令、长度错误、CRC错误或无效浮点不覆盖旧记录、不刷新期限。完整字段按小端显式解码；有效浮点拒绝NaN/Inf，`0x0202`前8字节和`0x020B`后8字节保留为原始字节，不解释为测量值。

固定长度严格匹配详细表。官方总表给 `0x0203` 16字节、`0x0303` 15字节，详细字段表与示例结构分别给出12字节；本工程按详细表和示例选择12字节并拒绝总表长度变体及任意额外尾部。`0x0301`机器人交互接收内容ID `0x0200～0x02FF`、0～112字节内容；检查机器人身份、同队及接收方为期限内的本机机器人。其他内容ID不发布。

`RefereeGetInteraction()`复制最近一条完整交互及首个UART接收块时间，新合法交互覆盖旧记录，读取不消费或延长有效期。`RefereeGetSnapshot()`中的交互数据只保留前五字节预览；两个读取接口分别获取，不保证跨两次调用属于同一条记录。接收记录本身不授权执行，业务须另行检查新鲜度和当前许可。发送使用`RefereeSubmit()`，入队和本机发送完成是不同结果，都不表示对端收到或执行。

当前身份检查仅验证编号、同队和本机身份，尚未核实并实施对应比赛阶段对哨兵、雷达等角色的收发方向限制；不能据此认定所有同队方向符合赛规。使用前须按实际比赛规则核对，缺口由 MC02-0022 跟踪。

## UI单独绑定

接收服务由 `RefereeInit()` 独立注册。只有机器人配置默认开启 `MC02_ENABLE_REFEREE_UI`；`bench_safe`、`rcdiag` 默认关闭。`UITaskInit()`只绑定长期有效的应用/UI状态，不注册UART。UI初始化及发送失败只停用UI刷新，不撤销裁判接收；显式再次调用 `MyUIInit()`才重新初始化。

UI身份只从新鲜 `0x0201` 建立。每次发送前再次检查机器人身份和期限；来源过期或ID变化后停止发送，不使用旧身份自动恢复。UI状态 `UI_OK` 表示构图完成，`UI_SUBMITTED` 表示已复制入UART队列，均不代表客户端已经收到或显示。共享发送预算见下节；一般机器人交互接收与配置化重绘仍由相关TODO跟踪。

LCD按组读取同一份快照：未接收或过期的项目显示 `--`；组合值只有在所需数据组都新鲜时显示。功率页读取有效功率上限，不从 `0x0202` 的保留字节推算实际功率；弹速显示为最近射击记录并附年龄。

## 异步UI与发送结果（MC02-0061）

`MyUIInit()`登记请求，`UITask()`每轮最多推进一帧，先等待新鲜身份，再按原顺序发送15份初始化帧；全部本机完成后进入运行。`UIGetState()`查询不推进。相邻实际启动至少115ms，函数内部没有115ms等待。演示数据按115ms逻辑步长、原50步换档规则修改，仍不代表真实机器人业务。

`UIDelete()`、`UIGraphRefresh()`、`UICharRefresh()`末参数为`const UITxOptions_t *`，用于完成回调、启动检查、长期上下文和编号输出；传NULL可用`UIGetLastTxEvent()`查询最近默认通知。成功入队后才增加帧序号，255到0自然回绕；后来传输失败不会回退序号。`RefereeSubmit(&request, &id)`检查身份、内容和长度，统一构帧／CRC／序号后提交复制队列，UI总期限100ms，不保留第二份持久缓冲，不在入口延时。`RefereeGetTxState()`复制最近事件及累计失败数，不推进发送。

UI只保留一条未完成报文，待刷新内容合并为最新版本；完成通知只有在版本相同的时候才能清除待刷新位。队列满时保留步骤和标记，实际传输失败进入错误停止，显式重新初始化才恢复。身份在入队和实际启动前各检查一次；过期、变化或重新初始化时取消旧代请求，旧代通知不会把新流程推进到运行，已经发出的字节不能撤回。

四条队列包含等待、在途和待通知项。HAL UART TC回调只登记事件，普通UART发送任务交付最终结果；DMA搬运完成单独发生时不算发送完成。队列隔离、取消、数组生命周期与只读查询见[UART接口](../../bsp/usart/bsp_usart.h)。接收保持独立，UI禁用构建不保留UI任务和发送入口。

[UI与生产队列联测](../../tests/host/uart_ui_integration_test.c)覆盖状态与版本，[H723后端联测](../../tests/host/uart_tx_backend_test.c)覆盖停止及接收独立性，详细命令及结果见[MC02-0061](../../docs/workflow/tickets/MC02-0061.md)。本轮没有串口波形、DMA物理停止或客户端显示证据；车型布局、真实数据绑定、自动恢复重绘仍归MC02-0095，REF-03共享预算及本轮验收见下节。


## 共享发送预算（REF-03）

公开发送类型集中在[referee_tx.h](referee_tx.h)，不依赖HAL或RTOS。删除公开原始帧`RefereeSend()`及可写`UI_Seq`。请求内容在提交时复制，回调及上下文须保持到最终通知；成功入队后才递增线上序号。六类UI准确长度分别为2／15／30／75／105／45字节，机器人交互子ID为0x0200～0x02FF、内容0～112字节且同队。未接入服务器自主决策命令。

复用原UART四条存储和唯一发送任务，严格FIFO，无第二份帧队列。所有0x0301实际启动至少相隔34ms；按接收机器人在滚动1000ms内累计完整帧字节，普通机器人3720、哨兵／雷达5120。年龄恰好1000ms时释放旧记录；本机身份或UI初始化不清历史。只覆盖本机发往目标的流量，不统计其他机器。启动错误按整帧保守计费；确认未启动的取消／超期不计费，已启动后的失败不退额度。

UI原115ms启动节奏及100ms入队总期限保留。限流暂缓不续期、不让后续报文越过。尚未启动即超期保留待刷新版本／初始化步骤，下轮尝试最新内容；启动错误、已启动失败或串口隔离仍停止并等待显式初始化。`RefereeGetTxState()`复制`uart`队列统计、细分取消／过期／错误、最近限流原因与序号；统计供诊断，不当作对端确认。

协议PDF指纹、页码和验证证据见[REF-03记录](../../docs/workflow/tickets/REF-03.md)。正常固件没有自动测试流量；只在独立bench_safe具名诊断中由现有RobotTask推进有限负载。采集工具使用[固定只读对象](referee_bench.c)及准确ELF，不发送执行器控制。机器人交互接口及测试见[MC02-0022记录](../../docs/workflow/tickets/MC02-0022.md)，MC02-0095车型布局、真实数据和自动重绘保持原范围。
