# LK 电机模块

本文说明本工程 LK9025 驱动的注册和多电机发送约定。电机协议字段以对应型号的官方说明为准；本机回归只验证 MCU 侧的软件注册与组帧，不验证电机实际响应。

## 电机编号与 CAN ID

调用 `LKMotorInit()` 时，`can_init_config.tx_id` 用作电机编号，允许范围是 **1～4**。它不是最终 CAN 发送 ID。每条物理 CAN 总线最多注册四个实例，可以稀疏、乱序注册；同一总线的编号不能重复，不同总线可以使用相同编号。

所有实例都接收反馈 ID `0x140 + 电机编号`，并使用 CAN 发送 ID `0x280`。编号独立保存在 LK 实例中，组帧时固定映射如下：

| 电机编号 | 命令帧字节 | 反馈 ID 示例 |
|---:|---:|---:|
| 1 | 0～1 | `0x141` |
| 2 | 2～3 | `0x142` |
| 3 | 4～5 | `0x143` |
| 4 | 6～7 | `0x144` |

输出值按有符号16位值的二进制补码编码，低字节先发。浮点结果非有限或经过方向处理后不能表示为有符号16位命令时，本轮记为数值失败、清除 PID 历史并把对应槽位置零，不对电流命令做饱和猜测。空槽、停止实例和其他本周期控制计算失败也保持对应字节为零。各总线先独立构造完整八字节帧，再由该总线首个成功登记的实例提交一次；一条总线提交失败不会阻止其他总线发送，也不会缓存失败帧等待重放。

## 初始化与失败回退

LK 注册只允许在启动阶段串行完成，并且要早于 CAN 接收派发、Daemon 和电机控制任务运行。驱动先检查配置类型、受支持的 CAN 句柄、电机编号、重复项和总线容量；随后在栈上验证启用 PID 环的参数，再依次准备 LK 对象、Daemon 和 CAN 接收注册。

配置由 `const` 指针传入，注册不会改写它。Daemon 失败时释放 LK 候选对象；CAN 注册失败时先注销 Daemon，再释放候选对象。只有 CAN 注册成功后才发布 LK 实例、发送对象和总线计数，所以失败不会留下悬空回调或占用 LK 槽位。成功实例没有运行期注销接口，相关对象会保留到复位。

`LKMotorControl()` 的返回类型仍是 `void`。是否成功把帧交给 MCU 的 CAN FIFO，由现有 `CANGetTxStats()` 统计；该结果不表示总线上收到 ACK，也不表示电机已执行命令。

## 当前闭环范围与验证

本任务仅改注册资源回退和按物理总线组帧。角度环当前默认读取 `real_current`，速度环仍调用 `angle_PID`，速度反馈源判断仍使用角度反馈选择字段；在 [MOTOR-01](../../../.Doc/TODO.md#L164) 处理前，不应据此启用角度或速度闭环。驱动初始化后实例带有运行标记，实际使用仍须先核对电机类型、总线和控制配置。

主机回归覆盖注册分配失败、Daemon 失败、生产 CAN 滤波注册失败及回退后的重试；还验证三总线容量、同号跨总线、稀疏／乱序编号、正负与超范围帧值、FIFO 忙、HAL 错误和下一周期新值。生产 `LK9025.c`、`daemon.c`、`bsp/can/bsp_can.c` 均进入集成测试，只有 HAL、时间和日志由本机替身提供。当前没有连接开发板或实际 LK 电机，因此不对物理链路、ACK 或电机性能作结论。
