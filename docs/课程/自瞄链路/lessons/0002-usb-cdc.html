USB CDC 收发

本课目标：解释为什么异步发送的数据必须活得比发送函数更久。

调用返回，不代表发送完成

USB CDC 把设备端数据表现成主机上的虚拟串口。发送通常交给 USB 中断和端点状态机继续处理。函数返回时，硬件可能仍在读取传入缓冲区；如果这块内存是栈变量，函数退出后就可能被复用。

因此发送缓冲区要有稳定生命周期，并且在传输完成前不能改写。遇到 USBD_BUSY 时，应保留或明确丢弃本帧并计数，不能假定它已经进入 USB。

空闲 → 复制到持久缓冲 → 提交传输 → 等待完成回调 → 空闲

可以对照本工程的 USB BSP、学习笔记 16 和最近的发送缓冲修复。

试着回忆

  1. 如果异步 USB 发送仍在读取，应用能否马上覆盖同一缓冲？
  2. USBD_BUSY 表示数据已经发送成功了吗？
核对答案

不能覆盖；缓冲要等传输完成。USBD_BUSY 表示当前不能接受新发送请求，不能记成成功。
