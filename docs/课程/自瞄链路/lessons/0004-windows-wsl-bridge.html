Windows–WSL 相机及串口桥接

本课目标：把相机采集与 Linux 识别分成两个可观测的进程边界。

驱动在哪里，采集就在哪里

工业相机 SDK 常常依赖厂商驱动。若 SDK 只在 Windows 可用，可以让 Windows 进程负责枚举相机和取帧，再通过显式桥接把帧送到 WSL 中的识别程序。USB/IP 是另一条路径：设备直接附加到 WSL 后由 Linux 侧访问；同一时刻设备不能由 Windows 同时使用。

桥接需定义帧边界、图像格式、时间戳、队列上限和断连行为。队列满时丢帧或阻塞必须是明确选择；串口桥也要保持原始 SP 帧字节流，不能在中间偷偷转换字段。

Windows MVS 取帧 → 有界帧桥 → WSL recognizer
MC-02 COM → 原始 SP 串口桥 → WSL serial client

USB/IP 步骤以 Microsoft 官方说明为准；本机桥接命令记录在 WSL 部署记录。

试着回忆

  1. 设备附加到 WSL 后，Windows MVS 还能同时打开它吗？
  2. 桥接队列不限制长度，会怎样影响延迟和内存？
核对答案

不能；附加期间设备交给 WSL 使用。无界队列可能积累旧帧，让延迟与内存占用持续增长。
