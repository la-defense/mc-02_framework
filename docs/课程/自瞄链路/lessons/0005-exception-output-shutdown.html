异常先关输出

本课目标：说明为什么异常入口要先用少量直接寄存器写入关输出，再读取和记录崩溃现场。

异常入口做两件事

  1. 先让已知输出失能。 HAL tick、任务和日志可能还没初始化，也可能已经停止。BSP_SafetyLatchOutputsOff() 直接禁用中断、把 PB1 切到低电平 GPIO、停止 TIM3_CH4，并拉低 PC13/14/15。
  2. 再记录可信现场。 读取 CFSR 后，先检查异常压栈地址、帧长度和栈错误标志；不能确认安全时就标记帧无效，不读取它。

HardFault 等入口是 naked 汇编。它先保存原始 MSP/PSP 指针和 EXC_RETURN，调用低层关断，再跳到 C 记录函数。低层函数没有 HAL、RTOS、tick、日志或内部子函数。

FPU 会把 R0 帧往后移

基本异常帧包含 R0、R1、R2、R3、R12、LR、PC、xPSR，共 8 个字。浮点扩展帧会在它之前占 18 个字，所以核心寄存器 R0 从 SP + 0x48 开始。EXC_RETURN 的 bit4 为 0 时使用浮点扩展布局。

基本帧：       SP ──→ R0 ... xPSR
浮点扩展帧：  SP ──→ S0 ... FPSCR / 保留区 ──→ R0 ... xPSR
                                          偏移 18 × 4 = 0x48

MC-02 用浮点运算，因此把“前 8 个字永远是 R0 到 xPSR”当成事实会读错现场。生产代码还检查 Cortex-M7 异常帧的 8 字节对齐、链接脚本列出的 SRAM 范围，以及 CFSR 的压栈和延迟浮点保存错误位。

调度停摆后的启动兜底

如果整个调度器停止运行，守护任务也不能执行软件关断；IWDG 负责触发复位。重启后，main() 的首个用户初始化步骤调用 BSP_SafetyStartupLatchOutputsOff()，先关断已知输出，再进入 HAL 和模块初始化。它会恢复调用前的 PRIMASK，避免安全关断让后续初始化一直处于关中断状态。复位向量到达 main() 之前的引脚状态仍需实测，不能把启动兜底当成物理边界验收。

怎样验证行为

关断测试给生产模块喂入非零 PWM 和高电平的寄存器状态，再检查 BSRR、GPIO 模式、TIM3 CCR4/CCER/CEN 和中断屏蔽。压栈测试覆盖基本帧、浮点扩展帧、错位地址、超出 SRAM 的地址和 CFSR 错误位。 Error_Handler 关断测试、异常重入复位测试。

这些测试证明程序发出了预期寄存器写入，并拒绝了不可信栈地址。它们不能证明板上电压、引脚波形、供电通道或负载响应；这些需要仪表和外部限能条件。

  2. 为什么异常入口先关输出，再读取 CFSR 和异常栈？
  3. 整个调度器停摆时，谁触发复位，重启后在哪一步先关输出？
  4. 寄存器测试通过后，还缺哪类证据才能说物理输出已关断？
核对答案

R0 从 SP + 0x48 开始；bit4 为 0 表示浮点扩展帧，bit2 为 1 表示原线程使用 PSP。先关输出可避免读取崩坏的栈或使用不可用的系统服务时继续维持旧输出。物理结论还需要安全接线和外部限能条件下的电压/波形测量。
