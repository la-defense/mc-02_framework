# 车型配置与底盘逆运动学

本篇结合 MC02-0054 说明三件事：CMake怎样选择车型和模块，启动时怎样检查依赖，以及底盘运动计算怎样与电机驱动分开。

## 从一份车型声明得到固件选择

车型参数应该只有一个权威来源。构建清单声明当前车型、芯片、板卡、RTOS、底盘类型、电机驱动和启用模块；CMake根据清单生成只读配置头，源码选择、启动清单和健康查询都读取这份选择。这样可以在生成固件前发现未知兵种、未实现驱动、缺失依赖和依赖循环。

当前哨兵的底盘是四轮全向轮，但实际轮位、滚动方向、速度上限和三轴云台实现还未全部确认。因此生产固件必须拒绝构建。`bench_safe` 使用单独的构建身份，供裸板启动检查使用；测试尺寸只存在于带有明确标记的软件夹具里，不会写回哨兵配置。

## 启动时区分核心和辅助模块

构建阶段先验证每个启用模块所需的其他模块，再按依赖顺序启动。核心模块或核心依赖启动失败时，整车保持失能；辅助模块失败时记录降级，跳过依赖它的功能。比如告警灯初始化失败可以保留底盘诊断，云台所依赖的姿态输入失败则不能允许云台控制。

模块“启动已接受”只表示初始化入口成功，不表示传感器数据已经有效。数据新鲜度、实际反馈和运行许可仍由各模块自己报告，安全管理继续依据这些状态决定输出是否可以工作。

## 把运动学与电机接口分开

底盘运动学使用机器人中心的速度输入：向前为 `vx` 正，向左为 `vy` 正，绕向上轴的角速度为 `wz` 正；平移单位是 m/s，角速度单位是 rad/s。纯计算模块只接收轮子位置、滚动方向、轮半径和目标速度，输出固定轮序“左前、右前、左后、右后”的轮轴 rad/s，不调用 HAL、RTOS 或电机驱动。

麦轮和全向轮几何不同，所以分别使用独立计算文件。舵轮、轮腿和半舵已有独立接口占位，选择它们时构建应直接报错。旧应用消息仍使用原来的 mm/s、deg/s；转换集中在适配处，避免每个轮子控制分支重复换单位。

## 验证的层次

主机测试检查纯运动学的前进、侧移、自旋、组合输入、轮序和非法几何。CMake测试检查车型身份、模块依赖和未实现选项是否被拒绝。ARM固件构建检查真实编译器和链接布局。裸板测试只验证固件身份、启动状态与辅助显示关闭路径；没有连接电机时，不能据此声称轮子方向或实车控制已经验收。

MC02-0054 的 WSL Debug、Release和ASan/UBSan回归各494项通过；ASan/UBSan串行全量运行通过。带LCD与关闭LCD的 `bench_safe` ARM 构建均通过，关闭LCD时配置为 `MC02_FEATURE_LCD=0` 且源码清单不含LCD模块。当前能识别 Horco CMSIS-DAP v2，但 OpenOCD 在400 kHz下初始化返回 `CMD_INFO` 失败；本轮未读取、备份或写入Flash。

## MC02-0054 复核补充

本轮复核后，车型清单和核心模块依赖由车型构建描述维护，构建入口只筛选当前板角色并验证关系。通信派发与电机控制分开选择：`bench_safe` 仍运行协议接收解析，但不调用 CAN 发送推进；启用机器人控制的构建才提交电机和板间控制帧。

运行期失败也更新同一份模块启动快照。异步 IMU 与 LCD 初始化失败会区分核心闭包和辅助模块：核心失败锁存诊断、撤销许可并关断输出；辅助失败只记录降级并停止使用失败模块。BMI088 注册失败返回 `NULL`，主机回归分别覆盖两种姿态后端。生成配置的健康快照还要根据 USB CDC 实际使用的功能标记 USB 模块。

本次复核新增验证：分板角色下分别编译 `robot_def.c`、生成配置健康快照包含 USB、BMI088 注册失败不返回姿态地址，以及运行期辅助／核心模块失败结果。被依赖检查跳过的可选 LCD 不创建任务；LCD 初始化失败后停止后续屏幕访问。麦轮和全向轮计算文件通过独立 ARM 编译。现有 ARM 裸板固件和物理板验收状态以任务票据中的新记录为准。


## 2026-11-01 复核补充：启动时验证底盘几何与功能关闭

底盘参数即使每个字段都是有限数，也不代表轮组能产生前进、横移和自旋三个独立运动。全向轮的滚动方向还必须是单位向量，四轮一起缺少某个方向的投影时，求出的轮速无法控制完整平面运动。启动校验因此复用车型所选的运动学计算入口，使用零速度请求触发与运行期相同的几何检查；这让参数错误在许可控制前被拒绝，而不是等到第一次移动请求才暴露。

模块“未启用”也应覆盖它的运行入口。仅把 PWM 限制为零，仍可能让 INS 初始化温控 PID、读取电源并定期处理温度。现在 MC02_FEATURE_HEATER=0 时，INS 跳过温控初始化与周期更新；校准和 Flash 维护的长操作接口仍保留，用于启用温控时禁止在这些操作期间加热。

回归验证新增合法几何、非单位方向和退化轮组的启动配置用例。WSL Debug、Release、ASan/UBSan 分别 495/495 通过；禁热 bench_safe 和无 LCD ARM 构建通过。设备探针仍无法完成 CMSIS-DAP CMD_INFO，本次没有读写 Flash 或烧录，硬件验收仍未完成。

## 2026-11-01 代码审查补充：配置接口与名称

车型配置验证和发射初始化都需要根据 `Shoot_Type_e` 得到启用的摩擦轮数。把映射放在同一个配置类型接口中，避免修改一种发射机构时只改到其中一个调用位置。底盘模型也使用命名枚举，确保读取调用点时能分辨麦轮和四轮全向轮，而不必记住数字编码。修订后的 Debug、Release、ASan/UBSan 全量主机回归均为495/495通过。

## 2026-11-01 最终审查补充：模块位图和跨构建映射

模块计划里的 `enabled` 和 `required` 是位图，`dependencies[i]` 的下标是模块枚举值、内容也是前置模块位图。构建身份则通过 `layout` 格式标识和 `version` 配置版本说明自身格式。增加工作流检查，比较 C 模块枚举、CMake 生成配置顺序和健康状态下标映射；它能在增加或重排模块时发现遗漏同步。

启动结果快照也应解释各字段：失败位图、依赖阻断位图、核心失败状态和首个核心失败模块编号分别回答不同诊断问题。任务分派依据已接受启动状态，不因编译功能开关打开就调用尚未通过依赖启动的模块。

## 2026-11-01 规格复审补充：禁用视觉时裁剪其生产路径

板卡角色决定模块集合后，源码、周期调用和健康查询都要跟着同一份选择变化。底盘板未启用 VISION 时，INS 仍可提供姿态服务，但不得链接视觉发布器或调用视觉更新接口；视觉初始化、发送和健康采样也必须编译期关闭。主机回归分别验证 SP、V2 选择不会把视觉实现带入无视觉底盘角色。

最终回归在 WSL Debug、Release 和 ASan/UBSan 均通过 495/495；CMake 角色源码测试同时覆盖 SP、V2。禁热 `bench_safe` 使用仓库 ARM toolchain 完整生成 ELF／HEX／BIN，链接报告 FLASH 238336 B、RAM 117224 B、RAM_D2 16992 B、DTCMRAM 14720 B、RAM_D3 128 B。构建产物验证不代表已烧录，探针仍因 CMSIS-DAP `CMD_INFO` 失败未能开始板上读写。

## 2026-11-01 规格复审补充：禁用温控时裁剪模块路径

功能关闭应同时移除模块源码、状态采集和调用点。`MC02_FEATURE_HEATER=0` 时，构建清单不包含 `imu_heater.c`；INS、BMI088 标定与 Flash 维护、整车维护、任务初始化和 LCD 不调用温控 API，健康快照也不把未选中的温控模块记为降级。TaskMonitor 的维护期限保护仍保留，因为它约束的是长操作时限，不依赖温控功能本身。启用温控的车型仍编入温控实现，并继续使用既有维护互锁。

回归扫描器会处理 `#else`、`#elif` 和否定条件，并分别只关闭 VISION 或 HEATER，同时保持另一功能启用后检查对应调用路径，避免一个功能的宏意外替另一个功能遮住未保护调用。最终 WSL Debug、Release、ASan/UBSan 均为495/495通过，车型选择工具5/5通过。仓库 ARM toolchain 的单板禁热固件 Build ID 为 `2968558b5dd1923271b3b97059ed4f24fe9032ee`，ELF SHA-256 为 `6C238B9494A0583FD8054795A5A8B434E99A2A52D1F5CBBE603051A66977FB41`；FLASH 237116 B、RAM 117024 B、RAM_D2 16992 B、DTCMRAM 14720 B、RAM_D3 128 B。禁用 LCD 的禁热固件也通过构建，FLASH 215116 B、RAM 111696 B、RAM_D2 16992 B、DTCMRAM 14720 B、RAM_D3 128 B。两份配置都确认没有温控驱动源文件；主构建全部生产对象均无未解析温控符号。探针仍因 CMSIS-DAP `CMD_INFO` 失败而未开始板上读写，物理验收未完成。

## 2026-11-02 复审修正：独立验证功能守卫

对条件编译的测试应一次关闭一个功能，并保持其他相关功能开启。否则，错误地用温控开关保护视觉调用（或反向）可能被两个开关同时关闭的测试掩盖。现在扫描器分别以 VISION=0、HEATER=1 和 VISION=1、HEATER=0 计算 `#if`、`#elif`、`#else` 路径；LCD 温控页注释也准确说明禁用构建显示占位值。直接工具测试5/5通过，CTest 集成测试1/1通过。禁热 ARM 构建复建后产物身份与哈希不变，且没有进行任何板上 Flash 操作。
