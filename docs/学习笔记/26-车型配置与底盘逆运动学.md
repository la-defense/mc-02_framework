# 车型配置与底盘逆运动学

本篇结合 MC02-0054 说明三件事：CMake怎样选择车型和模块，启动时怎样检查依赖，以及底盘运动计算怎样与电机驱动分开。

## 从一份车型声明得到固件选择

车型参数应该只有一个权威来源。构建清单声明当前车型、芯片、板卡、RTOS、底盘类型、电机驱动和启用模块；CMake根据清单生成只读配置头，源码选择、启动清单和健康查询都读取这份选择。这样可以在生成固件前发现未知兵种、未实现驱动、缺失依赖和依赖循环。

当前哨兵的底盘是四轮全向轮，但实际轮位、滚动方向、速度上限和三轴云台实现还未全部确认。因此生产固件必须拒绝构建。`bench_safe` 使用单独的构建身份，供裸板启动检查使用；测试尺寸只存在于带有明确标记的软件夹具里，不会写回哨兵配置。

## 启动时区分核心和辅助模块

构建阶段先验证每个启用模块所需的其他模块，再按依赖顺序启动。核心模块或核心依赖启动失败时，整车保持失能；辅助模块失败时记录降级，跳过依赖它的功能。比如告警灯初始化失败可以保留底盘诊断，云台所依赖的姿态输入失败则不能允许云台控制。

模块“启动已接受”只表示初始化入口成功，不表示传感器数据已经有效。数据新鲜度、实际反馈和运行许可仍由各模块自己报告，安全管理继续依据这些状态决定输出是否可以工作。

## 把运动学与电机接口分开

底盘运动学使用机器人中心的速度输入：向前为 `vx` 正，向左为 `vy` 正，绕向上轴的角速度为 `wz` 正；平移单位是 m/s，角速度单位是 rad/s。纯计算模块只接收轮子位置、滚动方向、轮半径和目标速度，输出固定轮序“左前、右前、左后、右后”的轮轴 rad/s，不调用 HAL、RTOS 或电机驱动。

麦轮和全向轮几何不同，所以分别使用独立计算文件。舵轮、轮腿和半舵已有独立接口占位，选择它们时构建应直接报错。旧应用消息仍使用原来的 mm/s、deg/s；转换集中在适配处，避免每个轮子控制分支重复换单位。

## 验证的层次

主机测试检查纯运动学的前进、侧移、自旋、组合输入、轮序和非法几何。CMake测试检查车型身份、模块依赖和未实现选项是否被拒绝。ARM固件构建检查真实编译器和链接布局。裸板测试只验证固件身份、启动状态与辅助显示关闭路径；没有连接电机时，不能据此声称轮子方向或实车控制已经验收。

MC02-0054 的 WSL Debug、Release和ASan/UBSan回归各494项通过；ASan/UBSan串行全量运行通过。带LCD与关闭LCD的 `bench_safe` ARM 构建均通过，关闭LCD时配置为 `MC02_FEATURE_LCD=0` 且源码清单不含LCD模块。裸板烧录仍待明确CMSIS-DAP连接和Flash备份校验；本轮未写入Flash。

## MC02-0054 复核补充

本轮复核后，车型清单和核心模块依赖由车型构建描述维护，构建入口只筛选当前板角色并验证关系。通信派发与电机控制分开选择：`bench_safe` 仍运行协议接收解析，但不调用 CAN 发送推进；启用机器人控制的构建才提交电机和板间控制帧。

运行期失败也更新同一份模块启动快照。异步 IMU 与 LCD 初始化失败会区分核心闭包和辅助模块：核心失败锁存诊断、撤销许可并关断输出；辅助失败只记录降级并停止使用失败模块。BMI088 注册失败返回 `NULL`，主机回归分别覆盖两种姿态后端。生成配置的健康快照还要根据 USB CDC 实际使用的功能标记 USB 模块。

本次复核新增验证：分板角色下分别编译 `robot_def.c`、生成配置健康快照包含 USB、BMI088 注册失败不返回姿态地址，以及运行期辅助／核心模块失败结果。被依赖检查跳过的可选 LCD 不创建任务；LCD 初始化失败后停止后续屏幕访问。麦轮和全向轮计算文件通过独立 ARM 编译。现有 ARM 裸板固件和物理板验收状态以任务票据中的新记录为准。
