# 引脚与外设资源冲突

本篇用 MC02 的 PA5 说明：一个 MCU 引脚在同一时刻只能接收一种配置。它可以作为 ADC 输入，也可以连接外设复用功能；后一次配置会替换前一次配置。

## PA5 为什么会失去按键采样

[`Core/Src/adc.c`](../../Core/Src/adc.c) 把 ADC1 通道19接到 PA5，`BSP_ADCInit()` 启动按键和电源的循环采样。原来的 [WS2812 初始化](../../bsp/ws2812/ws2812.c) 把 PA5 配为 SPI6 的 SCK，同时把 PA7 配为 MOSI。若这两个初始化都运行，PA5 就不再是 ADC 模拟输入，按键采样会失效。

当前 `BSPInit()` 会启动 ADC 采样，LED 初始化接口暂时没有生产调用点。这个调用现状不能保证以后接入 LED 时不会发生冲突，所以仍要修正初始化请求。

## 只把灯的数据线接到 PA7

WS2812 只读取单根数据线上的编码序列。SPI6 在芯片内部仍使用移位时钟产生 MOSI 数据，但程序不必把 SCK 输出到 GPIO。`WS2812_SPI6_Init()` 现在只将 PA7 配为 SPI6 MOSI；PA5 保持 ADC1 的模拟输入配置。

这次改动没有重映射 ADC 通道，也没有改变 SPI 字节编码、颜色顺序和复位低电平发送规则。真实灯珠的高低电平时间仍需用板上测量确认。

## 怎样验证引脚请求

主机测试直接链接生产 `ws2812.c`，用 HAL 替身记录 `HAL_GPIO_Init()` 收到的引脚掩码。测试要求初始化只请求 PA7，且重复初始化不会再次配置 SPI。它先在旧实现上失败，再在修复后通过。

WSL Debug 和 Release 主机回归各 419 项通过；bench_safe、rcdiag、robot single/chassis/gimbal 的 Debug 与 RelWithDebInfo 共10种 ARM 固件均构建成功。测试代码见[主机回归](../../tests/host/ws2812_pin_ownership_test.c)，完整证据见[BSPMISC-06任务记录](../workflow/tickets/BSPMISC-06.md)。源码层面的测试能检查驱动请求的引脚，不能证明板上 MOSI 波形、LED 亮度或 ADC 电气采样质量。

## 仍需单独验证的内容

本轮没有电流受控的主输入，因此没有给板上电，也没有测量 LED 波形。SPI 位宽、频率和 WS2812 的 T0H/T1H 时序仍由 MC02-0025 跟踪；构建中还观察到 `modules/alarm/led.c` 对 `malloc()` 和 `abs()` 缺少显式标准库声明，留在 MC02-0051 的可选驱动审查中。

## 车型编号与板级 CAN 绑定（MC02-0086）

[platform_resources.h](../../bsp/board/platform_resources.h) 给车型提供不含芯片句柄的 CAN 编号，[board_can_stm32.c](../../bsp/board/board_can_stm32.c) 决定 MC-02 上编号与 FDCAN1／2／3 的对应关系。双板桥接启动时先查询绑定；编号没有绑定就拒绝启动，避免静默使用另一条总线。底盘板仍选总线 2，云台板仍选总线 1，板间帧 ID 不改变。

板级表只能说明软件声明了哪个控制器，不能说明外设初始化成功、线上设备存在或总线能够通信。两种桥接角色已在主机测试验证映射、非法编号和既有通信逻辑；当前禁热固件不编译桥接，双板实物通信仍未验证。

车型的 DJI、LK、HT、DM 电机配置也只保存逻辑总线和 ID；驱动注册前通过板级绑定取得现有 CAN 注册参数。转换失败不改旧输出，并在申请电机资源前拒绝未绑定总线。核心底盘配置也会拒绝无效编号；对应的 PID、电机组帧和故障回归在主机通过。驱动的实际收发接口及超级电容等其他 CAN 使用方仍待迁移，完整资源能力检查见 [MC02-0086 记录](../workflow/tickets/MC02-0086.md)。
