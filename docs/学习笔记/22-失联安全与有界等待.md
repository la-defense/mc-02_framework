# 失联安全与有界等待

本篇记录两条实际联调中发现的边界：固件不能把上一周期的开火命令留在静态状态里；相机和网络等待要有期限，超时后控制循环才能及时撤销。

## 输入失效时要生成完整的新命令

`shoot_cmd_send` 是跨控制周期复用的静态结构。旧实现只在视觉数据有效时改写它；视觉回调失联时函数直接返回，上一帧 mode 2 的 `SHOOT_ON` 和 `LOAD_BURSTFIRE` 就会保留下来。跳过一次更新不等于撤销旧状态。

现在 `VisionControlBuildShootCommand` 每次都生成一份完整的视觉发射策略：mode 1 保留预热但停止装填；mode 2 允许 burstfire；无效输入生成中立命令。这里 `shoot_mode` 是发射电机组的总使能，mode 1 可保持它开启来预热摩擦轮；是否装填/击发由 `load_mode` 控制，所以 mode 1 必须是 `LOAD_STOP`。`RobotCMDTask` 再由 `VisionControlSelectShootCommand` 决定当前命令来源：有效视觉优先；视觉 mode 0、过期或断连时，若遥控器或键鼠仍是当前输入，就保留本周期刚算出的手动命令；没有有效控制源时才撤销为中立。这样“视觉命令无效”不会误删仍有效的手动请求，也不会让无控制源时的上一条命令残留。

手动遥控器在摩擦轮或装填被请求时打开发射总使能；键鼠在 E 选择单发/三发/连发或 F 打开摩擦轮时也使用同一规则，键鼠连发射频固定为 8 发/秒，不继承上一帧视觉射频。拨轮阈值和 E/F 映射被提取为纯函数，固件与主机测试共用，避免测试只验证手工构造的示例命令。主机回归覆盖拨轮边界、键鼠模式、视觉 10→手动 8 发/秒恢复、视觉优先、mode 0、过期、断连和无控制源中立输出，不需要 STM32 或执行器。它验证命令生成和选择逻辑；遥控器帧合法性、机械限位和真实电机响应仍由其他待办负责。完整任务进度见 [R25-06](../../.Doc/TODO.md#p1-上车前关闭)。

## 通信有效与控制有效是两道检查（R25-02）

CRC 正确说明接收到的字节通过协议校验；它不能证明目标角度在云台机械范围内。接收计数增长、在线和时间戳更新仍保留为通信证据，控制层另检查模式、50ms 内的新鲜度、六个数值有限，以及明确配置的机械范围。这样诊断时能区分“没有收到帧”和“收到帧但不能接管”。

新增的 `VisionControlLimits_s` 使用最终云台命令坐标系的度；SP 帧仍传弧度。以主机模拟为例：俯仰输入 25°，配置零偏 5°，最终命令为 30°，刚好落在 [-20°,30°] 的上边界；输入 30° 则得到 35°，必须拒绝。检查原始弧度或在加零偏之前检查，都可能漏掉越界。该组范围仅在测试中，生产 `VISION_LIMITS_CONFIGURED` 默认 0；现有零上下限不能被当作实机已标定参数。偏航也须明确选择连续旋转或有限范围，不能因为暂时没有参数就默认忽略机械约束。

`VisionControlInput_s` 保存的是配置指针，不复制或拥有配置。生产配置为静态只读对象，生命周期覆盖控制任务；每周期输入又固定本次时间与帧快照，所以云台和发射看到相同依据。`VisionControlBuildGimbalCommand()` 先把输出清零，仅当全部检查通过才发布转换结果。这种接口让调用者容易做到“失败时没有半份新命令”。

视觉失效后，要清的不只有发射位。旧目标角度、角速度和角加速度都存放在跨周期结构中；直接返回会继续保留它们。当前任务每周期先清除前馈，切回手动时用本周期收到的有限姿态反馈作为起点，再应用遥控杆或鼠标增量。例如上一视觉目标是 14.32°、板子当前实际朝向为 12°，遥控要求加 0.2°，新手动目标应为 12.2°，不会继承旧目标 14.32°。交接时拿不到反馈就发布中立，并等待新反馈；正常连续手动则保持目标增量累积。

手动接续还要求遥控链路在线且选择了有效模式。没有来源时清零目标与前馈、停云台输出并关闭发射；SAFE/CALIB/FAULT/ESTOP 在发布前再次覆盖选择结果。有效手动命令仍可发射，故“视觉退出”在此表示撤销视觉控制，而不是新增全局发射锁存规则。

本轮回归直接运行生产 `RobotCMDTask()`、RobotSafety 与消息队列，通过订阅实际发布的命令验证行为；默认未配置与模拟有效配置各构建一个主机目标。裸板构建不链接整机控制任务，裸板烧录成功不能证明视觉接管决策已经在板上运行，更不能证明真实云台或发射机构已失能。软件与裸板记录见 [R25-02 票据](../workflow/tickets/R25-02.md)，真实机械范围和输出失能继续由 TODO 跟踪。

## 为相机和连接等待设定期限

联调主循环必须能在相机停止送帧时继续运行，发送中立控制并响应退出信号。`CameraBase::read_for` 现在是纯虚接口；每个启用的后端都必须实现带期限的读取，不能再默认调用可能永久阻塞的 `read()`。MindVision 通过 `ThreadSafeQueue::pop_for` 等待队列数据，HikRobot 已使用同一限时队列模式。

Windows MVS 桥的 TCP 客户端在连接阶段切换到非阻塞模式，用 `poll` 等待可写，再读取 `SO_ERROR` 确认连接结果。所有已解析地址共用两秒期限，避免 IPv6 和 IPv4 轮流等待各自的系统超时。DNS 解析在这个期限之外；桥接脚本使用 WSL 可达的数值地址，避免依赖慢速主机名解析。

当前 CTest 用本地关闭端口验证连接被拒绝时构造函数快速失败。它没有模拟 SYN 静默丢弃，所以 [VIS25-0015](https://github.com/la-defense/sp_vision_25/blob/85c27907725b58929505de69f05a6235cf217386/TODO.md) 仍未完成。相机超时到中立帧的完整路径也还需要主机故障注入或硬件记录，见 [VIS25-0005](https://github.com/la-defense/sp_vision_25/blob/85c27907725b58929505de69f05a6235cf217386/TODO.md)。

## 收尾发送也属于发送

视觉 HIL 在循环结束时发送一次中立帧；异常退出时，RAII 清理对象也可能发送中立帧。两条路径都使用相同的计数发送函数。正常退出先完成发送并更新摘要计数，再关闭清理对象，避免摘要输出后又悄悄重试一帧。

中立帧发送失败时，软件只能记录失败；若链路已经断开，MC-02 自身的视觉超时逻辑还必须清掉最后一条旧命令。主机测试不能证明这条硬件链路一直正常。
