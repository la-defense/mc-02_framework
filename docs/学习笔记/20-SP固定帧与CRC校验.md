# SP 固定帧与 CRC 校验

本文记录 MC-02 与 `sp_vision_25` 的固定帧约定，以及如何用纯主机测试守住两端的协议边界。

## 1. 两个方向，两种长度

| 方向 | 结构 | 长度 | 典型内容 |
|---|---|---:|---|
| MC-02 → Vision | `Vision_Send_s` / `GimbalToVision` | 43 字节 | 模式、姿态四元数、云台角度与弹速/计数 |
| Vision → MC-02 | `Vision_Recv_s` / `VisionToGimbal` | 29 字节 | 控制模式与 yaw/pitch 位置、速度、加速度 |

帧头为两个字节 `SP`。双方结构加上 packed 属性和 `static_assert` 能检查大小，但字段顺序、浮点表示、大小端和 CRC 覆盖范围仍必须由双方共同遵守。

## 2. 从字节流里找帧

UART/USB 回调拿到的是字节区间，不保证从帧头开始。MC-02 从缓冲区起点逐字节扫描 `SP`，每找到一个候选位置，就确认剩余长度足够，再校验 CRC。完整且校验通过后才复制到接收状态并更新时间；坏 CRC 会增加错误计数，但不能刷新链路在线状态。短于一帧时直接拒绝。

当前解析函数 `VisionProtocolFindCommandFrame()` 把这个动作抽成不依赖 HAL 的纯 C 函数，因此可以由主机 GCC 直接测试：

```text
长度不足 → 拒绝
完整但没有 SP → 继续扫描
SP + CRC 不匹配 → 计错误，继续扫描
找到有效帧 → 返回帧；只由调用方发布并刷新在线状态
```

## 3. CRC 不是认证

CRC 可以发现覆盖范围内常见的意外传输损坏，但不能证明发送者是谁，也不防止恶意构造。这个工程的线格式要求完整保留当前 CRC 算法、初值、反射方向、覆盖长度和两个 CRC 字节的顺序；“都叫 CRC16”不代表结果相同。

MC-02 和视觉代码的当前实现使用同一位运算表述，主机测试将 `123456789` 的结果固定为 `0x6f91`。这是仓库实际协议实现的回归向量；更换 CRC 库前先核对 MCU 端算法和已抓取的真实帧。

CRC16 数值在协议帧尾按低字节、再高字节排列。读回时也按相反步骤组合为 16 位数值。测试应同时验证已知向量、完整合法帧、帧头错误、载荷翻转、短帧，以及坏帧后紧跟合法帧的重同步行为。

## 5. 找到帧以后怎样使用（MC02-0123）

[crc.h](../../modules/algorithm/crc.h) 提供计算入口，[vision_protocol.h](../../modules/master_machine/vision_protocol.h) 提供检查帧和找帧入口：
计算入口的长度不含待追加的 CRC，检查入口的长度包含末尾两字节。
找帧入口逐字节前移，头或 CRC 不对就继续，找到第一份完整正确帧立即返回。
失败时命令输出不改写，错误计数则先清零；调用方不能把上一份输出当成本次找到的帧。

[master_process.h](../../modules/master_machine/master_process.h) 在采用数据前按真正接收时刻检查 50 ms 时限，
读取和发送时也会检查旧命令是否到时。角度使用 rad，角速度使用 rad/s，进入电机控制前另做换算。
CRC 正确只说明字节检查通过，模式、数字、机械角度和当前是否允许控制仍由后续代码检查。

同目录的 [seasky_protocol.h](../../modules/master_machine/seasky_protocol.h) 保留另一种 A5 帧头格式，
不能和 SP 帧混用。它没有接收长度或输出容量参数，调用方须先保证整帧及空间足够，
帧头长度至少包含两字节标志；校验失败返回 0，标志和数据输出保持原值。

## 6. 裁判系统 CRC 和图形发送（MC02-0123）

[crc.h](../../modules/algorithm/crc.h) 提供统一的计算接口，裁判接收和 UI 组包直接检查返回状态。计算长度不含预留的校验字段：CRC-8 写末尾1字节，CRC-16 按低字节、高字节写末尾2字节。计算函数只交付数值，写帧和比较字段由调用方完成；裁判 CRC-8 必须选择 `CRC8_REFEREE`，不能换成同为8位的 CAN／A5 算法。

[referee_UI.h](../../modules/referee/referee_UI.h) 的 `UIGraphRefresh()` 只支持1、2、5或7个图形，图形通过可变参数按值传入；`cnt` 与后续参数数量必须对应。函数根据数量选择协议命令，再把每个图形放入帧中并追加 CRC-16。[RefereeSend()](../../modules/referee/rm_referee.h) 用 DMA 发送后还会等待115 ms；它没有返回发送状态，调用方不能把函数返回当作发送成功的证明。

## 7. 同样的位数，五套参数（MC02-0079）

完整算法需要同时说明多项式、初值、输入／输出位方向和最后异或值。项目只提供五种固定选择，配置和查表均在只读区；调用者不能改写配置或在首次调用时生成共享表。

| 选择 | 多项式正常表示 | 初值 | 输入／输出反射 | 最后异或 | `123456789` |
|---|---|---|---|---|---|
| `CRC8_CAN_A5` | `0x31` | `0` | 否／否 | `0` | `0xA2` |
| `CRC8_REFEREE` | `0x31` | `0xFF` | 是／是 | `0` | `0x0B` |
| `CRC16_MODBUS_A5` | `0x8005` | `0xFFFF` | 是／是 | `0` | `0x4B37` |
| `CRC16_SP_REFEREE` | `0x1021` | `0xFFFF` | 是／是 | `0` | `0x6F91` |
| `CRC32_IEEE` | `0x04C11DB7` | `0xFFFFFFFF` | 是／是 | `0xFFFFFFFF` | `0xCBF43926` |

正常表示省略最高位；从低位处理的实现分别使用反射后的多项式，例如 SP 的 `0x8408`。当前 SP 结束时没有取反，因此文档不再把它称为 CRC16/X25。此次保留原字节结果，不要求视觉端升级。

## 8. 先检查状态，再使用数值

新接口把失败原因与 CRC 数值分开。有效 CRC 可以正好为0，不能用 `if (crc)` 判断计算是否成功。

```c
uint32_t result;
CRCStatus_t status = CRCCompute(CRC16_SP_REFEREE, bytes, byte_count, &result);
if (status != CRC_OK)
    return; // 没有本次结果，不提交报文。
frame_tail_low = (uint8_t)result;
frame_tail_high = (uint8_t)(result >> 8u);
```

长度以字节计，调用者负责真实容量。长度为0允许空数据地址；空输出地址、非法算法和未初始化上下文都会失败，原输出保持不变。保留旧输出便于调用者决定如何处理，不能把它当成本周期计算成功。

CAN、SP 和裁判接收计算失败时不发布字段、不刷新有效时间；发送失败时不提交帧。参数保存先算 CRC，再擦除目标区；读取计算失败则不接受记录。A5 组包改为返回状态，失败把输出长度置0，数组中可能已有部分内容，不得发送。A5 原有接收长度和容量检查限制仍由调用者承担。

## 9. 分段接收和异常入口

分段计算先将 `CRCContext_t` 置零，再调用 `CRCInit()`；每段使用 `CRCUpdate()`，最后用 `CRCFinal()` 读取结果。Final 不清除历史数据，可重复读取，也可继续 Update。它保存的是尚未进行最后异或的余数，不能随意把已经输出的 CRC32 当成下一段初值。

每个上下文单独保存算法和余数，不同对象可交错或并发计算；同一对象仍须串行访问。失败不会改上下文或输出。普通模块不需要 HAL、RTOS、动态分配或硬件 CRC 外设。

[异常 CRC 入口](../../bsp/crash/bsp_crash_crc.h) 独立逐位处理固定记录中的32位字，每字先处理低字节。它不调用普通查表模块，不打印日志、不等待、不分配内存。读取长度来自当前固定结构，不能使用损坏记录声称的长度；未算出 CRC 时不写完成标记，继续原有复位路径。

CRC 算法兼容不代表任意旧固件的崩溃记录都会被当前固件接受：原有版本、长度和构建编号检查仍然保留。

## 10. 怎样证明迁移保持兼容

[算法测试](../../tests/host/crc_test.c) 用独立的最高位逐位算法对照生产查表，覆盖全部单字节、不同长度、分块、重复读取、继续追加、错误入口和独立实例；Linux 还使用真实线程。固定向量同时锁定具体参数，防止两份实现一起改错。

[A5 测试](../../tests/host/crc_a5_test.c) 保留基线完整帧；[协议测试](../../tests/host/crc_protocol_test.c) 经过真实 SP／裁判回调及 UI 组包，注入头部和尾部计算失败。CAN 测试使用真实生产 CRC，参数测试保留旧格式固定记录并检查失败前没有擦除或编程。
