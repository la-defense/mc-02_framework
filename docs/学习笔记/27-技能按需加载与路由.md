# 技能按需加载与路由

本仓库安装了 39 个 Matt Pocock 技能（37 个带上游锁文件、1 个本地编写的 `student-code-comments`、外加几个写作技能）。这些技能正文加起来三千多行，却不会拖慢每一次对话——因为它们**按需加载**，不在常驻上下文里。

本文解释这套机制，以及 **MC02-0127** 为什么把"技能路由"单独抽成一份文档，而不是抄进 `AGENTS.md`。

## 把技能抄进 AGENTS.md 会发生什么

`AGENTS.md` 是每一轮对话都要读的仓库说明。它适合放"永远成立的约束"，比如任务状态只在 [.Doc/TODO.md](../../.Doc/TODO.md)、上板只允许裸板。

技能的正文不适合放进去，原因有三个：

1. **成本固定、收益不定。** 39 个技能约 3000 行，写进 `AGENTS.md` 意味着每次对话都为这 3000 行付 token，哪怕这一轮只是在改一个注释。
2. **失效方式很隐蔽。** 技能正文会随上游更新，抄一份到 `AGENTS.md` 就有了第二份副本。以后改技能不改文档，规则就静默过期，而且没人会去比对。
3. **触发机制被绕过。** 技能自带 `description`，模型是靠它判断"这活归我"的。抄成正文后，判断依据变成了人写的一行路由，等于把自动匹配降级成人工转述。

正确的分工是：**`AGENTS.md` 只说去哪找，路由文档说什么时候用，技能正文说怎么做。**

## 技能是怎样被找到的

DSH 的技能来自若干扫描根，按 rank 从小到大排序：

| rank | 来源 | 路径 |
|---|---|---|
| 100 | 项目 DSH 根 | `<仓库>/.dsh/skills` |
| 200 | 项目 agent 根 | `<仓库>/.agents/skills` |
| 300 | 自定义根 | 配置项 `customSkillDirs` |
| 400 | 用户 DSH 根 | `~/.dsh/skills` |
| 500 | 用户 agent 根 | `~/.agents/skills` |
| 600 | 内置根 | `$DSH_BUNDLED_SKILL_DIR` 配置时 |

同名的技能，先被扫到的胜出，所以本仓库 `.agents/skills` 里那份会压过 `~/.agents/skills` 里的全局副本。这也是为什么全局装了一套 Matt Pocock 技能之后，本仓库的行为没有变化——37 个同名技能里，本地改写版仍然生效。

一个技能可以是目录包 `<名称>/SKILL.md`，也可以是平铺的 `<名称>.md`；嵌套在子目录里的 `SKILL.md` **不会被发现**。文件头必须有 YAML frontmatter 的 `name` 和 `description`，否则整个技能被跳过且不报错——目录里看得到、用不了，是最难查的一类问题。

## 两种可见性：模型目录和 `/` 菜单

frontmatter 里的 `disable-model-invocation: true` 决定触发面：

- **没有这一行**：技能进入模型可见的目录，模型读到 `description` 与当前任务匹配时可以自己加载。
- **有这一行**：技能只出现在 `/` 菜单里，只有人敲 `/名称` 才能加载。

本仓库原来的问题就出在这里：`docs/agents/issue-tracker.md` 写着"大功能用 to-spec / to-tickets"，但这两个技能带 `disable-model-invocation: true`，模型根本看不见它们。规则写了，能力没有。

## 路由表解决的是"何时用"

路由表是任务到技能的映射，形如：

| 任务 | 技能 | 触发 |
|---|---|---|
| 只在特定条件下复现的故障 | `diagnosing-bugs` | 自动 |
| 需要一手来源的协议、手册行为 | `research` | 自动 |
| 路线不清楚的大工程 | `wayfinder` | 自动 |
| 用户点名的 diff 审查 | `code-review` | 仅显式请求 |

它和技能正文的分工是：路由表回答"什么情况下该想起谁"，技能正文回答"想起之后具体做什么"。前者的篇幅随任务种类增长，后者的篇幅随方法细节增长，混在一起两边都会失控。

## 本仓库现在由四个文件分工

| 文件 | 职责 |
|---|---|
| [AGENTS.md](../../AGENTS.md) | 常驻约束，链接到路由与适配规则 |
| [docs/agents/skills.md](../agents/skills.md) | 唯一的技能路由表，含触发方式与边界 |
| [docs/workflow/skill-overrides.md](../workflow/skill-overrides.md) | 本地改写与上游的差异 |
| [skills-lock.json](../../skills-lock.json) | 上游来源与哈希，用于判断何时需要重新比对 |

四者不重复。`skills.md` 不解释技能内容，`skill-overrides.md` 不列任务清单，`AGENTS.md` 不复制任何一张表。

## MC02-0127 实际改了什么

1. `AGENTS.md` 原来那句"skills 按本地适配规则使用"没有指向任何文件，改为分别链接路由文档和适配文档。
2. 新建 `docs/agents/skills.md`，把散落在 `issue-tracker.md` 和 `skill-overrides.md` 的规则收成一处。
3. 去掉 `wayfinder`、`to-spec`、`to-tickets`、`triage` 四个技能里的 `disable-model-invocation: true`，让路由表真的能生效。
4. 给 `research` 和 `diagnosing-bugs` 写明触发条件——这两个技能对应"协议调查"和"只在特定条件下复现的故障"，此前完全靠临场发挥。

改动只碰文档和四个技能的文件头，没有代码、没有构建配置。

## 验证方式与局限

能验证的部分：删掉这一行之后，本会话的技能目录立刻出现了这四个技能，说明扫描与解析都正常；`tools/workflow/check_todo.py` 校验 TODO 格式；改动文件里的相对链接逐个检查目标存在。

验证不了的部分：不能证明模型每次都会正确选中技能。路由表降低漏用的概率，不提供保证；`/` 菜单和显式点名仍然是可靠入口。

另外，`skills-lock.json` 记录的是上游哈希，本地改写后本来就对不上——这不是损坏，而是"本仓库版本与上游不同"的标志。更新技能时必须对照 `skill-overrides.md` 人工评审，不能直接覆盖。
