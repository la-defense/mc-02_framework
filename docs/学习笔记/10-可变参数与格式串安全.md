# 10 可变参数函数与格式串：为什么"一条日志"能把整个系统打崩（写给零基础）

> 本篇回答的问题：
> 1. `printf("...%d...", x)` 里的参数，函数是怎么知道该取几个、各是什么类型的？
> 2. 为什么格式串写错一个字母，结果可能不是"打印错"，而是**整机 HardFault**？
> 3. 为什么 `%f` 在这个工程里是"禁用词"？
> 4. 现场怎么定位"崩在 printf 里"这种故障。
>
> 对应代码：`bsp/log/bsp_log.h` 的 `LOG_PROTO`、`Middlewares/Third_Party/SEGGER/RTT/SEGGER_RTT_printf.c`、
> `modules/BMI088/bmi088.c`。这是本轮 `LOG-01` 的完整复盘。

> **2026-09-26 更新（LOG-02）**：本篇讲的是"精简 printf 不消费不认识的参数"这个机制与当时的崩溃现场，
> 作为**历史复盘**保留。此后日志已经改成"先由 newlib `snprintf` 格式化到栈缓冲，再写 RTT"，
> 结尾的复位色码也不再作为格式串里的 `%s`；同时 CMake 里补了 `-u _printf_float`，
> 所以 **`%f` 现在可以正常打印，参数也不会再错位**。新的实现见《18-一条日志的旅程》。

---

## 1. 可变参数是怎么"传"进去的

`printf(const char *fmt, ...)` 里的 `...` 叫**可变参数**。ARM 架构上调用约定（AAPCS）规定：

1. 前 4 个整数/指针参数放在 `r0~r3`；
2. 多余的参数**顺序压到栈上**；
3. **`float` 会被自动提升成 `double`**（叫"默认实参提升"）；
4. `double` 占 **2 个 32 位槽**（寄存器对或栈上 8 字节）。

所以关键点是：**被调用者（printf）并不知道你到底传了什么**，
它只能"按格式串的指示，一个接一个地去取"。

---

## 2. `va_arg` 就是"取下一个参数"

printf 内部长这样（简化版）：

```c
while (*fmt) {
    if (*fmt == '%') {
        switch (*++fmt) {
        case 'd':  v = va_arg(args, int);        print_int(v);    break;
        case 's':  s = va_arg(args, const char*); print_str(s);   break;
        case 'x':  v = va_arg(args, int);        print_hex(v);    break;
        default:   break;      /* ← 不认识的说明符, 什么都不做 */
        }
    } else {
        putchar(*fmt);
    }
    fmt++;
}
```

`va_arg(args, T)` 的语义是：**"把下一个参数按类型 T 取出来，并把游标往后挪 `sizeof(T)`"**。

于是有了一条铁律：

> **格式串里出现的每一个"取值类"说明符，都必须精确对应实参列表里的一个参数
> （类型/数量都要对）。错一个，后面**全部**跟着错位。**

---

## 3. 错位的后果：三种，一种比一种难受

| 错法 | 例子 | 后果 |
|---|---|---|
| 类型不符 | `printf("%s", 123);` | 把 `123` 当地址去读 → 几乎必然崩溃 |
| 数量少了 | `printf("%d %d", 1);` | 第二个 `%d` 取到栈/寄存器里的垃圾 → 打印出乱数（这一般只是"打印难看"） |
| **说明符不被实现支持** | `printf("%f", 1.5f);` | 取决于实现：**有的实现直接跳过、不消费参数** → 后面全部错位 |

第三行就是我们的案发现场。

## 4. 本工程的日志宏：风险被放大了

`bsp/log/bsp_log.h`：

```c
#define LOG_PROTO(type, color, format, ...)                       \
        SEGGER_RTT_printf(BUFFER_INDEX, "  %s%s" format "\r\n%s", \
                          color,                                  \
                          type,                                   \
                          ##__VA_ARGS__,                          \
                          RTT_CTRL_RESET)

#define LOGINFO(format, ...) LOG_PROTO("I:", RTT_CTRL_TEXT_BRIGHT_GREEN, format, ##__VA_ARGS__)
```

注意拼出来的最终格式串是：

```
"  %s%s"  +  format  +  "\r\n%s"
   ↑  ↑                    ↑
 color type            复位颜色码(一个额外的参数!)
```

也就是说：**`format` 后面永远还跟着一个 `%s`，它的参数是 `RTT_CTRL_RESET`。**

那么如果有人写了：

```c
LOGINFO("[bmi088] 标定记录: gNorm=%.4f off=%.5f", b->gNorm, b->gyro_offset[0]);
```

参数表实际是：

```
[color] [type] [gNorm(double, 2槽)] [off(double, 2槽)] [RTT_CTRL_RESET]
```

解析过程：

```
%s         → color          ✓ 消费 1 个槽
%s         → type           ✓ 消费 1 个槽
%.4f       → SEGGER 不支持, default: break 且 **不消费**   ✗ 本来该消费 2 个槽
%.5f       → 同上                                            ✗
\r\n%s     → 取到的不是 RTT_CTRL_RESET, 而是 gNorm 的位模式!
```

结果：**一个浮点数的二进制位被当成 `const char *` 去解引用**。

```c
case 's':
  const char *s = va_arg(*pParamList, const char *);
  do { c = *s;  /* ← 就是这里炸的 */ s++; ... } while (...);
```

实测崩出来的现场：

```
CFSR = 0x00008200   → BFSR.bit1 = PRECISERR(精确总线错误) + bit7 = BFARVALID
HFSR = 0x40000000   → FORCED(由可配置故障升级)
BFAR = 0xC0000000   → 出错地址: FMC/SDRAM 区(本板没接这颗外存)
PC   = SEGGER_RTT_vprintf : 428 行 → c = *s;
```

**为什么以前没炸？** 因为错位后取到的那个"指针"是 `float` 的位模式，值随机：

- 有时候是 `0x00000000` → 读 ITCM 区（`0x00000000~0x00010000` 是 ITCM 别名，**可读**）→ 侥幸通过；
- 有时候是别的值 → 落在没接外设的区域 → **BusFault → HardFault**。

这就是"偶发崩溃、改个参数就不崩"的典型特征。

## 5. 为什么 `%f` 在这个工程里是禁用词

SEGGER RTT 的 printf 是一个**为了体积而手写的精简实现**，只支持：

```
%c %d %u %x %X %s %p %%   （以及宽度/前导零等标志位）
```

**不支持浮点**。这一点在 `bsp_log.h` 的注释里其实写了：

> `@attention 注意这些接口不支持浮点格式化输出,若有需要,请使用Float2Str()函数进行转换后再打印`

但"不支持"三个字的代价被低估了：**它不是"打印不出来"，而是"打乱参数表"**。

另外 `snprintf`（newlib-nano，`-specs=nano.specs`）默认也**不支持 `%f`**
（需要额外链接 `-u _printf_float`）。它不会崩（vfprintf 的解析是完整正确的），
但会打印成空/异常，所以项目里也约定不用。

**本工程现行约定**：

| 想打印 | 正确做法 |
|---|---|
| 一个浮点值 | `LOGINFO("x1000=%ld", (long)(v * 1000.0f))`（放大成整数） |
| 必须可读的浮点 | 用 `Float2Str()` 转成字符串再 `%s` |
| LCD 显示浮点 | 用 `LCD_BufShowFloat()`（自己实现，不经过 printf） |

## 6. 缺陷现场定位方法（可复用）

这次从"板子跑几秒就挂"到"定位到某一行日志"用了 4 步：

**① 判断是"挂死/复位/慢"**

读 `RCC->RSR`（复位原因）+ 两次读同一个变量看是否变化。这次是"挂死 + 看门狗复位"。

**② 读故障寄存器，判断故障类型**

```bash
openocd ... -c "init" -c "halt" \
  -c "reg pc" -c "reg lr" -c "reg msp" -c "reg psp" \
  -c "mdw 0xE000ED28 1" -c "mdw 0xE000ED2C 1" -c "mdw 0xE000ED38 1" -c "shutdown"
```

- `CFSR=0x00008200` → BusFault 精确错误 + BFAR 有效；
- `BFAR=0xC0000000` → 出错地址；
- `PC=HardFault_Handler`、`LR=0xFFFFFFE9` → 是**从另一个异常里**升级进来的
  （`EXC_RETURN` 的 bit3=1 表示"返回 Handler 模式"）。

**③ 解栈帧找"出错的 PC/LR"**

异常进入时硬件会压 8 个字到栈上（顺序固定）：

```
[SP+0x00] R0     [SP+0x10] R12
[SP+0x04] R1     [SP+0x14] LR      ← 出错时的返回地址
[SP+0x08] R2     [SP+0x18] PC      ← 出错指令地址
[SP+0x0C] R3     [SP+0x1C] xPSR
```

`LR` 是 `0xFFFFFFEx` 形式就说明"当前在异常处理里"，用 `msp`/`psp` + `mdw` 把栈 dump 出来，
找那个形如 `0x08xxxxxx`（Flash 地址）和配套的 `xPSR`（bit24=1，即 T 位）。

本例 dump 到：

```
0x2401fc38: 00000000 00000073 2401fd34 2401fd30 00000036 08006411 080063d4 01000000
                                                              ↑ LR      ↑ PC    ↑ xPSR(T=1)
```

**④ `addr2line` 把地址翻译成源码行**

```bash
arm-none-eabi-addr2line -f -e build/Basic_Framework_MC02.elf 0x080063d4 0x08006411
# SEGGER_RTT_vprintf   .../SEGGER_RTT_printf.c:428
```

> 也可以用 `debug-gdb-openocd` 的 `--mode crash-context` 直接拿 `bt`，
> 更省事；手解栈的好处是不依赖工具链、在只有 OpenOCD 的环境里也能用。

## 7. 怎么防（我们做了什么）

### 7.1 清掉现有 `%f`（治标，但必须做）

`bmi088.c` 三处、`bsp_dwt.h` 的 `TIME_ELAPSE` 宏一处，全部改成"放大成整数"打印。

顺带说明：这些 `%f` 在 RTT 下**本来就打印不出东西**
（之前日志里看到的是 `gNorm= off=//`），所以改掉没有任何信息损失。

### 7.2 在库层兜底（治本）

`SEGGER_RTT_printf.c` 的 `default:` 分支加了一段：

```c
default:
  switch (c) {
  case 'f': case 'F':
  case 'e': case 'E':
  case 'g': case 'G':
  case 'a': case 'A':
    (void)va_arg(*pParamList, double);   /* 不打, 但把参数消费掉! */
    break;
  default:
    break;
  }
  break;
```

这样将来谁再写 `%f`，最坏情况只是"这一项不显示"，**不会再破坏后面的参数表**。

### 7.3 写代码时的自查清单

- [ ] 日志格式串里的说明符，和我传的参数**数量、类型**都对得上吗？
- [ ] 有没有用到 `%f`/`%e`/`%g`/`%lld`/`%zu` 这些**精简 printf 可能不支持**的说明符？
- [ ] `%s` 的实参**一定是**有效字符串指针吗？（不要传 `char` 数组里没结束符的内容）
- [ ] 打印 `uint8_t`/`int8_t` 时有没有转成 `unsigned`/`int`？
      （可变参数里小整型会提升成 `int`，用 `%u` 打 `uint8_t` 是有风险的）
- [ ] 打印 `size_t`/指针差时用 `%zu`/`%ld` 是否被支持？不确定就显式转 `(unsigned long)`。

## 8. 顺带记住的两个"日志系统常识"

1. **日志不是免费的**：1kHz 任务里打一条日志可能占用几百微秒（RTT 写缓冲 + 格式化），
   本项目因此给热路径日志加了限速（见《02》《03》）。
2. **日志代码也会崩**：这次就是"功能性代码全对、日志代码把系统打崩"。
   排查时不要因为"这只是一行 log"就跳过它——
   恰恰相反，PC 落在 `printf` 里时，先怀疑**格式串**。

## 9. 速查表

| 现象 | 结论 |
|---|---|
| PC 停在 `SEGGER_RTT_vprintf` 的 `*s` | 十有八九是 `%s` 拿到了坏指针 |
| CFSR bit1+bit7（0x00008200 之类） | BusFault 精确错误，BFAR 里有出错地址 |
| BFAR 是 `0x0`/`0xC0000000` 之类的怪地址 | 指针被算错/被当成别的类型解释了 |
| 偶发崩溃，改一下打印内容就好 | 典型"参数错位"，错位后取到栈上垃圾 |
| `%f` 打印出来是空 | 该 printf 实现不支持浮点——**并且可能正在破坏后面的参数** |

---

## 10. 一句话总结

**可变参数函数是"用格式串当说明书、按顺序盲取参数"的机制；
说明书里多一个、少一个、或者写一个实现不认识的说明符，
后面取到的就全是垃圾——而垃圾一旦被当成指针，一条日志就足以让整机 HardFault。**
