## 命令任务时序失败时撤销旧目标

- 原任务只调用整车失能，通用消息读取仍可取得未过期的底盘目标。修改后，时钟等待失败、完成检查失败、漏拍和超期都先调用受限命令模块的撤销入口，再上报任务监控。
- 两项受限底盘联测使用真实安全管理和消息中心实现，验证旧消息即使未到期也立即不可读，旧安全代际不再许可，退出后恢复进入时的中断状态。重新请求使能后仍需下一份新输入，首个目标为零。普通与跨毫秒回绕两种场景及四项任务周期回归共 6 项通过 ASan／UBSan。
- 隔离受限底盘、正式单板 SP／V2 和遥控观察固件通过 ARM 构建、源码与 ELF 检查。撤销入口只链接进受限底盘，Flash 为 310020 B，较 `c9ed4e7` 增加 32 B，主 RAM 保持 119952 B。仓库实际车型的受限底盘构建仍报告轮组和人工输入两组确认缺项。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过。WSL Debug 和 Release 各通过 859 项，普通禁热和遥控诊断通过 ARM 构建及 ELF 检查，六种正式预设仍按未确认条件拒绝。本轮只验证本机撤销和构建隔离，实际停止时延仍待现场验收。
