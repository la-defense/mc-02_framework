# MC02-0060：经典 CAN 分用途发送调度

任务状态只维护在 [.Doc/TODO.md](../../../.Doc/TODO.md)。实现分支为 `feat/can-purpose-scheduler`，基线为 `12f6bf640cc60868ff4e933eb4c10aff1b592fc7`。本轮只进行 WSL 主机测试与 ARM 禁热固件构建，不连接 CAN 设备，不发送真实总线帧。

## 实现范围

- `bsp/can/bsp_can.h/.c`新增固定存储发送调度器。提交时复制帧头和负载；支持标准／扩展 ID及0～8字节经典 CAN 数据，不支持 CAN FD 长帧。
- 周期接口以稳定的来源指针和键合并未启动目标，只保留最新副本；每周期由调用方重新提交。队列忙或 HAL 拒绝时本周期终止，调度器不重放旧控制目标。
- 一次性单帧及1～8帧批量请求有队列容量、优先级和从入队计时的期限。每总线的配置可以在首个 CAN 实例注册前修改，周期流按保守帧长及最小周期核算利用率。
- `MotorControlTask()`调用`CANProcessTx()`；每次每总线最多尝试一帧。调度器依优先级及期限选择；尚未有帧被 HAL 接受的一次性请求在重试间让出选择权，批次已有帧被接受后继续提交其余帧以保持组内软件顺序。
- 一次性帧初次未被 HAL 接受时最多重试3次。HAL 接受后若中止，只记录失败而不重发。请求查询区分排队、HAL 接受和 FDCAN 完成；完成状态不表示应用层对端已接收或执行。
- 原`CANTransmit()`和`CANSetDLC()`入口已从活动接口及生产调用方移除。DJI、DM、HT04、LK、XM、CANComm和超级电容均迁移到新接口；电机任务集中推进发送。

默认配置：CAN1每总线16项／700‰、CAN2为12项／650‰、CAN3为8项／500‰，标称速率均为1 Mbit/s。允许通过`CANConfigureTxBus()`分别配置队列容量1～16、利用率1～1000‰及大于0的标称位速率。预算仅包含本固件登记的周期流；不代表整个物理总线利用率。每总线保留16项周期流预留和32条发送结果历史，终态历史被复用后查询会返回未找到。

## WSL 主机验证

CAN专项测试链接生产调度器、DJI/LK电机代码及生产帧编码，仅替换 HAL、时间、RTOS、DWT 和日志。七个独立场景覆盖：

- 输入范围、标准／扩展 ID、0～8字节、提交复制、ISR 拒绝、失败不改请求编号及最坏帧长估算；
- 每总线独立容量、批量原子拒绝、批内顺序、最大8帧、优先级和期限排序；
- 周期同来源同键覆盖、预算精确边界、忙／HAL 错误后不重放、下一次新值恢复；
- 期限边界及毫秒计数回绕、过期后容量立即释放、排队取消；
- 单次失败时初次尝试＋最多3次重试、HAL 错误与硬件忙统计、HAL 接受后的中止不重发；
- 大速率和最大周期参数的带宽运算不溢出；
- 低优先级请求未被 HAL 接受时让出位置，让后来紧急请求先提交；已有部分批次被接受时仍保持批内顺序。

验证结果：WSL Debug全量主机测试 **380/380**，WSL Release全量 **380/380**；CAN调度专项 ASan／UBSan **7/7**。所有新增主机检查均在Release下执行。

## ARM 禁热构建与资源

最终构建通过10种禁热预设：`bench-debug/rel`、`rcdiag-debug/rel`、`robot-single-debug/rel`、`robot-chassis-debug/rel`、`robot-gimbal-debug/rel`；其中`rel`为RelWithDebInfo。十个ELF均通过角色、源码清单、编译数据库及实际链接输入隔离检查；非法角色配置按预期失败。工具链为ARM GCC 10.3.1，编译选项为Cortex-M7、`fpv5-d16`和hard-float，所有配置均未启用fast-math。

CAN固定工作区放在32字节对齐的`RAM_D2` NOLOAD区，BSP启动时显式清零并初始化；本轮各固件该区占用均为12,768 B（32 KiB的38.96%）。代表性资源数据如下：

| 配置 | Flash | DTCM | 主 RAM | RAM_D2 |
|---|---:|---:|---:|---:|
| bench-debug | 216,880 B | 14,656 B | 113,560 B | 12,768 B |
| bench-rel | 206,708 B | 14,656 B | 113,552 B | 12,768 B |
| rcdiag-debug | 219,120 B | 14,656 B | 116,728 B | 12,768 B |
| rcdiag-rel | 208,876 B | 14,656 B | 116,720 B | 12,768 B |
| robot-single-debug | 262,640 B | 14,656 B | 126,584 B | 12,768 B |
| robot-single-rel | 249,884 B | 14,656 B | 126,552 B | 12,768 B |

robot/single是本次主RAM占用最高的角色：Debug剩余约4,488 B，RelWithDebInfo剩余约4,520 B；仍在链接脚本界限内，但余量有限。chassis和gimbal两种角色的Debug及RelWithDebInfo构建、隔离检查也通过。CMake增量检查逐项覆盖新增、移除、移动源码及头文件目录，既有目录与干净配置的清单和包含目录一致；证据保存在`/tmp/mc02-cmake-regeneration-can/run-20261025-034949-o09kyjlz/`。

没有烧录，也没有物理总线、ACK、波形或外设对端行为结论。本实现建立的是本固件登记流量的预算，不代表可以控制或测量总线上的其他节点流量。
