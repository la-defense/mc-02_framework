# R25-13：修复 Release 回归检查并清理构建告警

任务状态只维护在 [.Doc/TODO.md](../../../.Doc/TODO.md)。基线 `d2a503b`，本轮仅在本机验收；按用户确认，不要求远端 Actions 运行，不烧录固件。

## 完成范围

- 将 `tests/host` 中受 `NDEBUG` 影响的检查统一改为始终执行的 `TEST_CHECK`，并把注册、发布、入队、快照读取和初始化等副作用调用移出检查表达式。
- 新增检查器的正向与负向控制；负向 CTest 只有在检查打印诊断并返回非零时才通过。
- 覆盖注册资源、初始化诊断、消息新鲜度、CANComm、VCP 队列及 Kalman 初始化测试。资源分配故障注入同时拦截 `malloc` 和 `calloc`，覆盖优化器合并 `malloc()+memset()` 的情况。
- 修正 `DWT_ProbeDone()` 的 `volatile` 参数类型、LCD 字模初始化层级、LCD 有界文本复制、未使用变量，并将 EKF 快速反平方根改为通过 `uint32_t` 与 `memcpy` 传递位型，避免严格别名违规和 64 位主机读取越界。
- Flash 地址转指针显式经 `uintptr_t`，消除 64 位主机回归中的整数到指针宽度告警。

## Release 假通过复现

在 `build/r25-13-release-red/` 的隔离副本里，将消息新鲜度检查的期望值故意改错。Debug 测试失败；原 Release 版本中 `-DNDEBUG` 删除了 `assert`，测试通过，证实检查表达式未执行。改为 `TEST_CHECK` 后，Debug 与 Release 均拒绝相同错误。故障注入另发现 Release 优化会将生产 `malloc()+memset()` 合并成 `calloc()`；增加 `calloc` 拦截后，两种优化级别都实际触发分配失败路径。
