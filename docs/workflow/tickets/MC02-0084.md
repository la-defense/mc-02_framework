# MC02-0084：RGB 与蜂鸣器接入统一 safety 告警

任务状态只在[TODO](../../../.Doc/TODO.md)维护。本轮共用分支 `feat/safety-alarm-rgb-buzzer`，基线 `fbb0b58`。验收限定为 WSL 主机测试与 ARM 固件构建；未连接或烧录开发板。

## 实现范围

- 新增纯策略层与运行适配层。策略每轮读取一致的 `RobotSafetySnapshot_t`，按配置优先级持续选取最高优先级故障；故障解除后选取下一项，无故障时显示 STOP、INIT、SAFE、CALIB、READY、FAULT 或 ESTOP 状态。未知故障位和未知状态有各自的配置后备样式。
- 车型表显式配置9种已知故障、7种状态、灯光及声音节奏、静音等级和期限。分段数量最多8，单轮节奏不超过10秒；灯段可循环或播放一次后保持末段，灯与声音共用事件起点，各自按同一实际毫秒时钟推进。相邻推进间隔小于一个完整32位计数周期时，累计时长跨多个周期继续推进节奏。静音请求从任务接口排入单槽，由后续任务轮次处理，只影响允许等级的蜂鸣器，不修改许可、故障和灯光。
- `RobotInit()` 在 safety 初始化后选择车型配置并初始化告警。LED／蜂鸣器初始化及运行失败只让对应辅助通道降级，不报告核心初始化失败，不改变关热、许可或看门狗路径。Daemon 每10毫秒调用告警入口；策略只在所需输出变化时提交驱动请求。
- 蜂鸣器使用类型化接口和固定频率表，`OCTAVE_8` 映射1046Hz。首次实现 `ad52ea5` 使用124字节阻塞 SPI 发送；后续异步实现及其证据另记在下方。SPI／灯珠实际波形和板上时序仍由 **MC02-0025** 跟踪。

## 后续异步输出实施计划

继续沿用本分支，目标是补齐 MC02-0084 的任务异步输出；实际灯珠、波形和物理时序仍按 MC02-0025 的独立条件验收。参考 [ST RM0468](https://www.st.com/resource/en/reference_manual/dm00603761.pdf) 的 D3 总线说明：BDMA 只能访问 D3 域资源，因此 SPI6 发送缓冲应固定放在 SRAM4，不能使用当前任务栈或普通 AXI RAM。

1. 为 SPI6 配置独立 BDMA 通道、SPI／BDMA 中断及固定缓冲；链接脚本明确 SRAM4 地址、容量和对齐，处理缓存可见性。核对现有外设资源，避免占用 PA5 或更改 LCD。
2. 建立单份在途状态及有界恢复：提交复制颜色并立即返回，DMA 搬运结束不算线端完成；SPI 完成、错误和超时由任务消费。超时／错误后确认 SPI 和 BDMA 停止并清除待处理中断，无法确认则隔离通道并保留缓冲；时基 lease 在事务及恢复期间保持。
3. 让现有 HAL 全局 SPI 回调按句柄分发到 SPI6 或原 SPI 封装，防止两者互相误处理。告警只在对应颜色实际完成后确认；发送期间新颜色保持待处理，旧完成不得确认新颜色，也不得修改 safety 许可。
4. 用生产状态机和 HAL 模型覆盖发送、忙、颜色变化、完成／错误、期限、计数回绕、迟到回调、停止失败、缓存复用及时基平衡；测试 SPI1／SPI2 路径不受影响。运行 WSL Debug／Release、适用 ASan／UBSan 和 ARM 禁热构建矩阵，并核对 SRAM4 链接与资源变化。
5. 更新教学说明和验证证据，按实际软件结果更新 MC02-0084；保持 MC02-0025 的物理波形要求。完成后对提交进行需求和规范审查，不自动推送。

准备异步接口时先发现并修复一处缓存问题：颜色 A 曾完成，B 返回忙后目标又回到 A，旧实现跳过了 A；生产策略回归先失败，修复后 WSL Debug／Release 全量各434/434、该场景 ASan／UBSan 通过，`bench-debug` ARM 构建通过。忙状态现在撤销颜色确认，下次推进会重新提交目标。此步骤尚未实现 BDMA 或完成异步输出。

## 异步输出验证记录

- SPI6 使用 BDMA 通道0、SPI6／BDMA0 中断及 128 字节 SRAM4 固定数组，发送时实际使用124字节；DCache 开启、外设已活动、时基不可用时拒绝启动。共享 HAL 回调按句柄分发，原 SPI1／SPI2 路径继续使用原事务处理。
- DMA 搬运完成不交付成功；SPI 完成后显式关闭可能仍使能的 BDMA 通道，并确认硬件状态后才允许复用和确认颜色。发送20毫秒超时后分轮请求停止，停止检查另给20毫秒；恢复结束即释放时基，失败或无法确认时隔离并保留数组，避免占住其他模块的时基。检查受 Daemon 调度影响，不能当作精确硬件截止时间。HAL 回调不带事务编号，清理待处理中断后可防止常规旧事件重用，不能识别任意伪造回调。
- WSL Debug／Release 全量各 **452/452**；ASan／UBSan 专项 **47/47**，包括生产策略、LED、WS2812、共享 SPI 回调模型、真实线程交错、DMA 搬运与 SPI 完成区分、早到／迟到事件、缓存开启、超时及停止失败隔离。测试只替换 HAL、时钟和必要外设。
- bench_safe、rcdiag、robot single／chassis／gimbal × Debug／RelWithDebInfo 十种禁热 ARM 构建及角色隔离均通过。[ELF 检查工具](../../../tools/workflow/check_ws2812_elf.py)逐个验证 SRAM4 `0x38000000–0x38000080`、32字节对齐及两个中断向量；旧固件缺少相关符号时正确拒绝。
- 与 `ad52ea5` 的 `bench-debug` 同工具链结果相比，Flash 映像 239080→247120 字节，主 RAM 120240→120384 字节，SRAM4 由0增加128字节；DTCM 和 RAM_D2 不变。`robot-single-debug` 主 RAM 使用130680／131072字节，剩余392字节链接余量。此比较包括当前 STM32 HAL 的 BDMA／SPI 中断支持；未测目标执行耗时。

本次没有连接或烧录开发板；结果证明软件数据归属、状态处理、构建和链接，不证明 LED 波形、物理发送时序或亮度。MC02-0025 的灯珠确认和物理回归保持开放。
