## 实现决定

- `MessageTopicDescriptor_t.diagnostics_enabled`决定话题是否出现在只读统计目录中，机器人话题显式启用；关闭的目录项不能从串口序号查询。
- `MessageGetTopicDiagnosticCount()`报告启用项数；`MessageGetTopicDiagnostic()`在一段临界区内复制一项配置、允许与实际端点关系、累计数和队列容量／占用。队列用量按全部已注册订阅者合计，最多64项。
- 发布计数按成功调用一次增加；覆盖按被替换的订阅者队列项数增加；拒绝按满队列导致失败的发布调用增加。过期只在读取者发现时增加：快照槽首次发现过期时记一次，FIFO项被读取并丢弃时记一次。查询不消费消息、不清理队列、不延长期限。
- 计数到`UINT32_MAX`后保持。`peak_backlog`记录所有订阅者队列的历史最高合计占用。
- USART10新增`GET_TOPIC_DIAGNOSTICS`命令`0x04`，请求负载为零起始目录序号。应答负载为状态、schema、序号、启用项总数和54字节记录，总长58字节；整数显式小端编码。每条请求最多读一项，不缓存跨页历史，也不周期发送。健康查询`0x03`保持原字节和120字节限制。
- 机器人角色在应用目录已初始化后注册处理器；失败只关闭该只读导出，不停止控制任务。其他构建没有话题目录或该适配器时，日志协议不对外提供此命令。

### 应答字段

前4字节：状态、schema版本1、请求序号、启用话题总数。接下来的54字节记录：

| 记录偏移 | 字段 | 编码 |
|---:|---|---|
| 0 | 话题ID、负载字节数 | u16 LE ×2 |
| 4 | 数据期限 | u32 LE，毫秒 |
| 8 | 单个订阅者容量、交付方式、满队列策略、源时钟类型 | u8 ×4 |
| 12 | 配置允许的发布端点、订阅端点 | u32 LE ×2 |
| 20 | 当前已登记发布端点、订阅端点 | u32 LE ×2 |
| 28 | 发布、覆盖、拒绝、过期计数 | u32 LE ×4 |
| 44 | 最高积压、发布者数、订阅者数、当前积压、总容量、剩余容量 | u8 ×6 |
| 50 | 查询时刻 | u32 LE，HAL毫秒 |

整个应答帧为66字节，低于现有USART复制队列的128字节上限。诊断序号只用于浏览目录，不是消息序号。
