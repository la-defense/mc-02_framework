## 已实现行为

- v4 记录结构固定为 **336 字节**，保留区固定为 **512 字节**，起始地址 `0x24000000`。链接脚本以 `.crash_record (NOLOAD)` 保留该范围，并为异常读取导出 Flash、DTCM、主 RAM、RAM_D2、RAM_D3 边界。链接断言检查区域起点、终点和容量。
- 记录存有 20 字节 GNU Build ID、profile、板卡角色、编译模块位图、异常寄存器、经过范围检查的硬件帧及最多 32 字栈快照。CRC32-IEEE 覆盖字节偏移 4～331，排除 `magic` 和末尾 CRC。
- 异常路径使用固定布局长度和独立逐位 CRC；不调用公共查表、日志、HAL、RTOS、分配器或 Flash。重入标志留在普通清零区，复位后重新允许下一次记录。
- 可读地址由链接脚本提供；在读取前检查范围表有序且无重叠、地址对齐、长度溢出、完整硬件帧、`EXC_RETURN` 和相关 CFSR 堆栈错误位。读取失败将 `frame_status` 记录为无效，不继续访问寄存器帧。
- 通用只读范围可以包含 Flash，但异常栈和硬件寄存器帧只允许落在标记为 RAM 的区域；主机测试确认对齐的 Flash 地址仍会被拒绝。
- `tools/crash_log.py` 离线检查 v3／v4。v3 只核对固定头部和 CRC，展示 53 个原始负载字，不推测寄存器含义或符号化。v4 只有在完整 Build ID 与所选 ELF 完全匹配时才调用 `addr2line`。归档要求匹配记录、ELF 和 map，并保留文件 SHA-256 清单。
- 专用 `crashdiag-debug` 仅供 bench_safe 单板、禁热和禁用其他诊断配置。普通 ELF 不含自测许可符号。工具只在匹配 CMake 缓存、ELF 和板上 Build ID／profile／role 后向固定 RAM 许可区写一种测试许可；任务先消费许可 magic，再触发一次 `udf`、assert 或 stack hook。工具不发送复位、停核或任意内存访问命令。

## 固定兼容向量

- v4 固定 336 字节零化样例：CRC32-IEEE `0x635E3450`；CRC 覆盖偏移 `[4, 332)`。
- v3 的 212 个零负载字节向量：CRC32-IEEE `0xF6F3E2C3`。旧板上记录固定长度 252 字节，CRC `0x4D3553AC`，保存在本机忽略目录 `build/observations/mc02-0068-legacy-v3-d25a36a806e060bdb94f243adab7b7063c6ab785/legacy-v3-record.bin`；该版本弱身份不用于 PC/LR 解析。
- 自测许可固定 10 个 32 位字，先写字段并回读，最后写 `magic` 发布。主机固定向量使用 Build ID 字节 `00..13`、case 1、nonce `0x12345678`。
