# MC02-0032：CMake 源文件清单自动更新

## 问题与改动

基线为 `bd41764`，分支为 `fix/mc02-0045-bmi088-init`。CMake 用 glob 收集业务源码及 include 目录，但构建系统原先没有检查这些 glob 是否变化。首次在 Windows Ninja 上复现：已有目录 `cmake --build` 成功返回，新加的 `bsp/mc02_cmake_regen_probe.c` 却不在增量编译清单中；对照新配置的编译清单时报告该文件缺失。日志：`build/mc02-0032/red-native/run-20261012-153737-623i5_rw/`。

修复在三个位置加入 `CONFIGURE_DEPENDS`：递归头文件目录收集、基础源码 `GLOB`、业务源码 `GLOB_RECURSE`。现有源码范围、HAL 显式列表、模板排除与 profile 构建方式保留。CI 现在运行新增的 `tools/workflow/check_cmake_regeneration.py`。

## 回归设计

脚本使用 `git ls-files` 建立只包含固件构建输入的隔离副本，所有测试文件写在 `build/` 工作目录。它先配置并完整构建，然后分别新增/删除 bsp、modules、application 源码，新建多层模块、移动源码、移动仅含头文件的目录，并添加/移除被排除的 `_template.c`。每个阶段都只对已有目录执行 `cmake --build`，然后与新配置生成的编译源码集合比较；删除源码还会从 Ninja 链接命令检查。失败和超时保存阶段日志。
