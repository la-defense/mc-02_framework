## 配置与中断基础

CAN 诊断模式切换后的过滤器重装改为按总线执行；重装失败会隔离受影响总线、取消旧发送请求并停止派发待处理反馈，保留其他总线。主机生产实现测试覆盖重装成功时不修改其他总线，以及重装失败时的队列、在途结果和跨总线收发。停止硬件为尽力操作，在途帧是否已发送不能仅凭取消结果判断；该单线程模型不验证调用时的并发协调。

一次性 CAN 回环和 DJI 反馈注入现在由启动协调者在设备注册完成后、周期任务创建前执行；接收和发送由诊断调用本身推进，因此不与电机任务并发。诊断后按车型中底盘、云台、发射及板间桥接的总线配置传播隔离：辅助模块降级，核心或间接核心依赖失败时关断并禁止创建任务。生产依赖传播和协调器测试覆盖两类结果及间接依赖；其他直接调用模式切换接口的调用者仍需满足接口的不并发约定。

新增纯计算的 CAN 过滤器容量规划器：按核心闭包优先、模块需求整体分配，并检查各总线标准／扩展槽和全局端点上限。主机测试覆盖容量不足、跨总线原子性与辅助依赖传播。启动协调者现已将现有车型设备需求和板级容量交给规划器；核心不足在注册前失能，辅助不足由模块启动结果报告。诊断后隔离检查复用同一需求清单。

板级接口现可查询已初始化 FDCAN 句柄的标准／扩展过滤器数量和驱动共用的端点登记上限；未绑定或初始化失败时不写输出，查询不启动总线。生产板级适配器的主机测试覆盖独立槽数、上限截断和失败路径。使用双板测试配置调用生产需求汇总和规划器，已检查四轮、云台、摩擦轮、拨弹及电容的数量映射和核心／辅助容量不足；真实车型配置、启动流程的端到端故障注入及回环诊断临时端点容量仍需验证，不能据此关闭容量验收项。

本次接入后，WSL Debug／Release 主机回归各通过 679 项；新增的需求映射测试还通过 ASan／UBSan。普通禁热、遥控诊断和裁判诊断的 Debug／RelWithDebInfo 六种固件均编译通过。普通禁热 Debug 的 FLASH 为 252240 B、RAM 为 121816 B。这些构建未启用生产电机模块，不能证明真实车型的失败处理；最终验收仍需执行。

继续核对时发现，底盘、云台和发射模块分别注册多个 DJI 电机；后续电机或话题注册失败时，先前成功的电机尚未从电机表、守护监控和 CAN 端点整体回退。电机初始化后默认失能，但这不能代替辅助模块失败后的资源清理。需要增加启动期回退接口并验证共享发送组、剩余端点和失败后的再注册；电容与话题的资源归属也需一并核对。

DJI 驱动现提供启动期单电机回退：守护监控开始后拒绝回退；启动期撤销时释放守护对象和 CAN 接收端点，清除对应发送字节，并根据剩余电机重算发送组。生产驱动的主机测试覆盖同组及跨总线端点保留、空组不发送、重新注册和守护任务运行后的拒绝。该入口尚未接入各业务模块的失败分支，也不适用于运行中的电机。

上述三项启动回退专项在 WSL Debug、Release 和 ASan／UBSan 中均通过；普通禁热 Debug 固件编译通过（FLASH 252240 B、RAM 121816 B）。该固件不启用 DJI 电机，不能据此验证电机固件路径；业务模块集成后仍需补齐 ARM 编译和完整回归。

发射模块现先暂存摩擦轮和拨弹盘实例，最后登记输入话题；任一步失败时倒序回退已注册电机。无法回退时，启动协调者立即记录发射资源故障、锁存整车失能并关断输出，后续模块不得注册设备。生产发射模块配合电机替身的十种电机／话题失败场景，以及生产启动保护函数的关断顺序测试，在 WSL Debug、Release、ASan／UBSan 下通过；带测试宏的 ARM 语法检查通过。Debug／Release 完整主机回归各通过 693 项，普通禁热 Debug 固件的 FLASH 为 252288 B、RAM 为 121816 B。此测试未贯穿真实电机驱动与完整整车协调入口；底盘、云台及电容失败清理也仍需完成。

云台初始化现先检查姿态存储，暂存两台电机，再成对登记控制订阅与反馈发布；失败时撤销已登记电机，回退失败交由启动保护锁存整车故障。消息中心成对登记在同一临界区检查两个句柄和订阅数据区，任一容量不足时均不新增端点，已有端点可复用。生产消息中心测试覆盖发布槽和订阅数据区不足、重复登记及实际消息收发；生产云台模块配合电机和话题替身覆盖五种失败场景。专项在 WSL Debug、Release、ASan／UBSan 均通过，带测试宏的 ARM 语法检查及普通禁热 Debug 构建通过；尚未贯穿真实云台电机与完整协调入口，底盘和电容清理仍待完成。

本次变更后的 WSL Debug／Release 全量主机回归各通过 700 项。主机构建出现过文件时间轻微超前的 clock skew 提示；云台和消息中心新专项已分别重新构建并执行，最终验收仍应复查构建时间与产物。

底盘初始化现先确认双板所需的姿态存储和命令话题期限，再依次暂存四个轮电机、旧电容和成对话题。失败时先回退本次取得的电容，再逆序回退轮电机；任一回退失败都会上报整车启动保护。电容驱动新增仅供启动阶段使用的回退入口。底盘失败注入、旧电容及真实 CAN 注册／队列回退专项在 WSL Debug、Release、ASan／UBSan 下通过；带测试配置的单板和双板底盘 ARM 语法检查通过。生产电容与 CAN 模型的联合测试确认同总线电机端点保留，旧电容接收帧不会进入重注册实例。该测试不代表实物电容协议已确认，真实底盘电机及整车启动协调的联合失败测试仍待补充。

该轮完成后，WSL Debug、Release 全量主机回归各通过 709 项；普通禁热、遥控诊断和裁判诊断的 Debug／RelWithDebInfo 六种固件均编译通过。普通禁热 Debug 的 FLASH 为 252288 B、RAM 为 121816 B。主机构建仍偶发文件时间轻微超前提示，最终验收需复核构建产物。

仍有底层回退缺口：`CANUnregisterInstance` 在硬件过滤器关闭失败时保留槽位，但接口没有返回该失败。现有电机和电容回退能够移除软件端点与旧队列引用，尚不能向整车报告硬件槽未释放；因此不能将资源回退完整性视为已验收，需补充可检查结果及对应故障注入。

默认任务现在先由启动协调者初始化视觉业务，再执行 USB 空配置兜底；此前相反的顺序会使视觉回调注册被传输层拒绝。主机测试核对默认任务顺序，并在生产 USB 传输层验证重复空配置不会覆盖已有接收回调；设备枚举和实际通信仍需裸板验证。CubeMX 重新生成后需检查没有恢复协调者之前的 USB 初始化调用。

## 早期保护的基础组件

启动阶段的日志提交先前会调用 FreeRTOS 任务临界区；调度器未运行时，该端口的初始嵌套计数会阻止退出时恢复中断。日志端口现在在调度前保存并恢复原中断状态，运行期仍使用任务临界区。主机模型覆盖原中断开启／屏蔽、嵌套与运行期选择；实际中断时序仍需裸板验证。

基础启动现在查询日志状态，分别记录 RTT 和诊断串口不可用；状态查询失败单独记录。当前哨兵将日志列为辅助功能，两条出口失败时仍允许其他模块启动。主机替身覆盖单独失败、同时失败和查询失败；运行期可用性继续由日志状态接口提供。

应用启动另外检查车型核心依赖：如果日志本身是核心模块，或被其他核心模块依赖，RTT 不可用或日志状态未知会使模块计划返回核心失败；辅助日志仍允许降级运行。诊断串口作为独立协议通道，不代替 RTT 日志出口。主机测试使用生产依赖计划验证辅助、间接核心依赖与状态未知。

看门狗启动窗口已移到系统时钟就绪之后、GPIO 和外设初始化之前；原 BSP 步骤只检查看门狗是否运行，不再重设它。外设与 ADC 阶段完成且未超过共同期限时，启动入口按进度喂狗。主机检查覆盖早期配置失败和 BSP 拒绝继续，另检查入口顺序；Debug、Release 完整回归和相关 ASan／UBSan 用例通过。看门狗窗口按标称 LSI 估算，真实时长与启动裕量仍由 0128 裸板验证。早期看门狗配置失败使用独立的跨复位原因，记录格式和原有原因编号不变；主机测试覆盖具体原因与恢复额度。

三路受控电源的 GPIO 初始化现在始终先写入关闭电平，再配置输出模式。主机直接编译生产 GPIO 源码，分别用裸板与生产宏检查写入顺序；这只是默认关闭，按配置分阶段开启及依赖检查仍待完成。新增不依赖 HAL 和 RTOS 的有界等待组件，测试固定期限、计数回绕、停止计数、过期就绪及无效参数；它尚未接入 H723 时钟初始化，不能视为硬件时钟等待已受保护。移除活动源码中未使用的 OSPI 示例缓冲；它们先前已被链接器丢弃，因此这一步没有减少 ELF 中的 RAM。

WSL Debug、Release 和 ASan／UBSan 分别通过等待组件 1 项、电源 GPIO 2 项。普通禁热 ARM Debug 构建及 profile 链接检查通过，FLASH 243304 B、RAM 116728 B。当时未执行其余固件组合或硬件测试。

随后将该等待组件接入看门狗寄存器更新：DWT 前进时使用固定周期期限，DWT 停止时使用检查次数兜底。等待会把条件函数本身耗时计入总期限，最后一次检查超过期限也报告超时。直接编译生产看门狗源码的主机模型覆盖 HAL tick 停止、DWT 停止和更新标志不清，WSL Debug、Release、ASan／UBSan 均通过；普通禁热 ARM Debug 固件构建通过，FLASH 243616 B、RAM 116696 B。主时钟和 VOS 等待尚未接入此保护。

任务监控增加可选的延迟放行接口：调度器运行后，尚未放行的周期任务不消耗启动宽限、不接收假心跳，也不会由监控例程喂狗；放行时一次确定所有任务的首次期限，不能重复放行来续期。启动期长操作仍使用原有固定时限，超期时关断并阻止放行。生产监控实现的主机回归在 WSL Debug、Release、ASan／UBSan 通过，普通禁热 ARM Debug 构建及 profile 检查通过（FLASH 243824 B、RAM 116696 B）。接口尚未接入 `RobotInit`／默认任务，启动协调者完整进度喂狗仍待接通，因此不能据此认定启动流程已经迁移。

启动标定新增按有效样本报告进度的接口：仅调度器运行、周期任务延迟放行且 INS 标定窗口有效时生效；样本编号必须递增，最多每 100 ms 喂一次狗，计时停止或重复样本不会续喂，原有 15 秒总期限不会延长。BMI088 只在样本读取和数值检查成功后报告进度；监控拒绝时停止后续采样并报告标定失败。申请新长操作时，若检查其他窗口才发现其已超期，也不再接受新操作。任务监控和 BMI088 分别使用生产实现、各自的主机替身验证，覆盖重复样本、时间回绕、超期、失败采样和拒绝后的停止；WSL Debug、Release 和 ASan／UBSan 通过。普通禁热 ARM Debug 固件构建通过，FLASH 241600 B、RAM 116632 B。协调者尚未调用延迟放行，启动状态、标定和看门狗的完整集成仍需验证；其他设备启动阶段的进度和时限也未接入。

INS 的初始化及失败分类已提取为可由启动协调者调用的 `RobotInitializeIns`：区分 INS 辅助失败、INS 核心失败及已启用温控的核心／辅助失败，核心失败请求整车失能并直接关断；辅助温控失败仍允许 INS 使用。现阶段原 INS 周期任务仍调用该入口，核心温控初始化失败后不再进入姿态周期循环。六种生产启动步骤测试在 WSL Debug、Release、ASan／UBSan 通过；普通禁热 ARM Debug 构建和源码隔离检查通过，FLASH 241616 B、RAM 116632 B。协调者及任务放行尚未连接，不能据此宣称启动阶段迁移完成。

车型任务监控现在依据模块依赖闭包判断 INS 是否为核心：直接或间接被核心模块依赖时为核心，否则为辅助；未启用时不注册监控。辅助 INS 运行故障会通知模块依赖图。任务创建只为已启动的 INS 模块创建任务；启动失败或辅助任务创建失败时，允许在周期运行前移除对应辅助监控，若监控是核心或无法安全移除则拒绝继续启动。生产依赖映射测试覆盖直接／间接核心、辅助、禁用、缺依赖和成环；任务创建与监控测试覆盖辅助失败、移除失败和核心保护。WSL Debug、Release 及 ASan／UBSan 定向检查通过，普通禁热 ARM Debug 构建和源码隔离检查通过，FLASH 242240 B、RAM 116632 B。INS 在当前任务入口初始化后发生的辅助失败仍需随协调者迁移重新处理；尚未进行整车分阶段集成测试。

## CAN 接收异常的初步处理

接收 HAL 返回错误时立即退出本轮 FIFO 处理；超过8字节的 DLC 和 FD 帧不再当作零长度经典帧派发，真正的零长度数据帧仍允许。HAL 在返回帧头前会先复制负载，因此目标缓冲按64字节预留；实际业务帧上限仍为8字节。WSL Debug、Release、ASan／UBSan 的异常帧和读取失败用例均通过，Debug 满队列回归通过。ARM 禁热 Debug 构建通过：FLASH 243304 B、RAM 116696 B；新增的中断栈占用尚需在最终验收量化。

当时尚未完成扩展 ID、过滤器和共享消息 RAM 改造：HAL 按 DLC 从消息 RAM 读取，仅扩大目标缓冲不能证明不会读到相邻元素。后续配置和验证见下方记录。

当前提交的 WSL Debug／Release 完整主机回归各通过 556 项；这不代替尚未实现的启动路径和板级验收。

## CAN 服务按总线启动

端点注册只启动所需总线；首次注册失败只停止本次启动的控制器，不改变其他总线。发送专用用途可使用 `PlatformCanStartBus` 显式启动已完成板级初始化的总线；未启动时发送被拒绝，状态为 UNKNOWN，健康监控也不读取该控制器。现有的车型启动计划尚未按这些入口完成所有外设初始化，板级 FDCAN 时钟的重复启停也仍待处理。

新增的跨总线失败回退用例在 WSL Debug、Release、ASan／UBSan 下通过；Debug 下 CAN 相关25项及 LK／CAN 相关11项通过。普通禁热 ARM Debug 构建和 profile 检查通过，FLASH 243368 B、RAM 116696 B。过滤器槽回收、标准／扩展帧区分和板上行为仍须另行验证。

## FDCAN 共享时钟和退出

`Core/Src/fdcan.c` 用控制器位图管理共享时钟，重复初始化或未初始化退出不增加／减少其他控制器的占用。时钟配置失败时不登记使用者；停止某控制器时先禁止并清除该控制器的两个 IRQ，再退出 GPIO，最后释放时钟。初始化和退出由调用方串行执行；当前时钟配置错误仍进入原有 `Error_Handler`，尚未实现辅助模块可降级的启动结果传播。

直接编译生产 MSP 的主机模型在 WSL Debug、Release、ASan／UBSan 均通过，覆盖时钟配置失败、重复初始化、未初始化退出、跨总线隔离、IRQ 清理顺序及全部退出后重新初始化。普通禁热 ARM Debug 构建通过：FLASH 243384 B、RAM 116696 B；真实外设行为仍由0128验证。

CubeMX 重新生成后应人工核对：`.ioc` 中 FDCAN 的 PLL 时钟与各 GPIO 复用仍符合板卡；`fdcan.c` 中 `USER CODE` 里的使用者位图和六处 MSP 入口／退出钩子仍存在；生成器若恢复原有共享时钟计数及三段重复配置，须与位图实现合并，不能同时保留两套计数；三个退出路径仍须先禁止、清除相应 IRQ，再释放 GPIO 和共享时钟。合并后重新运行 `production_fdcan_msp_shared_clock` 与固件构建。此检查目前为人工流程，未声称重新生成已经自动保持修改。

## 经典 CAN 扩展标识符与消息 RAM

端点明确声明标准／扩展 ID，零初始化保持标准帧。登记与派发按总线、类型和完整 ID 区分；硬件过滤器槽按总线及类型分别管理，注销成功后可复用，关闭失败时保留占用，避免覆盖未确认关闭的槽。既有 DJI、LK、DM、HT 驱动只使用标准帧，错误选择扩展类型时拒绝初始化。发送与接收业务仍限制为经典 CAN、最多8字节。

每条 FDCAN 配置14个标准和16个扩展过滤器，两个接收 FIFO 均为4项。当前 HAL 按 DLC 复制负载，因此接收元素预留64字节，避免异常 DLC 的读取跨过硬件元素；发送元素仍为8字节。每条控制器占用254个 SRAMCAN 字，比先前配置多144字；编译期检查三个固定区域互不重叠且落在 HAL 声明的0x2800字节范围内。`.ioc` 同步设置这些参数，并将原先与生成代码不一致的发送 FIFO 数量由4改为16。尚未用 CubeMX 实际重新生成，重新生成后必须人工核对 `.ioc` 选项、代码与检查公式。

WSL Debug／Release 完整主机回归各通过560项；扩展端点、容量及回退场景和 MSP 配置检查通过 ASan／UBSan。普通禁热 ARM Debug 构建及 profile 检查通过：FLASH 243440 B、RAM 116696 B；真实过滤、SRAMCAN 访问及中断栈余量仍待0128验证。过滤器重装失败的上报、按车型确定硬件过滤容量及启动时资源检查仍未完成。

## 看门狗配置失败的传播

致命错误入口现在先关断输出，再记录故障；有恢复额度时清除旧复位标志并请求软件复位。恢复锁定或复位意外返回时保持关断，并直接重载可能跨复位仍在运行的独立看门狗，避免仅靠空循环导致连续复位。主时钟失败入口采用相同的锁定处理。主机替身核对关断、记录、清标志和复位的顺序，以及锁定时的寄存器写入；硬件看门狗是否跨复位运行及实际电平仍需板测。

上述致命错误及主时钟失败专项在 WSL Debug、Release 和 ASan／UBSan 中通过；普通禁热 ARM Debug 编译通过，FLASH 243944 B、RAM 121880 B。完整回归及其余固件配置仍需在最终验收时复核。

H723 主时钟启动对 HAL 电源、振荡器和时钟切换调用增加固定总周期与查询次数保护，并将 VOS 等待改为独立的有界检查；完成切换后还检查 HAL 原始 tick 前进。到期时 HAL 接收的临时时间偏移不会写入真实 tick，外层始终拒绝超期结果。失败先关断并记录具体阶段；未锁定时清除已读取的复位标志后请求软件复位，锁定后保持关断。恢复记录保留已标记的具体故障原因，复位额度规则不变。周期与次数上限基于 64 MHz 复位时钟和 480 MHz 切换后时钟估算，真实时序、寄存器行为和上限须由板测核对。主机直接运行生产保护适配器和恢复策略，注入 VOS 不就绪、原始 tick 或周期停止、总期限、复位和锁定；它不代替硬件测试。CubeMX 重新生成后须人工核对 `main.c` 中的保护入口、失败分支、时钟参数及 HAL 中所有等待的超时条件。
