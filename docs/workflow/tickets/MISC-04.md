# MISC-04：超级电容接口与未选型边界

## 实施计划

从 `140af58` 建立本轮分支，保留 MC02-0022 已提交的软件成果及其尚待核实的赛规限制。电容设备尚未选型，本轮不认定现有 CAN ID、原始字段比例或电压／电流单位适用于实物，也不连接电容、执行器或开发板。

1. 核对当前单例注册和 CAN 所有者、初始化失败回退、帧长度、缓存和发送结果；拒绝空参数及长度不足的控制缓冲，保留现有固定8字节协议输出和 CAN 提交结果，不改用裸指针推测长度。
2. 反馈至少含三个16位原始字段才接收；保存 CAN 接收事件原始毫秒时间，坏帧不刷新。提供复制读取和明确的未收到／新鲜／过期状态，期限由调用方显式提供，单位为毫秒、边界允许，不把未经确认的原始值解释为物理量或功率许可。
3. 核对普通供电回退是否已有可信实现；如没有，不能通过删除电容启动检查放宽底盘条件。缺失的实际功率限制和回退条件留作开放验收，未收到、过期或未选型不产生电容额外功率授权。
4. 用生产注册和接收回调及 CAN 模型测试：唯一实例、分配／注册失败、0～8字节帧、时间零与回绕、过期边界、读取一致性及发送源缓冲／长度／错误。使用真实底盘初始化路径验证电容不可用时不影响核心资源失败处理。
5. 执行 WSL Debug／Release 主机回归、适用的 ASan／UBSan 及所选 ARM 禁热构建／ELF 检查，记录资源变化。更新模块说明、学习笔记及索引，明确未选型和物理验证边界。验收通过后更新 TODO、审查已提交差异并本地提交，不推送或创建 PR。

## 已发现的回退缺口

`PowerManagerFeedback()` 和 `PowerManagerUpdate()` 尚未执行功率计算；底盘未接入可验证的普通供电限制。仅删除 `cap == NULL` 判断会改变可启动条件，却无法证明功率回退，因此本轮保持原判断。完成该项全部验收需要可信功率限制方案、对应许可和参数；不能以主机替身或电容未连接的现象代替。

## 本机验证证据

WSL Debug／Release 全量均通过458项；新增4个独立进程覆盖分配／注册失败、长度、时间边界与并发复制，ASan／UBSan 4/4。Release 编译器将分配后清零优化成 `calloc`，测试替身同时覆盖 `malloc` 和 `calloc` 后再通过。CAN后端由模型替代，真实设备协议和物理通信未验证。

bench_safe、robot-single、robot-chassis 各 Debug／RelWithDebInfo 共6种禁热固件构建通过。`robot-single-debug` 相对本轮基线 Flash 293764→293836字节，主 RAM 130816字节不变，仍仅余256字节；此数据不能证明运行时栈余量。未连接硬件。相关教学见[学习笔记03](../../学习笔记/03-非阻塞通信与CAN收发技术细节.md)。
