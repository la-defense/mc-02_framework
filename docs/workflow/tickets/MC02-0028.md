# MC02-0028：RobotCMD 消息路径性能记录

## 计划范围

先对生产消息路径建立耗时和复制量基线，再只优化测量确认的无效读取；保留线上控制字段、来源优先级、有效期和安全归零行为。回归覆盖单板、双板、旧版／V2协议及无效输入路径。验证限定 WSL 主机测试和 ARM 固件构建，不做硬件操作。

## 定位结果

`RobotCMDTask()` 每周期读取云台反馈和遥控快照，并发布控制命令。底盘反馈快照则只写入 `chassis_fetch_data`，没有任何后续读取：单板通过消息中心订阅、复制9字节并进入临界区；云台板调用 `CANCommGetSnapshot()` 后同样只保留未使用结果。该读取不参与模式选择、控制计算或安全输出。

## 改动

删除这份无消费者的底盘反馈订阅和周期快照读取。单板仍发布底盘命令；云台板仍注册 CANComm 并发送底盘命令，其他有效反馈和控制输入路径不变。双板生产任务回归明确检查不再请求此快照，且继续发送安全零输出。

新增 `robot_cmd_perf_test`，通过链接包装器统计生产 `RobotCMDTask()` 每轮调用的 `memcpy` 字节数；另用不带包装器的 `robot_cmd_time_test` 测量线程 CPU 时间，避免拷贝计数插桩影响耗时数据。测试先预热，再在固定输入下执行100组、每组50,000次生产任务。计时分位数来自每批平均值，不是单次函数的 WCET。

## 基线和改后测量

基线源取本分支父提交 `8b352236acb56d336e9ea0cf9041749a6edadb6c` 的 `application/cmd/robot_cmd.c`，与改后版本使用同一 WSL Release 主机工具链、编译选项、测试输入和测量程序。两份二进制固定在同一可用 CPU 11 上，交错运行5次；每次计时程序包含5,000,000次采样任务调用，拷贝量由独立插桩程序测量。

为保留可重复的比较过程，新增脚本从 `compile_commands.json` 取得当前目标参数，读取基线提交中的 RobotCMD 源码并替换链接命令中的单个对象。脚本检查基线是当前提交的祖先、计时源码和构建文件干净，按同一 CPU 交错运行两组目标，并将逐次数据保存为 JSONL。复测命令：

```sh
python3 tools/workflow/compare_robot_cmd_performance.py \
  --baseline-ref 8b352236acb56d336e9ea0cf9041749a6edadb6c --runs 5
```

默认原始记录写到 `build/mc02-0028-comparison.jsonl`；该目录被 Git 忽略，重新运行脚本可生成新会话，不覆盖提交中的代码或记录。

| 指标 | 基线中位数 | 改后中位数 | 变化 |
|---|---:|---:|---:|
| `memcpy` 字节／任务调用 | 51 B | 42 B | −9 B（−17.6%） |
| 每批均值 P50 | 77 ns | 60 ns | −22.1% |
| 每批均值 P95 | 94 ns | 81 ns | −13.8% |
| 100批均值最大值（五次运行中位数） | 98 ns | 84 ns | −14.3% |

计时指标是 WSL 主机测得的线程 CPU 时间；P50、P95和最大值均基于每组50,000次调用的批次均值。“最大值”一行是五次运行所得100批最大均值的中位数，不是单次任务最坏时间，也不是 ARM 的 WCET。每轮固定少复制9字节是稳定结果，主机计时只说明同一环境下生产路径对比。

## 验证证据

- WSL GCC Release 基线与改后测试使用相同输入、批次和 CPU 亲和设置；拷贝计数固定为51 B→42 B。计时程序采用 `CLOCK_THREAD_CPUTIME_ID`，不包含复制计数包装器。
- WSL GCC 11.4 主机全量 Debug／Release 各415项通过；RobotCMD 相关ASan／UBSan测试8项通过。生产路径回归覆盖单板任务、安全归零、视觉/V2 路径和双板不再读取无用反馈。
- ARM GCC 十种固件预设通过：`bench-debug/rel`、`robot-single-debug/rel`、`robot-single-v2-debug/rel`、`robot-chassis-debug/rel`、`robot-gimbal-debug/rel`；这里只验证交叉编译和链接。
- 本轮不连接板卡。WSL 时间不代表 STM32H723 的执行周期、任务调度延迟或控制周期上界；双板 CAN 收发和硬件总线负载仍需各自的实物验收。
