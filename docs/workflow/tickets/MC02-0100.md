# MC02-0100：只读观测整合与旧探针退役

本票据记录实现、软件验证和裸板证据；唯一状态见 [.Doc/TODO.md](../../../.Doc/TODO.md)。观测只用于诊断，不参与控制许可。软件验收采用 WSL 主机测试与 ARM 固件构建，不运行 Windows 原生构建。

## 已定范围

- 默认执行30秒性能观测，每秒采样一次；会话独立保存 `raw.jsonl` 与 `summary.txt`。
- 所有快照先将 ELF Build ID、固件身份记录和链接 RAM 边界相互核对，再读取固定白名单字段。缺失标识、布局或目标运行状态不符时停止，不猜地址、不读后续业务字段。
- 复用约5秒统计发布，不增加任务和运行期分配。任务、DWT、CAN、LCD 组分别保存编号和发布时间；重复编号不作为新数据，组间发布时间不互相替代。
- `tools/rtt_monitor.py` 使用 OpenOCD 原生 RTT 服务，匹配 ELF 的 `_SEGGER_RTT` 地址和大小。客户端只接收，不写 RTT 环形缓冲；此入口与 RAM 快照独立。
- 删除旧 `tools/probe_snapshot.py` 和 `tools/rtt_dump.py`。HIL-10 与旧代码审查报告保留当时方法及局限作为历史记录。

## 实现记录

- `bsp/observation/` 在输出关断后登记 profile、板角色、已选模块和 GNU Build ID；身份记录位于固定主 RAM。链接器保留 Build ID note 与身份模板，未加入启动任务或控制接口。
- LCD 原有统计发布后调用 `BSPObservationCapture()`。统计结构以固定布局、generation 和 sample id 发布；CAN 通过 `CANGetObservationCounters()` 复制纯软件累计计数，不查询外设寄存器、不触发恢复。
- `tools/probe_snapshot_live.py --performance` 支持5～300秒窗口、每次读取总超时、单调时钟调度、错过时点不追赶、部分记录保存和明确退出码。摘要区分未启用、未采样、过期、不可计算；不会把任务计数比例称为精确 CPU 占用率，也不会把最大观测耗时称为 WCET。
- 每次会话记录命令参数、CMake配置、ELF路径和SHA-256、Build ID、目标身份、原始样本及错误。Build ID用于匹配链接映像；SHA-256校验本地ELF文件，两者都不等同于整片Flash逐字节验证。

## 裸板验收

用户报告本轮板端输入23.9V、电源实际显示0.08A；电源设定24V、限流0.5A。仪表为德力西DLX890D+，显示分辨率0.1V，未找到精度规格；用户称新出厂、无校准记录。电源型号及完整可调范围未知，用户确认覆盖12～24V。上述电压、电流及连接信息来自用户现场报告，未由软件独立读取。现场仅接LCD、DR16、DAPLink，无电机、舵机或发射机构，板向DAPLink供电。

烧录前保存整片1 MiB Flash，SHA-256为`9cb60833d238ccc3768b305cdb5316ed5c98a07227b052494dfd772a20ba8ae9`；参数区262,144字节的SHA-256为`413f4da1afa9483a6bf156cb7124f05276927eb843ce5d040c85725257120de4`，且与整片备份对应区间逐字节一致。烧录匹配的`bench_safe Debug` ELF并由OpenOCD报告verify通过；烧录包装脚本随后在保存配置时出现`Namespace.no_save_profile`属性异常，故进程最终返回错误，但该异常发生在烧录和verify成功之后。烧录后重新读取参数区，与烧录前SHA及内容逐字节相同。

匹配固件身份为GNU Build ID `d25a36a806e060bdb94f243adab7b7063c6ab785`，ELF SHA-256为`83a6f75f8cf70c74716595f50a05e3712cc534ac9c60eef4738f1ddf274ecb14`。另一份有效`rcdiag` ELF（Build ID `465836e65a93aec1fb3c37eada050f0abac8fe1d`）在身份地址与目标布局兼容时被明确判为固件身份不匹配；JSONL只含session、identity和error记录，没有sample业务字段读取。

最终连续只读窗口保存在`build/observations/mc02-0100-final-session-20261022/`。COM14连续采集85.184秒，共732,505字节、17,035个43字节SP状态帧；CRC错误、非有限四元数、重同步字节及尾部残留均为0，四元数范数范围`0.9983132514～0.9983140335`，串口发送字节数为0，原始记录SHA-256为`60c618a8d92cace0ac3b635dafc173da35df040075f43efa14a4daf41cb0b3f3`。该连续窗口覆盖下面两份报告的全部60个样本时间戳。

- `observations/20261022T111948.163834Z_16512/`：30个样本，tick从1,263,289递增到1,292,307；所有分组可计算，JSONL重算摘要与保存摘要一致。
- `observations/20261022T112019.985323Z_23832/`：30个样本，tick从1,295,113递增到1,324,119；所有分组可计算，JSONL重算摘要与保存摘要一致。此窗口启用了原生RTT接收器，RTT无新字节输出；之前的原生RTT接收窗口保存了1,019字节启动日志，最终会话的实时状态日志在`build/observations/mc02-0100-final-20261022/native-rtt.bin`。
- `acceptance-check.json`记录了报告重算、两份报告均处于同一连续串口窗口、替代ELF拒绝、整片备份和参数区比较的自动检查结果。最终窗口的RTT接收器没有写入或发送数据；既有启动日志含一条无时间戳的历史HardFault记录，计数1，无法据此判断其发生时间。85秒观测期间tick、IMU序号和SP帧序号持续递增，IWDG复位标志为0，未观察到新增复位迹象。
- 观测后IMU状态为valid，初始化阶段9且错误为0；样本序号从1,427,217递增到1,429,359，加热占空比为0。安全快照显示`estop_latched=1`、`enable_requested=0`、`accepted_frames=0`、`fault_flags=0`、`iwdg_reset_flag=0`。三路CAN均未启用／无总线流量。本轮没有连接或使用CAN发射器，也没有注入控制帧；软件许可状态表明输出保持关闭，但未用仪表测量引脚电平。VIN精度、温升及电源轨未在本轮测量。
