## 验收计划

- 使用生产快照／事件接口测试初始化前查询、复制失败、字段时间、事件排序、容量覆盖、序号回绕、首次失败保持及并发读取一致性。
- 使用生产聚合入口与模块状态替身测试单板／双板启用项、模块未初始化／未选择、通信与裁判有效期、温控字段及 USB 剩余额度；缺少来源状态不能伪装成有效。
- 覆盖健康查询不推进状态、不刷新数据时间；初始化事件写入及健康更新无动态分配，记录由一次受保护的复制发布。
- USART10 诊断导出使用既有 `D3 6C`、版本1和`CRC16_MODBUS_A5`帧；请求命令`0x03`、序号回显、118字节固定快照编码加状态／schema，共120字节应答负载，帧总长128字节。应答经现有复制发送队列，不输出日志文本或改变安全许可。
- 初始化历史由固定RAM环保存16项并提供复制读取。串口健康快照携带最近启动失败摘要；完整事件环通过只读快照 API 查询，不新增事件分页命令。
- 运行 WSL 全量 Debug／Release、适用的 ASan／UBSan 和五种角色各 Debug／RelWithDebInfo 共10种禁热 ARM 构建；核对 ELF 配置隔离、严格格式告警、浮点 ABI、无 fast-math 和 RAM 增量。
- 实质更新学习笔记21和索引；完成文件规范、本地链接、TODO 合约及差异空白检查。全部验收通过后才在 TODO 关闭 MC02-0065；其余 TODO 不变。

## 完成记录

### 实现

- `VehicleHealthProcess()`复用现有模块快照，每50ms从普通 `RobotTask` 更新一次；复制查询不推进采样。模块掩码区分编译启用、当前可用和降级状态。
- 初始化诊断记录最多16条阶段变化、失败及READY事件，保存HAL毫秒时刻、模块、资源、原因和严重程度；查询按旧到新复制。原首次失败字段和失败计数保留。
- USART10命令 `0x03` 在同一解析／CRC路径内查询健康处理器，健康数据按小端固定偏移编码，不依赖C结构体填充。健康尚未首次发布时只回复未就绪状态和schema。
- 118字节版本1健康体末尾含一个零值保留字节；温度使用0.01°C有符号值，`0x8000`表示无效／越界。未知系统复位额度使用`known=0`并保留`UINT32_MAX`哨兵；当前没有温稳判据时明确`known=0`。PWM字段表示软件比较值，不冒称物理电流或温升。

| 健康体偏移 | 字段 | 编码 |
|---:|---|---|
| 0 | schema | u8，当前1 |
| 1 | 序号、发布时间 | u32 LE、u32 LE |
| 9 | 角色、启用／可用／降级模块 | u8、u32 LE×3 |
| 22 | 初始化失败、阶段、模块、原因、资源、计数、心跳 | 按字段顺序：u8×4、u16 LE、u32 LE×2 |
| 36 | safety 状态、故障位、急停、任务监控故障位 | u8、u32 LE、u8×2 |
| 43 | IMU有效、标定有效、采样时刻、样本序号 | u8×2、u32 LE×2 |
| 53 | 遥控、视觉及裁判状态／源时刻 | 按头文件字段顺序；掩码和时间为u32 LE |
| 86 | 三路CAN状态及Bus-off计数 | u8×2、u16 LE×3 |

应答负载开头为处理状态、schema，再接118字节健康体；未就绪应答只有前两字节。USART10只扩展读取命令，不承载日志字符串。完整启动事件环可由`VehicleHealthGetInitEvents()`复制读取；本轮不增加分页协议。

### 验证

验证均在 WSL 完成，未连接开发板，也未运行 Windows 原生构建。

- 主机 Debug：`cmake --build --preset host-debug -j4`，`ctest --preset host-debug --output-on-failure`，400/400通过。随后将健康诊断注册错误映射细化为独立状态，四种角色定向回归再次4/4通过。
