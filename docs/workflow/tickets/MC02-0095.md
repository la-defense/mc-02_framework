# MC02-0095：配置化裁判 UI 与分批重绘

任务状态只在 [.Doc/TODO.md](../../../.Doc/TODO.md) 维护。本记录说明实现边界和本次软件验收证据。

## 目标与当前缺口

裁判接收、只读分组数据和 REF-03 发送额度已独立完成。本任务开始时，UI 仍显示自动变化的演示值，没有按哨兵配置布局、样式或真实只读来源；机器人身份过期后不能自动重绘。

## 本次范围

- 在机器人配置中提供有界的只读裁判 UI 布局：字段来源、短标签、三字节图形名、位置和样式；当前哨兵显示真实裁判快照中的比赛阶段／剩余时间、血量、底盘功率上限、缓冲能量和17mm热量。
- 每次 UI 服务复制一份裁判数据用于同轮格式化；来源字段未新鲜时显示 `--`，不把旧值继续标成有效。
- 删除运行时演示数据修改。初始化、恢复和人工重绘按配置字段数拆成有界多帧；连续变化只保留最新字段，维持单个在途帧、REF-03 发送额度和不少于115ms的启动间隔。
- 裁判身份数据过期后停止刷新并撤销在途旧代；身份重新有效后自动进行一次完整重绘。保留 `MyUIInit()` 作为显式人工重绘入口。UI 发送/渲染失败只影响显示，不影响裁判接收或整车许可。

## 实施计划

1. 添加纯配置描述及有界校验，并把哨兵布局放入机器人配置。
2. 将 UI 状态机改为消费裁判只读快照、版本化增量更新和有限初始化／恢复重绘。
3. 先扩展生产接口主机回归，再运行 Debug／Release、ASan／UBSan 和 UI 启用固件检查。
4. 更新模块说明、学习笔记与索引；软件结果确认后关闭 TODO 并提交。硬件客户端显示不在软件验收范围内。
