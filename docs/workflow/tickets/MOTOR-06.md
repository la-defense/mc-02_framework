# MOTOR-06：舵机注册索引与发送缓冲区隔离

## 范围

修复 `ServoInit()` 的参数、实例分配、重复 ID 和底层注册失败处理；按 `servo_id` 保存稀疏实例，并使用现有 UART 复制队列验证多路在途帧互不覆盖。保留舵机命令格式、位置字段、固定设备编号和 PWM 计算行为。本任务不连接舵机，不验证设备协议和机械动作。

## 实现约定

- 注册ID范围为0～6，同ID跨类型也视为重复。
- 注册仅在启动阶段串行调用；成功对象长期保存，没有本轮新增的注销接口。
- 输入配置只读。参数、分配或底层UART／PWM注册失败返回`NULL`，失败候选不会写入实例表。
- UART回调的上下文使用成功注册的长期舵机实例。
- 总线发送继续生成旧16字节命令并提交现有每UART复制队列，不修改固定设备编号。

## 验收证据

生产调用方测试应覆盖空配置、无效ID、无效类型、稀疏ID、重复ID、重复UART、底层PWM注册失败、失败后空槽重用及并行UART传输时的固定帧字节。新增和已有检查均在WSL Debug／Release运行；固件构建使用现有禁热ARM预设。

## 验证记录

- 生产调用方场景`production_uart_caller_servo`覆盖空配置、越界ID、无效类型、空UART、稀疏ID 1／6／3／0、重复ID、重复UART、候选分配失败、PWM注册失败及失败后的ID复用。
- 两路UART同时启动不同舵机帧时，逐字节核对两份16字节帧；第一帧仍在途时再提交本路下一帧，确认在途字节不变，首帧完成后队列发出后续数据。
- WSL `host-debug` 全量CTest：416/416通过；`host-release` 全量CTest：416/416通过。Release下分配失败注入同时拦截`malloc`与优化后可能出现的`calloc`。
- WSL `host-motor-asan` 的舵机调用方场景：ASan／UBSan通过。
- ARM禁热预设`bench-debug`、`bench-rel`、`rcdiag-debug`、`rcdiag-rel`及single／chassis／gimbal的Debug／RelWithDebInfo共10种均构建成功。当前显式固件源码清单没有纳入未被应用引用的舵机模块，故这些固件构建为增量无重编；舵机实现由上述主机目标直接编译并链接生产UART队列验证。
- 未连接开发板或舵机；没有验证线路波形、舵机协议解释或机械动作。
