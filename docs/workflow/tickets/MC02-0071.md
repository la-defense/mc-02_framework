# MC02-0071：任务事件与来源状态

## 目标

把来源监控从 Daemon 任务调用次数改为 HAL 毫秒时基的绝对期限，并把来源状态变化交给有界事件接口。来源通信在线、关键数据有效和模块恢复分别记录；监控任务不直接运行来源恢复逻辑。

## 实施决定

- 保留最多64个启动期登记的来源实例；每项独立配置通信期限、数据期限、首帧宽限、事件策略、事件容量和唯一消费者。
- 期限单位为毫秒，采用无符号时差比较；配置值不超过 `INT32_MAX`，零时刻与回绕合法。
- 首帧状态依次为等待首帧或离线；收到协议合法帧后通信在线。关键数据有效另按自己的接收时刻和期限判断。读取状态不续期。
- 来源只在接收方已校验通信帧后报告通信有效。语义数据不合法时可以报告“通信在线、关键数据无效”；协议校验失败不更新通信期限。
- 每个来源的状态事件只允许一个消费者，支持保序 FIFO、同状态计数和最新状态合并；事件有最大年龄，过期丢弃并计数。队列满时拒绝新事件并记录溢出。
- 已有模块任务通过生产事件处理接口消费所属事件。可选独立事件任务使用固定入口和有界轮询；创建失败、溢出、过期均可查询。独立任务回调是来源模块的有限事件处理步骤，不在监控任务中执行。
- 保留既有来源超时：CANComm沿用其配置的计数并明确折算为10 ms单位；DJI 20 ms；DM 100 ms；HT04／LK／XM 50 ms；Remote 100 ms；裁判300 ms；视觉V2 300 ms、SP 50 ms。启动宽限以旧默认100次 Daemon 调用折算为1000 ms。
- 离线处理不自动重复重置。HT04沿用每个离线事件至多提交一次模式请求，其余只做原有清理或诊断；恢复后再次失联才会产生新的离线事件。

## 验证边界

主机生产接口测试覆盖边界、回绕、首帧宽限、通信／数据分离、非法帧不续期、三种事件策略、唯一消费者、队列溢出和事件过期。适用调用方回归及 WSL Debug／Release、专项 ASan／UBSan、六种 ARM 禁热构建后，可关闭本项。当前板为 USB-only，本任务不烧录，也不把主机事件测试解释为实体通信或恢复验收。

## 后续

MC02-0067的静态关断、看门狗与复位期间实体输出行为仍保持原状态；本任务只处理通信来源状态与模块异步事件。

## 实现与最终验证

- `DaemonReportAt()` 现在使用收到帧的原始 HAL tick，先按当前时刻结算超时，再接收尚在期限内的帧，避免旧排队数据把已离线来源误报为恢复。`DaemonGetSourceStatus()` 分别复制通信和关键数据年龄；查询不续期。
- 每个实例固定一种事件策略和唯一消费者。监控任务只更新状态并入队；MotorTask、RobotCMDTask消费绑定事件，独立模式用固定1ms任务每轮最多处理8条。状态读取和实例注销均受短临界区保护；开始监控或消费后禁止注销。独立任务创建状态先于任务启动发布，避免新任务抢先轮询时误报“消费者未启动”。
- 远程控制的来源时间测试拆成零时刻和回绕两个独立进程，避免同一进程倒拨模拟时钟。
- WSL Debug 与 Release 全量 CTest 各 **413/413**；来源／事件 ASan／UBSan 覆盖 **11/11**。Release 检查保持生效。
- bench_safe、rcdiag、robot-single 的 Debug 与 RelWithDebInfo 共六种 ARM 构建通过，GCC 10.3.1。六份产物的 `check_firmware_profile.py` 源码清单、Compile DB、链接输入和角色隔离检查全部通过。
