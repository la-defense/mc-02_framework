# MC02-0057 四轮全向速度与本地里程计验证

## 速度估计

- 目标轮速与估速共用轮位、滚动方向和轮径。最小二乘估计输出前、左、上坐标下的底盘中心速度。主机用不同轮径及非对称轮位的手算速度检查结果，并拒绝非有限输入和退化轮组。
- 底盘任务读取四轮的 DJI 输出轴速度，检查有效性、单位和参考位置。主机注入跨毫秒回绕、等待超过原始期限、错误单位和资源撤销。发布者停更时，读者仍按最早轮速接收时间判定有效性。
- 底盘专项 29 项通过。运动学、全向轮速度发布、双板话题失效和桥接过期恢复共 4 项通过 ASan／UBSan。四个独立 ARM 对象验证了本地接口以及全向轮估计的编译选择。对象检查未链接正式固件。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过，WSL Debug／Release 各 822/822。普通裸板、遥控诊断、TIM5 自测及观察版通过 ARM 构建与 ELF 隔离，FLASH 和 RAM 用量沿用上轮。六种正式预设仍因核心配置未确认而拒绝。
- 本阶段验证本地速度和原始来源时间。实车几何、打滑识别、其他参考系及实际运动测量未覆盖。

## 可选本地里程计

- 配置字段 `odometry_max_gap_ms` 为 0 时关闭里程计，正值启用全向轮里程计并限制相邻来源时刻的间隔。主机验证了合法配置、非全向轮启用被拒绝以及间隔超过 32 位时间的可比较范围时被拒绝。哨兵间隔待实测，当前配置为 0。
- `Chassis_GetOdometry` 返回本地位姿、原始轮速时间及段号。专项测试覆盖时间回绕到 0、重复和乱序样本、轮速无效、样本间隔超限、发布者停更及释放资源。样本失效后不沿用旧原点。数值测试用半径 1 m 的四分之一圆弧检查转向积分，并覆盖直行、航向跨越 π 和异常输入。
- 速度、里程计、运动学和配置校验 4 项通过 ASan／UBSan。麦轮和全向轮各完成 4 个 ARM 对象的独立编译，全向轮底盘引用积分函数。相同编译选项下，`ChassisTask` 自身栈帧分别为 240 B 和 256 B，和改动前相同。全向轮新增的 `UpdateOdometry` 自身为 16 B，未测整条调用链的峰值栈用量。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过，WSL Debug／Release 各 823/823，底盘及板间桥接专项 35/35。普通禁热和遥控诊断通过 ARM 构建与 ELF 隔离检查，两者 Flash 各增加 4 B，分别为 257360 B、260904 B，RAM 分别为 122168 B、122680 B。六种正式预设仍因核心配置未确认而拒绝。
- 里程计只在本板接口提供，原板间帧保持兼容。实际反馈间隔、轮组几何、打滑及位置误差留待现场测量。

## 手动平移的方向反馈

- 生成配置的大 yaw 参照在发布前重读云台反馈，使用同一条数据计算方向角和有效期。原采样期限、原话题期限及人工输入期限取最先到期者。测试覆盖毫秒回绕、发布前过期、显式撤销、单圈编码器越界及新方向恢复。底盘本体参照测试继续输出零方向偏移。
- 生成配置、新版协议和单位换算共 7 项通过 ASan／UBSan。用单板和云台板、SP 和 V2 两种协议分别编译本地 ARM 对象。与同工具链基线相比，`RobotCMDTask` 静态栈帧增加 48 B，SP 为 344 B，V2 为 376 B。未测板上栈高水位和执行时延。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过，WSL Debug／Release 各 824/824。普通禁热和遥控诊断通过 ARM 构建与 ELF 隔离检查。两套诊断沿用既有 ELF，其源码清单不含命令任务；命令任务由上述 ARM 对象检查。六种正式预设因核心配置未确认而拒绝。
- 单板可以携带角度反馈的短期限；旧板间话题不能表达短于 50 ms 的来源期限，这类命令保持拒绝转发。未启用新的生产参考系，枪口与场地参照仍待对应来源和变换接线。

## SI 方向转换与输出前复核

- 麦轮与全向轮共用 `ChassisMotionRotateToBody`。旧消息在旋转前换算成前左上坐标，旋转只改变平移分量。主机测试覆盖 ±90°、原位转换、非有限方向及投影相加溢出，并重跑旧的速度上限、轮速符号和旋转向量。
- V2 导航是底盘本体坐标。命令侧把左向速度换成旧消息的右向速度，将方向角置零。回归在云台偏转 90° 的输入下检查 V2 横移符号及零偏移，既有导航授权和超期回归继续通过。
- 单板底盘算完轮速后再次核对消息序号和来源期限。测试令计算开始时来源刚好有效、提交前跨过期限，检查四轮停止并清零。双板沿用同一复核入口，本地许可和恢复回归继续通过。底盘运动、任务、反馈、板间桥接及 V2 共 7 项通过 ASan／UBSan。
- 单板及底盘板的麦轮／全向轮底盘代码、单板及云台板的 V2 命令代码分别通过独立 ARM 对象编译。与同工具链基线相比，单板 `ChassisTask` 静态栈帧仍为 240 B／256 B。底盘板移除重复副本后，自身栈帧由 320 B／336 B 降至 264 B／280 B。未测调用链峰值和板上运行耗时。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过，WSL Debug／Release 各 824/824。普通禁热和遥控诊断通过构建及 ELF 隔离检查，Flash／RAM 分别为 257360 B／122168 B 和 260904 B／122680 B，与基线相同。正式哨兵的六种预设仍因核心配置未确认而拒绝。当前本机证据覆盖底盘与大 yaw 方向，更多参考系、实际停止时延与运动精度仍待验证。

## 裁判功率数据的独立期限（R25-15）

- `RefereeGetChassisPower` 同时复制 `0x0201` 功率上限和供电许可，以及 `0x0202` 缓冲能量的独立接收时刻和期限。控制读口只交付有效值。生产解析器回归覆盖时间零、过期边界、已判定过期后跨整轮计时、同组新帧恢复，以及当前与晚到离线事件。
- V2 导航的功率检查使用上述接口。回归覆盖上限帧和缓冲帧各自的有效期、零功率上限、供电许可撤销，以及导航选定后发布前失效。可发布的导航继承最先到期的依赖。两项生产入口测试通过 ASan／UBSan。
- 单板和云台板的 V2 命令独立 ARM 对象编译通过。相同选项下，`VisionV2NavigationAllowed` 自身静态栈帧由 1376 B 降至 48 B，`RobotCMDTask` 自身仍为 376 B。未测板上峰值和读口耗时。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过，WSL Debug／Release 各 824/824。普通禁热和遥控诊断通过 ARM 构建和 ELF 隔离检查，Flash 和 RAM 用量与上轮相同。另行用 `refdiag-debug` 构建并通过裁判诊断 ELF 检查，Flash 264096 B，主 RAM 128152 B。六种正式预设仍因核心配置未确认而拒绝。
- 本轮验证裁判数据的来源与撤销。普通供电模型、保守功率余量、电容传输协议及实际限功率仍需确认，现有 V2 路径在缺少缓冲反馈时保持停止。

## 车型几何及减速比（APP-10）

- `ChassisConfigIsValid` 按编入的模型调用同一套轮组计算。麦轮配置使用 SI 的半轴距、半轮距、中心偏移和轮半径，全向轮使用各轮的独立几何。未选中的几何项可留空，旧尺寸宏、重复减速比和哨兵全向轮配置里闲置的麦轮尺寸已移除。
- 电机安装方向由驱动使用，轮速限制和反馈统一引用电机输出轴的减速比。主机注入较高减速比，让轮轴目标触发限速，再将四轮目标作为理想轮速反馈，估算结果仍为前进。麦轮任务继续通过原轮序及符号回归。
- 底盘运动、任务、轮速反馈、里程计及麦轮／全向轮车型校验共 6 项通过 ASan／UBSan。单板、底盘板分别选择麦轮／全向轮编译了 12 个 ARM 对象，符号检查确认校验和控制只调用选中的模型。未使用测试参数生成可部署车型。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过，WSL Debug／Release 各 825/825。普通禁热和遥控诊断通过 ARM 构建与 ELF 隔离，Flash 较上轮各减少 4 B，分别为 257356 B 和 260900 B，主 RAM 分别为 122168 B 和 122680 B。六种正式预设仍因核心配置未确认而拒绝。哨兵的实际几何、方向、减速比和限值仍待现场确认。

## 四轮编号及安装方向（APP-10）

- 四轮共用总线、型号、减速比和控制参数。逐轮登记按车型表使用对应的设备编号与方向，CAN 恢复用同一组编号核对反馈。主机回归覆盖不同安装方向的四轮正常登记、编号未按数值排序的恢复、非法或重复编号，以及方向待确认时拒绝车型。相关 6 项通过 ASan／UBSan。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过，WSL Debug／Release 各 825/825。普通禁热和遥控诊断通过 ARM 构建及 ELF 隔离检查，Flash／主 RAM 分别为 257356 B／122168 B 和 260900 B／122680 B，与上轮相同。单板、底盘板与麦轮、全向轮共 16 个相关 ARM 对象通过独立编译，六种正式预设因核心配置未确认而拒绝。
- 哨兵仍记录历史电调编号，四轮安装方向保持待确认。生产配置仍须确认实际接线、轮位和安装方向。没有执行板上测试。

## 异步轮速的里程计积分

- 积分保存上次使用的四轮反馈序号和接收时刻。只有四轮各自更新且最早时间前进，才使用该组速度积分。短暂等待四轮数据时保留还未到期的位姿；单轮时间倒退会中断该段。独立速度估计继续使用当前新鲜的四轮反馈，保留其中最早的接收时间。
- 三项 ASan／UBSan 专项通过。主机注入最早一轮先更新、四轮补齐、反馈序号回绕，以及最早时间前进但单轮时间倒退的场景。还验证旧位姿到期后可继续读速度，必须等齐四轮才开始新段。
- 隔离的 `commissioning/chassis` 通过 Cortex-M7 Debug 构建和 ELF／源码检查，FLASH 306796 B、主 RAM 125936 B，分别增加 144 B 和 32 B。哨兵仍关闭里程计，未连接硬件，轮速反馈时差和实车里程计精度待测。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 2` 通过。WSL Debug／Release 各通过 834 项；两种禁热固件通过构建与 ELF 检查，六种未确认的生产配置按预期拒绝。

## 启动时准备全向轮估速系数

- 轮组方向、尺寸和轮径固定后，启动一次求出三行四列的系数。周期估速仍逐轮检查单位、数值和原始接收时刻，每个速度分量通过四个乘积相加得到。非法几何使底盘初始化在轮电机登记前失败，重新准备失败后也不会继续使用旧系数。
- 四项 ASan／UBSan 专项通过。手算轮速验证前进、左移和旋转，另一组验证同一系数可处理不同方向的反馈。另覆盖未准备、几何退化、非有限输入和原有反馈超期、异步积分行为。
- 隔离的 `commissioning/chassis` 通过 Cortex-M7 Debug 构建及 ELF／源码隔离。反汇编确认准备先于电机登记，周期估速仍读取实际轮速，应用系数的函数没有矩阵求逆或除法。FLASH 为 306924 B、主 RAM 为 126032 B，较上次分别增加 128 B 和 96 B。未连接硬件，板上执行耗时和反馈精度仍待测量。
- 相同 ARM Debug 编译选项下，`-fstack-usage` 报告原周期估速函数占用 296 B 静态栈帧，改后的周期点积函数为 24 B。启动准备函数为 256 B。这些数值只描述单个函数的静态栈帧，任务峰值栈水位仍待测量。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 2` 通过。WSL Debug／Release 各通过 834 项，普通禁热和遥控诊断固件的内存用量与上轮相同，六种未确认的生产配置仍按预期拒绝。

## 启动时准备目标轮速投影

- 麦轮和全向轮在登记轮电机前检查几何和减速比，将轮位、方向与轮径换算为固定系数。底盘任务使用每轮三个乘积求转速，继续按原轮序进行共同限速和减速比换算，并在提交前复核命令期限和许可。准备失败会清除已有系数。
- 底盘运动、轮速估计、里程计、双板话题及桥接过期等共 9 项通过 ASan／UBSan。用例覆盖未准备、连续复用、重新准备失败和非有限输入，也验证麦轮与全向轮的转向和限速。
- 隔离的 `commissioning/chassis` 通过 Cortex-M7 Debug 构建及 ELF／源码检查。比同配置基线增加 352 B Flash 和 128 B 主 RAM，分别为 307276 B 和 126160 B。该构建用于本机检查，实车几何和限值仍待确认。
- 相同 ARM Debug 编译选项下，`-fstack-usage` 显示 `ChassisTask` 自身静态栈帧从 288 B 降至 160 B，`ChassisInit` 从 336 B 增至 440 B。单次轮速计算入口的静态栈帧为 272 B，周期使用的 `ChassisKinematicsCalculatePrepared` 为 16 B。板上执行耗时和任务峰值栈水位仍待测量。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 2` 通过。WSL Debug／Release 各通过 834 项。普通禁热和遥控诊断通过 ARM 构建及 ELF 隔离检查，Flash／主 RAM 分别为 257664 B／122168 B 和 261208 B／122680 B。六种生产预设因核心配置未确认而按预期拒绝。
