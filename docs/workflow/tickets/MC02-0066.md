# MC02-0066：类型化异步日志与关键记录

任务状态只在[TODO](../../../.Doc/TODO.md)维护。本轮按仓库规则只做WSL主机验证和ARM固件构建，不连接硬件。教学入口为[学习笔记18](../../学习笔记/18-一条日志的旅程.md#12-类型化事件怎样进入-rtt-mc02-0066)，旧格式串背景见[学习笔记10](../../学习笔记/10-可变参数与格式串安全.md)。

## 基线与范围决定

- 基线：`cd31516e37cf3461dcba3c7b018c2370160b8758`；分支：`feat/typed-async-log`。
- 所有工程诊断改为固定目录中的类型化事件；提交只复制并校验字段，不在生产者路径格式化、分配或等待。事件目录集中记录稳定编号、来源、严重程度、类别、文字、字段类型、标签和单位。
- 按用户决定关闭标准输入输出：正长度`_write`失败，`fputc`返回`EOF`，`_read`返回不支持。正常运行只通过RTT非阻塞输出事件；每条最多尝试一次，失败计数且不补发。NMI／HardFault仍使用独立崩溃记录路径。
- 普通任务创建日志任务失败不提升为核心启动失败；调度器未运行的启动失败循环可用同一处理入口，每轮最多处理一条。ISR提交拒绝。

## 固定资源与行为

| 项目 | 实现值 |
|---|---:|
| 队列 | 32条；普通事件最多24条，关键事件可挤出最早的普通待发项 |
| 编码数据／文本 | 每条最多96字节；每个文本字段最多保留48字节并统计缩短 |
| 关键历史 | 独立保留首次关键故障，另循环保存最近16条关键记录；查询复制，不消费 |
| 普通事件 | 正常配置默认关闭；显式诊断配置为全局20条/秒、突发8条 |
| 输出与任务 | 定长256字节输出缓冲；静态BelowNormal任务，1024个`StackType_t`，约5ms推进，每轮最多2项 |
| DTCM | `.log_workspace`为`NOLOAD`且32字节对齐，日志初始化清零；链接断言不超过16KiB |

关键事件按来源合并连续相同编号和字段值，重复数与首次／最近提交时间写入记录。普通事件先通过默认过滤、限速和容量检查，成功入队才消费令牌。所有计数饱和保持。输出渲染只支持固定字段写入器；NaN／Inf使用明确文字，大幅值附原始位形。

RTT写入直接按整条记录检查上行环剩余空间后一次发布写偏移，不使用可能阻塞的printf包装。当前固件不启用DCache；若检测到DCache开启，停用RTT后端并继续保留RAM关键历史。启动代码与日志任务不共享并发处理入口；任务创建失败可在调度器启动前重试。

## 调用迁移

`bsp_log_events.def`和`bsp_log_sources.def`为统一目录。BSP、应用和模块中的旧`LOG*`／`PrintLog()`调用已迁移；LCD日志汇总改为提交原始分组值，日志单位转换及数值转文字由处理端执行。保留面向屏幕的格式化接口，因为它们直接绘制用户界面而非工程日志。移除活动代码的`SEGGER_RTT_printf`输出依赖；异常记录仍为独立路径。

日志初始化位于DWT之后、看门狗之前。任务入口由应用任务初始化创建，不加入核心超时喂狗集合；任务创建或RTT后端不可用可通过只读状态查询。标准I/O关闭不影响`snprintf`等用于LCD绘制的格式化函数；`Float2Str()`作为独立数值工具保留。

## 主机验证

WSL Ubuntu 22.04 / GCC 11.4.0：全量Debug和Release各 **288/288** 通过。生产日志专项覆盖值格式、历史、队列挤出和仅保留、事件目录、任务创建失败／重试、真实线程交错、限速、普通开关、渲染溢出和stdio失败；日志专项ASan+UBSan **13/13** 通过。新增测试在Release下使用持续生效检查，每场景10秒超时。

ARM／WSL格式诊断使用ARM GNU GCC 10.3.1；当前固件配置正反例 **16项**通过。生产日志核心测试拦截`snprintf`／`vsnprintf`，确认提交和队列处理接口不调用通用格式化函数。静态搜索确认活动工程无旧`LOGINFO`、`LOGWARNING`、`LOGERROR`、`PrintLog`及直接RTT printf调用；剩余`snprintf`用于LCD／UI文字绘制。
