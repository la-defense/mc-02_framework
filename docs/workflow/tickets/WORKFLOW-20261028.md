# WORKFLOW-20261028：工作流效率工程化

任务状态只维护在 [.Doc/TODO.md](../../../.Doc/TODO.md)。本记录保存设计、实现和本机证据，不代替任务状态。

对应任务：**MC02-0139**（文档链接与 TODO 治理）、**MC02-0140**（统一验证入口与预设清单）、**MC02-0141**（CI 收敛）。本记录同时用于检验这些改动能否缩短一个真实 TODO 的交付路径；本次选中的是 **MC02-0001**（I²C 10 位地址）。原分支的结果和 TODO 数量是 2026-10-28 的历史快照，不代表当前整合后的验证状态；本轮结果另见下文“整合后本机验证”。

## 问题

1. 验证证据大量指向 `build/`，而该目录被 Git 忽略；换机或清理后链接失效，“可重复验证”只剩本机结论。
2. 十种官方预设的名称和角色在 CI 构建、归档、profile 检查和文档中重复维护；新增预设容易漏改。
3. 本地没有统一入口，需要手工记住 TODO、链接、主机测试、ARM 构建、源码隔离和归档命令。
4. 文档相对链接只靠人工检查；TODO 只能验证格式，不能给出待办分布。
5. CI 同一分支的旧运行不会取消，且每次重新编译全部源码；本机 WSL 构建目录位于 `/mnt/d`，文件系统开销较大。

## 未完成与边界

- `.Doc/TODO.md` 的“未完成／已完成”分文件整理没有执行：主工作树当时有未提交的 MC02-0084 修改，直接重写 TODO 会在合并时覆盖他的条目。先交付检查器和摘要，等该分支提交后再迁移。
