# MC02-0045：恢复 BMI088 加速度计初始化

关联任务：MC02-0042（初始化失败安全降级）、HIL-10（只读 SWD 快照）。任务状态只记录在 [.Doc/TODO.md](../../../.Doc/TODO.md)。

## 现场基线

板上诊断曾连续读到加速度计 ID `0x00`、陀螺仪 ID `0x0f`、初始化错误 `0xff`、重试 `5`，SPI HAL 状态均为 `HAL_OK`。这说明 MCU 的 SPI API 报告事务完成，但不能单凭该状态证明从器件返回了正确数据。

首要待验证点是加速度计软复位后第一次 SPI 读取被直接当作 chip ID。实现会增加独立 dummy read，并继续校验后续读取的 `0x1e`。如果仍失败，保留读到的失败阶段、HAL 状态和两侧 ID；没有电压表或波形仪，不能仅据此判断传感器损坏或信号质量。

## 软件行为

- 加速度计软复位后，丢弃一笔独立 chip-ID 读取，再读取并校验 `0x1e`。
- BMI088 初始化写入通过有界、同步的 `SPITransRecv()` 返回 HAL 状态。ERROR、BUSY 或 TIMEOUT 结束当前传感器初始化尝试，外层最多重试五次。
- 只发布固定宽度的初始化阶段、失败阶段、HAL 状态、芯片 ID、成功样本序号与时间、INS 有效状态和加热占空比诊断符号。
- `tools/probe_snapshot_live.py --imu` 使用离线 ELF 查符号，现场只读白名单 RAM 地址；开始和每次读取后检查目标仍处于 running。不得发送 halt、reset 或 resume 命令。
- 裸板构建持续关闭加热和执行器；SP 帧协议、参数存储布局不变。

## 主机验收

通过生产 `BMI088Register()` 路径模拟传感器复位后的首次无效读取。验证第一次 dummy read 被丢弃、后续两侧芯片 ID 正确、五次重试上限，以及加速度计 probe、复位写入和 dummy read 的 HAL_ERROR/BUSY/TIMEOUT 故障传播。另运行 BMI088 采样、标定温度、温控、SPI 总线和安全相关回归。

## 板上验收记录

上板条件：仅开发板、LCD、USB、调试器；12.5 V、2 A 限流，记录输出电流和 CV/CC 指示。烧录前备份固件与参数区并核实构建 SHA、ELF 哈希和写入边界。保持裸板安全配置、加热与执行器关闭。

验收五次启动（四次 MCU 复位、一次断开 USB 和主输入后的冷启动）及连续十分钟运行。`--imu` 快照需显示初始化 READY、两侧 ID `0x1e/0x0f`、样本序号递增、样本有效且加热占空比为零；记录复位、任务心跳和供电面板状态。若加速度计仍无响应，保存快照后停止本项板上测试，并把任务状态改为 `needs-info`，等待供电轨、片选及 SPI 波形测量。
