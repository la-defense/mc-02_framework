# MC02-0045：恢复 BMI088 加速度计初始化

关联任务：MC02-0042（初始化失败安全降级）、HIL-10（只读 SWD 快照）。任务状态只记录在 [.Doc/TODO.md](../../../.Doc/TODO.md)。

## 现场基线

板上诊断曾连续读到加速度计 ID `0x00`、陀螺仪 ID `0x0f`、初始化错误 `0xff`、重试 `5`，SPI HAL 状态均为 `HAL_OK`。这说明 MCU 的 SPI API 报告事务完成，但不能单凭该状态证明从器件返回了正确数据。

首要待验证点是加速度计软复位后第一次 SPI 读取被直接当作 chip ID。实现会增加独立 dummy read，并继续校验后续读取的 `0x1e`。如果仍失败，保留读到的失败阶段、HAL 状态和两侧 ID；没有电压表或波形仪，不能仅据此判断传感器损坏或信号质量。

## 软件行为

- 加速度计软复位后，丢弃一笔独立 chip-ID 读取，再读取并校验 `0x1e`。
- BMI088 初始化写入通过有界、同步的 `SPITransRecv()` 返回 HAL 状态。ERROR、BUSY 或 TIMEOUT 结束当前传感器初始化尝试，外层最多重试五次。
- 只发布固定宽度的初始化阶段、失败阶段、HAL 状态、芯片 ID、成功样本序号与时间、INS 有效状态和加热占空比诊断符号。
- `tools/probe_snapshot_live.py --imu` 使用离线 ELF 查符号，现场只读白名单 RAM 地址；开始和每次读取后检查目标仍处于 running。不得发送 halt、reset 或 resume 命令。
- 裸板构建持续关闭加热和执行器；SP 帧协议、参数存储布局不变。

## 主机验收

通过生产 `BMI088Register()` 路径模拟传感器复位后的首次无效读取。验证第一次 dummy read 被丢弃、后续两侧芯片 ID 正确、五次重试上限，以及加速度计 probe、复位写入和 dummy read 的 HAL_ERROR/BUSY/TIMEOUT 故障传播。另运行 BMI088 采样、标定温度、温控、SPI 总线和安全相关回归。

## 板上验收记录

上板条件：仅开发板、LCD、USB、调试器；12.5 V、2 A 限流，记录输出电流和 CV/CC 指示。烧录前备份固件与参数区并核实构建 SHA、ELF 哈希和写入边界。保持裸板安全配置、加热与执行器关闭。

验收五次启动（四次 MCU 复位、一次断开 USB 和主输入后的冷启动）及连续十分钟运行。`--imu` 快照需显示初始化 READY、两侧 ID `0x1e/0x0f`、样本序号递增、样本有效且加热占空比为零；记录复位、任务心跳和供电面板状态。若加速度计仍无响应，保存快照后停止本项板上测试，并把任务状态改为 `needs-info`，等待供电轨、片选及 SPI 波形测量。

本票据是依据、接口和验证步骤，不拥有任务状态。

## 2026-10-08 受控姿态响应验收

用户重新确认仅接开发板、LCD、USB 和调试器，主输入为 12.5 V／2 A 限流电源，实际电流约 0.1 A、CV 亮、无异常。本轮沿用此前已烧录并校验的 `ab8fd5f5144eb442a5231adeff38543cbb88e84b` 裸板固件，重新计算的 ELF SHA-256 仍为 `1120665da7ccad08ba7ca475f973f584a601a6f20b40a951f857de729cd9850d`；本轮没有重新烧录，不能把本机 ELF 哈希单独视为芯片 Flash 的新一次回读校验。

通过 `tools/openocd_running_inspection.cfg` 启动仅绑定 loopback 的 OpenOCD，使用现有 `probe_snapshot_live.py`，匹配上述 ELF、`--samples 3 --interval 1 --timeout 3 --imu` 读取前后 IMU 状态；另用 `--samples 2 --interval 0.5 --timeout 3` 读取通信与复位状态。只读白名单 RAM 地址并检查 running，未发送 halt、reset、resume 或 Flash 写入命令；验收后关闭了本轮启动的 OpenOCD 进程。

COM14／115200 仅被动接收。一次性采集脚本及产物保存在本机 `build/mc02-0045-pose-20261008-181022/`，没有新增永久诊断工具。采集从北京时间 18:12:46 开始，持续 63.895 秒，最长等待限制为 180 秒。先采 5 秒基线；用户回复“已倾斜并保持”后等待 3 秒、采 5 秒；回复“已放回并静置”后同样等待 3 秒、采 5 秒。动作转换期间也持续保存原始数据。

CRC 使用生产 `VisionProtocolCRC16()` 的参数：初值 `0xffff`、反射多项式 `0x8408`、不作末尾异或，校验前 41 字节、按小端读取末尾两字节。四元数按 `(w,x,y,z)` 从状态帧偏移 3 解码，检查有限性及原始范数后归一化，沿用 `EarthFrameToBodyFrame()` 的定义计算板坐标系重力方向。

| 稳定阶段 | 采集相对时间窗口（秒） | 有效帧数 | 相对基线方向差 | 方向波动 P95 |
|---|---|---:|---:|---:|
| 静置基线 | 0.000–5.000 | 1,000 | 0° | 0.073° |
| 倾斜保持 | 34.440–39.440 | 1,000 | 21.154° | 0.602° |
| 放回静置 | 58.880–63.880 | 1,000 | 0.253° | 0.016° |

三个窗口都超过 100 帧，方向波动 P95 均小于 3°；倾斜响应超过 5°，放回差小于 5°，满足本次功能验收阈值。人工动作要求是约 10–20°，实际没有角度仪表；`21.154°` 是 INS 输出的计算结果，不是人工倾角的独立测量值，也不构成角度精度验收。

全程收到 549,326 字节、12,775 个 CRC 正确的完整 43 字节帧，坏 CRC 候选和重同步字节均为 0；结束时余下 1 个尚未组成完整帧的字节，不计作 CRC 错误。四元数全部有限，原始范数范围 `0.998309608–0.998318110`，全部落在 `0.95–1.05` 验收区间。

测试前、后各三次 IMU 快照均为 READY（9）、ID `0x1e/0x0f`、初始化错误 0、HAL 状态 0、重试 1、样本有效 1、加热占空比 0。样本序号从 `1037091` 增至 `1270388`；通信快照 tick 从 `1039800` 增至 `1271497` ms，IWDG 标志和 CRC 错误计数均为 0，未见复位迹象。RX 计数保持 0，与本轮没有发送命令一致。快照为逐字段读取，不是同时采样，不能把字段间的毫秒差直接解释为传感器错误。
