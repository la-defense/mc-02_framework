# R25-12：栈余量与任务耗时复核

任务状态只维护在 [.Doc/TODO.md](../../../.Doc/TODO.md)。本轮软件验收基线为 `cc752782048c505f1787ec6604a20db2485ef72d`，分支为 `test/r25-12-resource-audit`。本票据将最大观测值称为“已测场景最大值”，不称为形式化 WCET。

## 本轮范围

- 为 INS、motor、daemon、robot 和 UART TX 任务记录任务主体最大耗时及调用次数；保留现有电机控制路径，不在缺少板上证据时拆分解析。
- 每约 5 秒发布 FreeRTOS 任务名、运行计数、优先级和历史最小栈余量快照。读取器按版本号前后相同且为偶数、固定布局标记和字段范围验证快照；任务数超过12时明确报告截断。
- 对已知任务将 `uxTaskGetSystemState()` 的水位值与实际创建时传入的栈深度比较，并输出剩余栈比例。未知任务只报告剩余 `StackType_t` 数，不猜总栈容量。
- 用生产 CAN 接收队列和 DJI 反馈解析器执行队列满压力测试；正常可运行性和板端资源数据仍需实际 `bench_safe` 观察。

## 栈容量解释

本工程的 CMSIS-RTOS v1 适配层把 `osThreadDef(..., stacksz)` 的 `stacksize` 原样传入 FreeRTOS `xTaskCreate()`；FreeRTOS 按 `StackType_t` 个数解释该值。因此，本记录使用下表中的创建实参作为容量，H723 每个 `StackType_t` 为4字节。若任务创建方式或栈大小变化，必须同步更新 `tools/probe_snapshot_live.py` 中的容量表。

| 任务名 | 配置深度（word） | 配置字节 |
|---|---:|---:|
| `defaultTask`、`IDLE` | 128 | 512 |
| `Tmr Svc` | 256 | 1024 |
| `instask`、`daemontask`、`uarttxtask` | 1024／512／512 | 4096／2048／2048 |
| `motortask` | 512 | 2048 |
| `robottask`、`logtask`、`lcdtask` | 1024 | 4096 |
| `uitask` | 512 | 2048 |

FreeRTOS 动态任务栈从配置为 **25,600字节**的堆中分配。任务栈余量是运行以来的历史最小剩余值，不等于堆余量；本工程没有为本轮增加运行时空闲堆测量入口。

探针工具只读取固定符号，不接受任意目标地址；不 halt、reset、写内存或发送控制帧。快照版本不匹配、写入中、任务表截断或栈水位超过已知配置时会拒绝或明确报告，不能当成完整有效测量。
