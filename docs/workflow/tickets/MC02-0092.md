# MC02-0092：新版 CAN 分片与话题桥接

任务状态以 [TODO](../../../.Doc/TODO.md) 为准。本记录保存实施计划和验证依据。

## 实施计划

以 `a668a9d099b95e171d4584243a896c43088b906b` 为基线，使用 WSL 主机测试和 ARM 禁热构建；不连接开发板或执行器。旧 `CANComm` 目前依赖固定长度和结构体布局，底盘与命令业务分别包含单双板分支。目标是让双板使用显式配置的话题桥接，且两端同时使用新格式。

1. 核对消息中心的发布者、订阅者、源时间和过期行为，及 CAN 发送组的容量、复制、失败和调度限制；据此确定版本、消息序号、分片编号、长度、校验及时间字段的字节布局和明确容量。不同板的时间不能直接相减；没有有效时间映射时，不能把远端旧消息当作新消息授权控制。
2. 使用固定容量实现发送、接收与话题适配；接收按独立消息、规定次序和总期限组装，坏长度、丢片、重复、乱序、混片和校验失败都不得发布或延长旧消息期限。发送必须检查整组入队结果，不重放已开始失败的旧组。初始化按配置检查话题关系及资源，运行中有界且不分配。
3. 用显式目录绑定跨板话题和两端角色，迁移底盘与命令业务的收发路径，使业务通过统一话题接口而不自行区分单双板；停止使用旧线上格式。保持现有失效关断，未能安全判断源期限时保持失效。板间对时本身继续由 MC02-0093 验收。
4. 测试先行：用固定字节答案、生产 CRC／消息中心／CAN 调度验证双方兼容，覆盖最大容量、分片和总线预算、各种异常序列、时间回绕、源过期、无同步、恢复与并发；失败不发布、不续期、不留下部分发送。检查旧帧不能误被接受。
5. 运行 WSL Debug／Release 和适用消毒器；构建五类角色各 Debug／RelWithDebInfo，验证双板角色隔离、非法配置、链接来源与 RAM 余量。当前单板主 RAM 余量很小，记录实际用量，不以关闭检查解决资源不足。
6. 更新 CAN 模块说明、学习笔记03和索引，记录格式、数据来源及尚未验证的板间实测。只有全部验收满足才关闭 MC02-0092；按用户要求复核提交差异并提交。保留未跟踪资料，不推送、不创建 PR；LCD 事项继续暂缓。

## 初步接口核对

现有 `CANSubmitOneShotBatch()` 一组最多8个经典帧，每帧最多8字节。分片的版本、序号、分片编号和整包校验均需占用这64字节，不能假定消息中心允许的64字节内容一定能装入一组；必须先核对实际跨板话题长度，并明确无法容纳时的拒绝或分组方案。现有消息中心的 `MESSAGE_CLOCK_REMOTE_RAW` 以本地首收时间计算年龄，不能单独证明发送前的数据仍新鲜；桥接控制话题前必须结合可信时钟映射和源期限，不可因重新封装而重新计时。

现有 `CANComm` 收齐后将末帧接收时间作为消息时间，可能让分片传输期间的时间被忽略。新实现应保留首帧时间，并对源时间和总期限分别检查；不能把只修复这一点当作完成新版协议与话题桥接。

## 发送容量的先行验证

按候选格式估算：每帧2字节版本／序号及分片标识，余6字节；内容最多64字节，加话题编号2字节、长度1字节、源时间4字节和校验2字节，共73字节，需要13帧。此处仅是设计预算，尚未完成格式实现及独立向量验证。

生产CAN队列的整组上限从8帧扩展为13帧。先增加固定下限测试并观察旧实现失败，再验证最大组按序提交和结束；WSL Debug 的7项生产CAN发送回归通过。`robot-single-debug`构建通过，RAM_D2由12768增加至16608字节，主RAM仍为130824字节。更长组对紧急请求等待时间和总线预算的影响仍需在完整桥接测试中验证，当前未完成MC02-0092。

## 编解码器初步结果

新增独立候选编解码器：帧首字节高4位为版本标记`0xA`、低4位为分片编号，第二字节为消息序号，其余最多6字节。整包为小端话题编号、内容长度、源毫秒时刻、内容及CRC16；最多64字节内容。接收检查连续编号、相同序号、完整长度、首次接收时间与CRC，仅完整成功才写出候选消息。重复上一条完整消息的相同序号不发布；该检查不代替源时间、会话重启及更久远重放检查。

WSL Debug／Release 的初步测试通过，包含13帧完整消息、固定短消息线字节、错序、超时、CRC错误及重复。候选模块已登记到固件编译清单，但尚无业务入口，可能被链接器回收；未连接话题中心，不能用于跨板控制。不同板的源时间映射、恢复和许可必须在后续接口中单独落实。

增加CAN批量提交适配层，测试队列替身中的整组复制、拒绝后不消耗序号，以及接收首帧时间；Debug通过。这不是生产CAN调度器联测，尚需验证同时调度电机流量、失败和期限。编码不判断源数据是否过期，当前由上层负责，不能仅凭接收入队就授权控制。

补充一组生产CAN调度器联测：13帧可从真实队列顺序提交，收集的帧经候选接收器还原64字节和首帧时间。测试还显示，组发送开始后新入队的紧急帧要等待本组结束；每次调度最多推进一帧，因而不能仅按总线带宽推断紧急帧延迟。此结果尚未证明电机控制期限满足要求；桥接接入前仍需解决或明确验证这一等待条件。此联测在WSL Debug／Release完成，未测真实总线。

进一步注入多帧组中途HAL中止，复现了结果已标失败但剩余帧仍被提交的问题。调度任务现在先检查结果状态，失败后清除尚未提交的分片；结果历史分配也避开仍被队列引用的失败槽。WSL Debug回归覆盖中止后40次提交／取消使结果历史回绕，确认失败结果保留且后续分片不再提交。已经交给HAL的帧无法撤回，接收方仍须依靠完整性及期限拒绝半包。

为避免候选话题组持续占用电机控制周期，增加显式可中断批量入口；更高优先级请求等待时，调度器将该组标为失败并放弃尚未提交的分片，再选择控制请求。普通批量入口仍保持原有组内顺序。生产调度模型覆盖13帧组完整发送、同优先级不打断，以及4ms期限的周期控制请求到来后中断；WSL Debug相关9项通过。已进入硬件FIFO的帧和物理仲裁不由该检查消除，实际时延及生产话题负载预算仍待验证，故不能据此宣称控制期限满足。

## 消息中心桥接候选

消息中心增加从已注册句柄复制话题定义的入口，桥接初始化用它检查长度、快照类型和时钟域。发送只读取本地时钟或已映射时钟的有效快照，队列期限不超过来源剩余时间，同一版本入队后不自动重放。接收要求映射函数给出本地时刻和误差上限，用最早可能的源时刻判断及发布；没有映射、时间过期、重复或倒退的源时刻均不发布。发送板复位后先撤销旧来源及未完成分片，重新建立可信同步后再接受新消息。

生产消息中心加CAN队列替身的WSL Debug／Release测试通过，覆盖队列拒绝、失同步、误差余量、期限边界、重复／倒退和32位回绕。单板Debug固件构建通过；候选桥接当前没有业务实例，不代表已实现MC02-0093，也未替换双板业务旧路径。后续仍须配置真实端点、测试生产CAN接收至消息中心并迁移双方业务；未同步时控制必须保持失效。

补充分片接收至消息中心的组合入口，并增加单发布端点话题的撤销入口。周期检查发现映射失效时，清除未完成的拼包并撤销已发布旧数据；多发布端点的话题拒绝这一撤销，避免误删其他来源。WSL Debug／Release测试覆盖完整分片发布、失同步撤销、恢复及多发布端点保护。失同步从发生到撤销之间存在调用周期的检测延迟；调用方接入时仍须确定服务周期和控制许可，当前没有生产任务调用该入口。

后续核对发现映射仍有效但校正方向发生变化时，旧值原先使用的来源时刻可能过于乐观。周期检查现重新计算已发布值最早可能的来源时刻；若它早于原先估计或已超期，撤销旧值并等待新消息。WSL Debug／Release用映射偏移向前修正的场景验证撤销，不把这种测试解释为完整对时误差保证。

新增链路对象，启动阶段先检查话题关系再注册CAN，接收回调调用拼包和发布入口，服务函数分别报告发送与同步状态。WSL Debug使用CAN注册替身模拟派发，覆盖初始化拒绝、重复初始化、收帧发布及失同步撤销；单板Debug固件编译通过，当前未创建生产链路实例。双板应用仍直接使用旧CANComm，消息内容仍需确定明确字段编码；尚不能将候选链路当作完整迁移。

新增底盘字段编解码：命令固定21字节，包括四个小端IEEE754单精度、一个模式字节及一个小端32位速度档；反馈固定3字节。拒绝非有限数和非法枚举，不使用结构体内存布局作为线上格式。桥接初始化现要求每个启用方向显式提供编解码回调，回调处理可能未对齐的数据。WSL Debug／Release和ASan／UBSan相关6项通过，覆盖固定向量、未对齐输入、编码失败及非法浮点不能覆盖旧话题；底盘板Debug构建通过。旧双板应用尚未迁移，对时和实际车辆参数仍未确认。

## 双板候选接入

双板目录为底盘命令和反馈配置桥接端点，底盘和命令应用统一读取／发布消息中心话题；启动时单独注册CAN链路，接收派发和链路服务在电机任务串行执行。此阶段尚未接入板间对时映射，所有远端接收均拒绝；旧CANComm线上格式不再由双板应用使用。WSL Debug测试覆盖无命令时停止、模拟已映射命令及撤销后停止、云台侧安全命令发布；两种双板Debug固件构建通过。后续对时接入和本轮最终证据见下文及[MC02-0093](MC02-0093.md)。

生产CAN中断接收队列、任务派发、候选拼包、映射及消息中心的WSL Debug／Release联测已通过；坏CRC不刷新已发布值，失同步服务撤销旧值。映射在测试中使用受控模型，不能代替MC02-0093。

容量核对：云台侧命令为21字节，加9字节消息头与校验后需要5帧；现有应用约每5ms产生一份，电机任务每1ms每总线最多推进一帧，在持续满速更新时会占满这一路的软件服务机会，尚无重试或调度抖动余量。当前配置云台电机在CAN3、发射电机在CAN2、桥接在CAN1；底盘电机在CAN1、桥接在CAN2。不同车型若共用总线不能沿用这一假设。生产调度模型还验证了同总线每轮都有高优先级帧时话题按期限过期，不伪报成功；桥接能否在目标周期稳定发送仍需解决并验证。

双板电机任务现对本板桥接总线额外推进至多一帧，其他总线仍每轮最多一次；调用仍不等待HAL。生产调度模型中，每5ms产生5帧、每组故意缺一次服务，其余每轮最多推进两次，六组均完成；模型还覆盖同一轮两帧在途并逆序完成，以及共享总线持续出现电机控制帧时话题被中断而非挤占控制。WSL Debug／Release各14项CAN发送测试通过，底盘／云台Debug固件编译通过。模型使用即时HAL完成，未测物理仲裁、总线重试或板上任务耗时；共用总线也不保证话题能按时传达，仍需按实际车型做预算。

发送侧现在只跟踪一个话题组。来源失效或新版本到来时取消旧组尚未提交的部分；结果查询新增HAL待完成帧数，旧帧仍在硬件中时暂不提交新组。WSL Debug／Release用生产CAN调度器验证取消、在途帧完成及新组重新提交，相关话题测试各13项通过；底盘Debug固件编译通过。已交给硬件的帧无法撤回，对端仍需检查完整分片和源期限；总线BusOff恢复与控制许可仍由MC02-0047跟踪。

当时的工作区全量WSL Debug／Release各475项通过，话题相关ASan／UBSan 13项通过；五类角色各Debug／RelWithDebInfo共10种禁热固件及其源码选择／ELF隔离检查通过。该阶段构建尚无实际板间时钟映射，不能作为双板控制或物理总线验收。

## 本轮软件验证

板间时间交换已接入同一链路，由电机任务串行处理；两端先取得有效映射，再按来源最早可能时间与首帧接收时间判断有效期。单板不编译板间桥接，对时接入和故障测试细节见[MC02-0093](MC02-0093.md)。哨兵车型配置按板角色声明CAN句柄、收发ID和底盘话题；启动拒绝非法ID及当前不支持的话题。更换车型需同步核对两板配置，目前只实现底盘命令和反馈的字段编码。

WSL Debug／Release全量各480／480通过；新增对时、话题桥接、两种角色实例、生产CAN调度预算和绝对期限共6项ASan／UBSan通过。生产CAN调度模型每5ms提交5帧命令，同期含对时及可选电容流量，故意漏一次推进后六组均在下一次更新前完成；它使用即时HAL替身，不覆盖真实仲裁、ACK、重发及板上执行耗时。共享总线若持续被高优先级请求占用，话题可能过期，不能假设必达。

五类角色的Debug／RelWithDebInfo共10种ARM固件重新构建，并用 `check_firmware_profile.py` 核对源码清单、实际链接及角色隔离。Debug底盘板主RAM使用130544／131072字节，仅余528字节；云台板使用126936字节，单板使用130824字节、仅余248字节；RAM_D2均为16800／32768字节。链接余量不等于实测栈余量。

规格审查发现旧话题过期后周期检查可能反复清掉新分片，现将“已发布数据是否仍有效”与“上次来源时间”分开；新分片可跨轮组装，旧来源仍被拒绝。另修复排队前被抢占时绝对截止时间后移的问题：队列在临界区检查来源截止时刻，已到期则拒绝入队。主机回归先复现上述恢复问题和缺失绝对截止接口，再覆盖恢复、延迟入队、相同时刻拒绝及32位回绕。规范审查指出复位后的接口说明不准确和抽象注释，已按实际行为更正；两个请求完成状态检查的重复属于可维护性建议，暂保留现有清晰职责。

未连接硬件。物理总线负载、时基持续性和精度、实际任务时间以及设备组合仍需在授权范围内另行验证；不能把软件结果描述成实车验证。`build-cmake`包装脚本在本机缺少 `tool_config` 模块，本轮使用仓库既有WSL CMake预设完成构建。

## 底盘许可与排队发送的后续复核（2026-11-01）

进一步复核底盘板发现，5ms 底盘任务与约1ms电机发送任务之间可能隔着远端命令的到期时刻；仅由底盘任务轮询会让旧许可短暂留存。双板底盘许可现保存命令来源时刻及话题最大年龄，`RobotSafetyIsReadyAt()`每次按当前时刻重新检查。授予时在一个临界区比较禁止代际、复核本地安全输入和命令年龄；CAN桥接撤销入站话题或失去时间映射时，回调立即撤销许可，使控制任务无需等下一轮才知道。

周期底盘电机帧增加发送前回调：调度器把帧交给 HAL 前，再检查许可与四轮速度、电流反馈，并修改队列内的帧副本。结果记录满时，新的零帧提交可能被拒绝；原排队帧仍会通过原回调变成零输出。回调只保存一个函数指针，复用固定生命周期的 `source` 作为上下文，避免再增加一个指针。已经被 HAL 接受的帧仍无法由软件撤回。

验证：WSL Debug／Release全量回归各485/485通过；`production_can_tx_periodic_guarded_revoke`、`production_can_topic_bridge`、`production_robot_can_bridge_chassis_board`、`production_safety_chassis_remote_permit`、`production_dji_chassis_safety_output_gate`的ASan／UBSan检查5/5通过。用最新源码重建并核对bench_safe、rcdiag、robot-single、robot-chassis、robot-gimbal五种Debug ELF，角色源码选择检查5/5通过。链接主RAM使用量分别为120408、120504、130840、130600、126960字节；单板和底盘板分别仅余232和472字节。五种构建的RAM_D2使用16992/32768字节。静态链接余量不代表实际栈余量。
