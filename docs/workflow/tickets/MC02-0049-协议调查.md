# MC02-0049：电脑 → DT7 键鼠协议调查

日期：2026-10-10。任务状态只在 [`.Doc/TODO.md`](../../../.Doc/TODO.md) 管理；本文记录协议依据，不代替真实链路验收。

## 1. 调查结论与证据层次

### 2026-10-11 补充：Z 字段有限对照

官方电脑结构允许有符号 16 位 Z，当前客户端原实现发送零，现有固件原先忽略 DBUS bytes 10/11。用户批准仅在裸板发送有限非零 Z，验证其是否保真透传；不把结构中存在此字段等同实机支持自定义心跳。生产解析、固定 RAM 观测与电脑编码已增加回归。Z=0/1/256/32767/-32768/-1 的完整向量通过官方 DLL 提取的 CRC16 表独立重建，硬编码在 `tests/tools/test_dt7_input.py`，软件 34/34 工具测试通过；板上结果另行记录。

透传若通过，才把该字段的 16 位原始模式解释为项目自定义序号；Z=0 表示未激活，不复用电脑协议头部固定为零的 sequence，也不修改 reserved。该自定义用途与原版客户端的兼容边界及验收见 [MC02-0049 票据](MC02-0049.md)。

已从**官网发布的 RoboMaster Client 5.0.2.37 原始程序集**读取发送实现，得到电脑 → DT7 的完整 22 字节帧、串口配置、CRC、键位和发送时序。它与 DR16 输出的 18 字节 DBUS 帧是两段协议。这里的向量由原始 IL 和原始 CRC 表离线重建，尚不是本机 DT7 的接收成功记录。

本次研究没有启动官方客户端、打开 COM4、发送任何字节或更新遥控器固件。主代理须使用已经验证的裸板诊断固件做有限的全松开、单键和鼠标动作对照；通过后才实施持续回放与实时转发。

来源分为三类：

- 官方用户手册证明链路及 DR16 输出：[DT7/DR16 V1.0，2016.09，第 5–7 页](https://cdn-hz.robomaster.com/tem/09f88aafe7ae51516874829340553427.pdf)。
- 官方裁判系统手册确认客户端负责向遥控器发送键鼠，并列出 DJI WIN 驱动及 RoboMaster Client：[2019 裁判系统用户手册 V1.1，第 9 页](https://rm-static.djicdn.com/tem/19806/RM2019%20%E8%A3%81%E5%88%A4%E7%B3%BB%E7%BB%9F%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8CV1.1%EF%BC%8820190329%EF%BC%89.pdf)。这本手册未给出电脑端帧格式。
- [官方客户端 2019 产品页](https://www.robomaster.com/zh-CN/products/components/detail/1414)的下载条目指向[官方 5.0.2.37 软件包](https://rm-static.djicdn.com/tem/17348/RoboMaster%20Client_CN_v5.0.2.37.7z)。以下编码事实来自该包，而不是从 DBUS 接收格式猜测。

## 3. 原始实现定位

无需运行客户端即可读取以下方法及结构的 CLI 元数据和 IL：

| 原始符号 | 作用与关键位置 |
| --- | --- |
| `SerialPortThread.OpenPort`，RVA `0x45b68` | 串口配置；配置后等待 100ms，再 `Open` |
| `SerialPortThread.WorkerProc`，RVA `0x45988` | 事件驱动串口线程，不独立周期制造输入 |
| `SerialPortThread.OnTimeTick`，RVA `0x45a90` | 每约 1 秒检查设备枚举；不是键鼠心跳 |
| `SerialPortThread.OnSendInputStatus`，RVA `0x45da4` | 组帧、CRC、调用串口发送 |
| `RobotInput.GetInputStatus`，RVA `0x6b9c0` | 鼠标及键位采集 |
| `RobotInput.Update` | 输入允许、设置面板关闭且累计时间超过 0.033s 时投递一次输入事件 |
| `ProtoManager.StructToBytes`，RVA `0x54adc` | `Marshal.SizeOf/StructureToPtr/Copy`，按结构布局复制 |
| `CRCCheck.GetCRC8/GetCRC16/.cctor` | CRC 初始化值、逐字节循环和查表数据 |

三种结构均为顺序布局、`Pack=1`：`CommonHeader_V1` 为四个 `uint8`，`Data_Body_Prefix` 为两个 `uint16`，`Input_Device_Status` 为三个 `int16`、两个 `uint8`、两个 `uint16`。官方 Windows 程序复制的是小端结构。

## 4. 串口、握手与发送周期

原始 `OpenPort` 设置 **921600、8N1、读超时 30ms、写超时 30ms**。该方法没有握手数据发送或读取；串口线程接到输入事件后直接发送完整帧。没有发现输入路径所需的额外登录/握手帧，也不能把其他 DJI 产品的 DUML 握手套入此链路。

原始方法没有改写 DTR、RTS 或流控。`.NET SerialPort` 的默认值分别是 `false`、`false`、`None`，依据为 Microsoft 的 [DtrEnable](https://learn.microsoft.com/en-us/dotnet/api/system.io.ports.serialport.dtrenable?view=netframework-4.8.1)、[RtsEnable](https://learn.microsoft.com/en-us/dotnet/api/system.io.ports.serialport.rtsenable?view=netframework-4.8.1)、[Handshake](https://learn.microsoft.com/en-us/dotnet/api/system.io.ports.serialport.handshake?view=netframework-4.8.1) 文档。Python 发送端应在打开前显式匹配这些值，不能沿用 pyserial 默认拉高控制线。

原始客户端阈值为 **0.033s**，发送受 Unity 帧率影响，约为 30Hz；每次 Update 最多投递一次。工具采用已经实测验证的 33ms 固定周期时，应跳过迟到周期，不补发积压动作。原始客户端没有在首次事件或串口退出时专门发送全松开；新工具必须增加明确的释放流程。

## 5. 22 字节电脑端帧

以下是 `OnSendInputStatus` 的离线重建结果，适用来源固定为上述程序集。

| 字节偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 1 | 帧头 `0x5A` |
| 1 | 1 | 长度 `0x10`：body prefix 4 + input 12，不含头和尾 |
| 2 | 1 | 协议版本 `1` |
| 3 | 1 | 前三个字节的 CRC8 |
| 4 | 2 | sequence，小端；原始方法固定为 `0` |
| 6 | 2 | cmd_id，小端 `0x2000`，即 `00 20` |
| 8 / 10 / 12 | 各 2 | 鼠标 X/Y/Z，`int16` 小端 |
| 14 / 15 | 各 1 | 左/右按钮，`0/1` |
| 16 | 2 | 键位位图，`uint16` 小端 |
| 18 | 2 | reserved，原始零初始化，保持 `0` |
| 20 | 2 | 前 20 字节的 CRC16，小端 |

CRC8：初值 `0x77`，反射多项式 `0x8C`，无最终异或。CRC16：初值 **`0x1862`（十进制 6242）**，反射多项式 `0x8408`，无最终异或。这里不能用 SP 的 CRC16/X25，也不能用其他 DJI 包常见的 `0x3692` 初值。已从原始私有 RVA 提取两个查表，并与对应多项式生成的全部 256 项逐项比较一致。

键位顺序为：`W S A D Shift Ctrl Q E R F G Z X C V B`，分别占 bit 0–15。按键保持状态，边沿由 MCU 从前后位图比较；长按应重复状态，不产生额外按下边沿。原始鼠标 X 使用正比例，Y 使用负比例；原始实现把 Unity 轴乘以灵敏度系数后转为 `int16`，Z 保持零。独立窗口的像素增量单位不是 Unity 轴单位，实际方向及比例仍须板上核对。

## 8. 实机协议门槛与后续资料

静态证据足以安排有限的协议验证，但不足以宣布工具可持续控制：

1. 核对用户确认的裸板连接与限流供电，使用禁热且禁止 READY 的遥控诊断固件。
2. 使用精确 VID/PID/序列号确认 COM4，固定上述串口设置；不自动换端口、重连或改固件。
3. 先验证全松开，再逐一验证 W/E/F、鼠标正负增量与两按钮；每个有限动作后发送全松开并只读核对 MCU 原始位图和字段。补充 A/D 以核对映射版本。
4. 记录原始发送字节、时间、对应 MCU 字段和 E/F 边沿增量。通过后将静态向量与实机结果合并到 MC02-0049 票据，再允许持续回放/live。
5. 正常退出及电脑 USB 断开分别验收。DT7 仍在线不代表电脑键鼠仍新鲜；若 USB 断开后键位残留，应关闭 DT7 撤销输入并保留问题证据。

如果有限动作不能得到预期字段，停止该阶段，补充 DT7 固件版本、匹配版本官方客户端的真实通信记录以及原始发送/接收对照。不得靠改变 CRC、握手或命令字轮流猜包。公开新客户端的 MQTT/图传键鼠实现与本 USB 链路不同，例如 [WMJ 的输入服务原始源码](https://github.com/dfcyyyds/RoboMasterClientWMJ/blob/c5cbeb4e5f592f8a84d02852f2c33b311ab2edc8/Assets/Scripts/Services/KeyboardMouseInputService.cs)明确通过 MQTT 发送；不能作为 DT7 串口发送实现替代。
