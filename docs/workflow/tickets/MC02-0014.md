# MC02-0014：跨板消息失效与恢复计划

任务状态以 [TODO](../../../.Doc/TODO.md) 为准。本任务与 [MC02-0092](MC02-0092.md)／[MC02-0093](MC02-0093.md) 直接相关，沿用当前分支；先验证新链路，再确认旧入口不会进入正式固件。

## 当前事实

新版双板应用只通过消息中心和带版本分片的CAN桥接收发；旧 `CANComm` 没有活动业务调用，旧格式没有消息序号或源时间，无法判断重放和跨板来源期限。用户已决定两板同时使用新版，不维护旧格式兼容。实施前旧源码仍在固件公共源码清单中，计划将其与活动路径明确隔离，不能给旧格式补接收时间就声称能防止跨板续期。

## 步骤与验收

1. 核对真实双板启动、CAN接收、拼包、对时、消息中心、底盘控制和许可的连接方式，复用0092／0093测试，找出尚未覆盖的失效和恢复行为。
2. 增加必要的生产接口联测，覆盖完整新命令、坏帧／丢片／重复／过期不刷新、超时撤销控制，以及恢复只接受新的有效输入；检查来源期限和跨周期分片，不依靠只验证替身内部字段。
3. 将没有生产调用且无法保证来源期限的旧格式从固件编译清单退出，保留源码及历史测试供查阅；明确旧接口不可作为活动双板通道，实际运行的新格式不兼容旧板固件。核对五类固件的源码清单和ELF。
4. 使用WSL Debug／Release和必要ASan／UBSan回归，构建受影响的ARM角色并检查资源、链接及角色隔离；不连接开发板或执行器，不声称实物总线已验证。
5. 更新TODO、CAN说明及已有学习笔记，记录现有许可边界和尚未验证的物理问题；按用户要求完成提交差异的规范／规格审查，修复有效问题后提交。

## 验收与验证记录

- WSL 主机 Debug、Release 当前完整回归均为 483/483 通过。生产桥接、消息中心、底盘任务和 Safety 联测覆盖跨周期分片、重复消息不续期、来源过期、坏 CRC、旧数据过期与新分片重叠，以及本地轮电机／IMU失效、急停和恢复后只接受更新话题序号；底盘恢复与桥接期限用例的 ASan／UBSan 检查也通过。
- 全量回归曾暴露消息中心并发评估测试的偶发失败：上一场景遗留数据与该场景的序号不匹配，读线程先运行时会误判。先通过初始数据检查稳定复现，再修正测试数据准备；Debug、Release 各重复 20 次通过，随后完整回归通过。生产消息中心未因此改动。
- ARM Debug 的 bench、rcdiag、robot-single、robot-chassis、robot-gimbal 五种构建及固件角色／源码选择检查均通过；旧 CANComm 不再进入固件构建。robot-chassis 链接 RAM 使用 130560/131072 字节，剩余 512 字节；这是链接区静态用量，不代表运行时栈余量，资源余量仍需关注。没有连接硬件或发送实际 CAN 报文。
- 本任务的软件验收已覆盖底盘板本地许可与新序号恢复；更完整的模式／分功能许可仍依赖 [MC02-0056](MC02-0056.md)。实际板间对时精度、总线时限及电机行为尚未上板验证，因此本记录不宣称实物双板联调完成。
