# MC02-0056：模式与分功能许可计划

任务状态以 [TODO](../../../.Doc/TODO.md) 为准。该任务与 [MC02-0014](MC02-0014.md) 共享板间命令恢复条件；本计划先核对现有实现和依赖，再分行为验证，不将通信有效等同于运行许可。

## 已知现状

当前 `RobotCMDTask()` 在单板和云台板更新 `RobotSafety` 并选择安全命令；底盘板不运行 `RobotCMDTask()`。底盘板已在 `ChassisTask()` 合并新鲜云台侧运动请求、本地 IMU／标定／任务／急停状态和轮组电机反馈，并在 DJI 周期发送路径再次检查许可及反馈。底盘板没有本地遥控器或人工 enable，因此本地许可不依赖这些输入；全车三种模式和分功能仲裁仍未完成。

## 计划

1. 核对机器人初始化、任务监控、急停、姿态／标定、裁判分组、遥控、视觉及消息中心的真实生产入口，建立单板／云台板／底盘板的事实来源表；用现有状态，不创造会掩盖失效的默认授权。
2. 建立单一管理者计算整车和各功能许可的边界；远端新鲜命令只能表达对端请求，本板核心故障及立即禁止必须独立生效。区分状态快照与立即禁止，规定失效期间已收到的旧命令和恢复后新命令的处理，避免因为清除故障而重放旧值。
3. 分别覆盖手动、视觉辅助、正式自主的来源仲裁与发射权；自主资格由车型配置，开始／结束使用新鲜裁判比赛阶段；调试遥控离线急停，正式自主按已批准规则运行。瞄准、导航与USB整体失效分别处理，健康切换平滑接管并撤销旧来源。
4. 保留人工急停的持续供电复位规则、明确解除后的调试／自主恢复差异，以及温控未稳定只提示的车型选择；与已有任务监控、复位恢复和维护保护相互验证。若某些必需状态或设备能力尚未实现，显式保持对应功能禁止，并在TODO记录剩余依赖。
5. 先写生产接口及跨任务故障场景测试，再实现每个可独立验收的切片；覆盖本地故障、过期、模式切换、复位、解除及新命令恢复，检查两板与单板行为一致且不增加隐含授权。
6. 执行WSL Debug／Release、适用ASan／UBSan及受影响ARM角色构建，核对RAM和任务预算；更新教学文档、TODO及本记录，按用户要求审查已提交差异并提交修正。不连接硬件，不做执行器、开火或加热动作。

## 已完成的独立切片

### 分功能电机反馈与姿态期限

`RobotControlFeedbackCollect()` 按固定车型清单逐台匹配 DJI 电机，分别给底盘、云台和发射生成有效位、原始采样期限及实际登记下标。速度和电流须有效，使用内部位置环的电机还须有可信位置。云台的有效期同时受姿态消息的来源和发布时间约束；未映射到本机的远端时钟不能用于该检查。

同机构漏登记、重复身份和未声明的额外电机会撤销受影响的功能；用途未知时撤销所有已选功能。每台电机保存上次接受的样本序号、时间和间断代次：两次汇总之间发生断流，即使新帧已到达也先交付一次无效，让安全管理记录恢复边沿。主机联测使用生产 DJI 驱动、反馈汇总和安全管理，验证底盘断流不撤销健康云台，底盘恢复后仍需新人工来源。

汇总结果尚未接入整车周期，也不覆盖非 DJI 设备、机械限位和所有业务依赖。现有安全接口不允许同一电机采样被重新提交时延长期限；姿态更新而电机采样尚未更新时，汇总器继续沿用较短期限，直到电机提供新样本。真正提交安全许可前还需在同一保护内复核设备与状态，并验证模式来源、时间预算及任务联动；不能将本次联测当成完整三模式许可或现场验收。

### 哨兵三模式许可计算

`robot_control_policy.c`提供纯C策略，读取同一批核心状态、立即禁止、分功能反馈／局部故障、人工使能及四种独立来源期限。纯手动不接受视觉控制；辅助只允许视觉接管云台，击发仍人工决定；正式自主要求车型资格和有效运行阶段，瞄准／导航分别失效后由本地索敌／自旋接管，视觉失效禁止发射。受限调试策略只接受纯人工且拒绝声明发射功能。

函数每次从全零结果重新计算，错误不改写输出；调用方必须依据返回结果禁止执行。策略现已通过可选配置接入RobotSafety：来源提交者只能提供来源、功能反馈和局部禁止；核心、急停和使能仍从管理者自己的状态取得。默认固件尚未从RobotCMD配置和提交新来源，继续保持旧路径，不能把接口接入理解为整车模式全部完成。

### 单一安全管理与恢复接管

`RobotSafetyConfigureControl()`只在初始SAFE、无使能／标定／急停时配置一次，底盘板仍保留既有远端许可路径。`RobotSafetyPublishControlInputs()`复制同一轮来源事实，错误提交撤销旧来源；`RobotSafetyGetFunctionPermitsAt()`在同一保护内复核当前期限和立即禁止，仅READY时交付功能许可。

相关全局故障、显式失能、标定和急停保留禁止变化及来源接管起点，故障即使在两个控制周期之间发生并恢复，也不能重用此前目标。核心恢复时建立一次新起点，不在每次查询续期。底盘、云台、发射的局部反馈／禁止另有独立恢复时间：局部恢复前旧目标不能接管，健康的其他功能可继续；正式自主先转本地自旋／索敌等待新移动或瞄准请求，旧击发始终撤销。

正式自主选择后，遥控离线只保留诊断，不在真实离线回调中另外锁存急停；比赛阶段和全部核心条件仍需有效。人工明确解除急停后，正式自主可重新检查条件恢复，人工模式仍需重新使能。人工显式失能与维护标定会保持禁止，不能被自主资格直接绕过；重新使能后依旧等待新目标。

RobotCMD三模式来源选择、目标平滑接续和电机执行路径的分功能接线继续后续切片。这里不测量实际停止时延，也不改变跨复位急停记录的现有维护入口。

旧 SP 命令路径在人工入口保留人工击发；只有安全管理明确选择正式自主并授予视觉击发许可时才采用视觉发射请求。分功能策略已启用时，命令发布前会按发射机构许可和击发来源撤销相应目标。主机测试直接向安全管理提交测试事实，实际车型的模式、来源和反馈仍需接入；这一改动没有完成三模式仲裁。

发射话题现携带命令计算时的安全代际及击发来源。命令发布前和发射任务使用前均复核代际；击发许可撤销由安全管理记录，即使在发射任务周期之间恢复，也要求对应来源晚于撤销时刻。发射任务检查失败时清零电机目标；击发受限但机构仍可用时，新的停止供弹命令可以保留摩擦轮。实际车型来源尚未连接策略；发送后的硬件动作与现场停止时间仍未验证。

单板 DJI 发送前另检查拨弹的击发许可及参考代际；发射任务按命令代际提交拨弹参考，许可检查和参考写入在同一中断保护内完成。新许可不能使旧拨弹参考恢复，摩擦轮仍按发射机构许可处理。该保护目前只覆盖单板 DJI；双板和其他电机型号仍需接入，目标板中断开销及硬件已接受帧的行为尚未测量。

本机检查见[软件证据](MC02-0056-evidence/README.md)，硬件条件继续由TODO原验收跟踪。

针对单板／云台板现有许可查询，先用主机测试复现上报故障但尚未更新状态时仍返回 READY；现在查询在同一临界区检查当前故障、急停、使能／标定请求及必需输入。这个早期切片没有覆盖底盘板许可和任务周期之间的短暂禁止；底盘板相关行为已在下节补齐，整车模式与分功能许可仍由本任务跟踪。

本切片验证：新测试在修改生产代码前失败，修正后安全相关测试 6/6 通过；WSL 主机 Debug、Release 全量各 482/482 通过，五种 ARM Debug 固件角色均构建成功。底盘板 Debug 的 RAM 链接余量为 528 字节，不代表运行时栈余量；本次未连接硬件。

## 底盘板本地许可切片

在现有 Sentinel 双板拓扑下，底盘板用新鲜且非零的底盘命令表达云台侧当前允许运动；CAN 在线或合法分片本身不授予该权限。底盘板再合并本地初始化结果、任务健康、姿态／标定、急停、四个底盘电机的速度和电流有效反馈及当前故障。安全故障、急停、标定和显式失能会在 Safety 接口中撤销远端许可；底盘控制任务在下一次运行时清除轮速参考，DJI 发送任务每次提交周期帧前再检查许可和反馈，拒绝时提交零输出帧。底盘板角色不等待本地遥控器或人工 enable，因为这些请求由云台板的统一命令路径处理。

本地禁止事件由单调变化的 Safety generation 记录，所以故障在两个控制周期之间出现并恢复，仍会要求重新接管。恢复时记录本地时刻与已见话题序号；只有序号更新、映射后的来源时刻严格晚于本地恢复点的命令才能重新授权，恢复前开始、恢复后才拼完的旧来源分片也不能解锁。设置轮速前重新读取话题，要求同一序号仍新鲜且 Safety／反馈仍有效；DJI 发送侧同样重查反馈有效性与许可，在线状态本身不视作有效测量。主机联测覆盖这些恢复边界、消息过期、旧新分片重叠及在线但反馈无效；既有单板配置回归保持通过。

这里的“撤销许可”是软件状态即时生效；轮速参考由底盘任务下一周期清除，DJI 发送任务在提交后续周期帧前再发零值。DJI 发送任务把许可检查和周期目标复制进 CAN 软件队列放在同一临界区；尚未交给 HAL 的同源周期目标会被新零目标替换，已经由 HAL 接受并进入 FDCAN FIFO 的帧不能撤回。硬件已接受的帧和发送／电机响应时限没有测量，因此软件测试不能给出物理关断的最坏时延。此切片不替代 MCU 引脚关断和实际电机／CAN 测量。

底盘桥接恢复、CAN桥接、安全许可、DJI 发送门与期限联测的 Debug、Release 主机回归均通过；全量 Debug、Release 均为 484/484，ASan／UBSan 定向检查通过。bench、rcdiag、robot-single、robot-chassis、robot-gimbal 五种 ARM Debug 固件均构建成功，角色隔离／源码选择检查通过。`robot-chassis-debug` 链接 RAM 使用 130576/131072 字节，剩余 496 字节；`robot-single-debug` 使用 130832/131072 字节，剩余 240 字节。这些数值是链接区静态用量，不代表运行时栈余量，单板和底盘角色空间仍紧张。未连接硬件。

单板 DJI 周期发送现会在计算前取得安全代际，入队时和硬件接受前分别复核整车许可与同一代际；失能后恢复不能让仍在软件队列的旧帧借用新许可。若替换周期帧失败，旧队列仍保留旧代际。旧兼容模式也记录禁止事件代际，但尚未获得三模式来源屏障。该检查只表示整车是否至少有功能许可，尚未按底盘／云台／发射分别检查，也没有接入单板轮电机反馈与新命令恢复；不能据此认定整车控制链完成。


## 单板 DJI 共享帧按功能过滤

底盘、云台、摩擦轮和拨弹电机注册时声明用途。安全新策略启用后，同一 CAN 帧按每台电机所属功能过滤，仅复制已许可电机的目标，未声明用途和未注册槽位保持零。失能或代际变化时撤销整帧旧目标；没有启用新策略时保留现有兼容路径。发射两类电机目前共用发射功能许可，拨弹的单次或多次击发许可仍由发射模块处理，不能据此认为击发级许可已经接入。

安全管理仍需由 RobotCMD 配置和提交实际来源，单板反馈过期、其他型号驱动及新命令恢复仍待接线。检查发生在 CAN 发送任务临界区内；高于该临界区屏蔽范围的中断与检查后硬件接收之间的关系，以及硬件已经接收的帧，需要后续专项核实，不能由主机测试推导物理停止时限。

`DJIMotorGetFeedbackRoles()` 可以按电机登记用途汇总速度和电流反馈：机构有电机、且所有已登记 DJI 电机都有效时才报告该机构有效；未知用途另计。每个机构附带已登记数量和有效数据中最早的原始采样时间；有效期限沿用 DJI 速度、电流反馈现有的 20 ms 检查。调用者还需与车型期望数量比较，并检查位置、外部反馈及其他驱动，不能将此结果单独当作功能许可。逐台读取期间反馈可以更新，本接口只提供一次查询结果，不自动撤销旧目标或完成恢复屏障。

安全管理的来源提交现在为底盘、云台、发射分别携带反馈原始时刻和期限。查询或下次提交时发现过期，会撤销对应功能、推进安全代际并记录恢复屏障；即使过期期间没有查询，后续提交新反馈时也会先检查旧反馈。相同原始时刻不能通过加长期限续命，旧时间或将来时间的有效反馈提交会被拒绝。提交方必须以所有必需数据的最早到期时间确定期限，不能用汇总时刻替代采样时间。当前整车尚未接入该提交，还需合并 DJI 以外的必需反馈，因此不能由此认定实际反馈链完成。

云台反馈包含完整 INS 姿态和 DJI yaw 单圈角度。INS 沿用现有外环的 5 ms 有效期，DJI 编码器沿用 CAN 反馈的 20 ms 有效期。消息携带两路中较早的原始时刻，到期点也取两路中较早的一个。任一路失效时，云台撤销自己发布的反馈。整车周期在选择命令之前刷新云台反馈，命令任务通过消息中心检查期限。分功能反馈与整车许可的周期接线继续由本任务跟踪。

V2 本地保持在发布时复核反馈话题与原始采样各自的期限，并与遥控和键鼠来源取最早到期者。到期后清除旧目标；发出的本地保持命令最多使用到同一截止时刻。云台板的本地保持也可携带这个期限，跨板底盘仍使用既有 CAN 线协议。

单板 DJI 发送回调在已有安全代际和许可检查之外，按槽位检查计算所用的内部反馈时间、反馈间断代次和环路所需测量量。一次短暂失效即使在下一次检查前已恢复，也会使此前入队的旧槽位清零。同帧其他槽位独立检查。整车分功能许可仍需接入统一输入，外部反馈的发送前期限仍待处理。
