# MC02-0056：模式与分功能许可计划

任务状态以 [TODO](../../../.Doc/TODO.md) 为准。该任务与 [MC02-0014](MC02-0014.md) 共享板间命令恢复条件；本计划先核对现有实现和依赖，再分行为验证，不将通信有效等同于运行许可。

## 已知现状

当前 `RobotCMDTask()` 在单板和云台板更新 `RobotSafety` 并选择安全命令；底盘板不运行 `RobotCMDTask()`。底盘板已在 `ChassisTask()` 合并新鲜云台侧运动请求、本地 IMU／标定／任务／急停状态和轮组电机反馈，并在 DJI 周期发送路径再次检查许可及反馈。底盘板没有本地遥控器或人工 enable，因此本地许可不依赖这些输入；全车三种模式和分功能仲裁仍未完成。

## 计划

1. 核对机器人初始化、任务监控、急停、姿态／标定、裁判分组、遥控、视觉及消息中心的真实生产入口，建立单板／云台板／底盘板的事实来源表；用现有状态，不创造会掩盖失效的默认授权。
2. 建立单一管理者计算整车和各功能许可的边界；远端新鲜命令只能表达对端请求，本板核心故障及立即禁止必须独立生效。区分状态快照与立即禁止，规定失效期间已收到的旧命令和恢复后新命令的处理，避免因为清除故障而重放旧值。
3. 分别覆盖手动、视觉辅助、正式自主的来源仲裁与发射权；自主资格由车型配置，开始／结束使用新鲜裁判比赛阶段；调试遥控离线急停，正式自主按已批准规则运行。瞄准、导航与USB整体失效分别处理，健康切换平滑接管并撤销旧来源。
4. 保留人工急停的持续供电复位规则、明确解除后的调试／自主恢复差异，以及温控未稳定只提示的车型选择；与已有任务监控、复位恢复和维护保护相互验证。若某些必需状态或设备能力尚未实现，显式保持对应功能禁止，并在TODO记录剩余依赖。
5. 先写生产接口及跨任务故障场景测试，再实现每个可独立验收的切片；覆盖本地故障、过期、模式切换、复位、解除及新命令恢复，检查两板与单板行为一致且不增加隐含授权。
6. 执行WSL Debug／Release、适用ASan／UBSan及受影响ARM角色构建，核对RAM和任务预算；更新教学文档、TODO及本记录，按用户要求审查已提交差异并提交修正。不连接硬件，不做执行器、开火或加热动作。

## 已完成的独立切片

针对单板／云台板现有许可查询，先用主机测试复现上报故障但尚未更新状态时仍返回 READY；现在查询在同一临界区检查当前故障、急停、使能／标定请求及必需输入。这个早期切片没有覆盖底盘板许可和任务周期之间的短暂禁止；底盘板相关行为已在下节补齐，整车模式与分功能许可仍由本任务跟踪。

本切片验证：新测试在修改生产代码前失败，修正后安全相关测试 6/6 通过；WSL 主机 Debug、Release 全量各 482/482 通过，五种 ARM Debug 固件角色均构建成功。底盘板 Debug 的 RAM 链接余量为 528 字节，不代表运行时栈余量；本次未连接硬件。

## 底盘板本地许可切片

在现有 Sentinel 双板拓扑下，底盘板用新鲜且非零的底盘命令表达云台侧当前允许运动；CAN 在线或合法分片本身不授予该权限。底盘板再合并本地初始化结果、任务健康、姿态／标定、急停、四个底盘电机的速度和电流有效反馈及当前故障。安全故障、急停、标定和显式失能会在 Safety 接口中撤销远端许可；底盘控制任务在下一次运行时清除轮速参考，DJI 发送任务每次提交周期帧前再检查许可和反馈，拒绝时提交零输出帧。底盘板角色不等待本地遥控器或人工 enable，因为这些请求由云台板的统一命令路径处理。

本地禁止事件由单调变化的 Safety generation 记录，所以故障在两个控制周期之间出现并恢复，仍会要求重新接管。恢复时记录本地时刻与已见话题序号；只有序号更新、映射后的来源时刻严格晚于本地恢复点的命令才能重新授权，恢复前开始、恢复后才拼完的旧来源分片也不能解锁。设置轮速前重新读取话题，要求同一序号仍新鲜且 Safety／反馈仍有效；DJI 发送侧同样重查反馈有效性与许可，在线状态本身不视作有效测量。主机联测覆盖这些恢复边界、消息过期、旧新分片重叠及在线但反馈无效；既有单板配置回归保持通过。

这里的“撤销许可”是软件状态即时生效；轮速参考由底盘任务下一周期清除，DJI 发送任务在提交后续周期帧前再发零值。DJI 发送任务把许可检查和周期目标复制进 CAN 软件队列放在同一临界区；尚未交给 HAL 的同源周期目标会被新零目标替换，已经由 HAL 接受并进入 FDCAN FIFO 的帧不能撤回。硬件已接受的帧和发送／电机响应时限没有测量，因此软件测试不能给出物理关断的最坏时延。此切片不替代 MCU 引脚关断和实际电机／CAN 测量。

底盘桥接恢复、CAN桥接、安全许可、DJI 发送门与期限联测的 Debug、Release 主机回归均通过；全量 Debug、Release 均为 484/484，ASan／UBSan 定向检查通过。bench、rcdiag、robot-single、robot-chassis、robot-gimbal 五种 ARM Debug 固件均构建成功，角色隔离／源码选择检查通过。`robot-chassis-debug` 链接 RAM 使用 130576/131072 字节，剩余 496 字节；`robot-single-debug` 使用 130832/131072 字节，剩余 240 字节。这些数值是链接区静态用量，不代表运行时栈余量，单板和底盘角色空间仍紧张。未连接硬件。
