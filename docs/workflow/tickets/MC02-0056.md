# MC02-0056：模式与分功能许可计划

任务状态以 [TODO](../../../.Doc/TODO.md) 为准。该任务与 [MC02-0014](MC02-0014.md) 共享板间命令恢复条件；本计划先核对现有实现和依赖，再分行为验证，不将通信有效等同于运行许可。

## 已知现状

当前 `RobotCMDTask()` 在单板和云台板更新 `RobotSafety` 并选择安全命令；底盘板不运行 `RobotCMDTask()`，`ChassisTask()` 根据新鲜命令及运动配置控制四轮，尚未读取本板独立许可。`RobotSafetyIsReady()` 又依赖本板遥控状态，不能直接移植为底盘板许可：底盘板没有本地遥控时会永久不能运行。紧急禁止、核心任务／初始化／姿态状态和跨板输入需先明确职责与生效顺序。

## 计划

1. 核对机器人初始化、任务监控、急停、姿态／标定、裁判分组、遥控、视觉及消息中心的真实生产入口，建立单板／云台板／底盘板的事实来源表；用现有状态，不创造会掩盖失效的默认授权。
2. 建立单一管理者计算整车和各功能许可的边界；远端新鲜命令只能表达对端请求，本板核心故障及立即禁止必须独立生效。区分状态快照与立即禁止，规定失效期间已收到的旧命令和恢复后新命令的处理，避免因为清除故障而重放旧值。
3. 分别覆盖手动、视觉辅助、正式自主的来源仲裁与发射权；自主资格由车型配置，开始／结束使用新鲜裁判比赛阶段；调试遥控离线急停，正式自主按已批准规则运行。瞄准、导航与USB整体失效分别处理，健康切换平滑接管并撤销旧来源。
4. 保留人工急停的持续供电复位规则、明确解除后的调试／自主恢复差异，以及温控未稳定只提示的车型选择；与已有任务监控、复位恢复和维护保护相互验证。若某些必需状态或设备能力尚未实现，显式保持对应功能禁止，并在TODO记录剩余依赖。
5. 先写生产接口及跨任务故障场景测试，再实现每个可独立验收的切片；覆盖本地故障、过期、模式切换、复位、解除及新命令恢复，检查两板与单板行为一致且不增加隐含授权。
6. 执行WSL Debug／Release、适用ASan／UBSan及受影响ARM角色构建，核对RAM和任务预算；更新教学文档、TODO及本记录，按用户要求审查已提交差异并提交修正。不连接硬件，不做执行器、开火或加热动作。

## 已完成的独立切片

针对单板／云台板现有许可查询，先用主机测试复现上报故障但尚未更新状态时仍返回 READY；现在查询在同一临界区检查当前故障、急停、使能／标定请求及必需输入。该切片不实现底盘板许可，不保证禁止在两个任务周期之间消失时旧命令不会重用，也不等于物理输出已关断；本任务和 MC02-0014 均保持未完成。

本切片验证：新测试在修改生产代码前失败，修正后安全相关测试 6/6 通过；WSL 主机 Debug、Release 全量各 482/482 通过，五种 ARM Debug 固件角色均构建成功。底盘板 Debug 的 RAM 链接余量为 528 字节，不代表运行时栈余量；本次未连接硬件。
