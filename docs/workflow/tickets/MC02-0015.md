# PID 显式 dt 与多实例隔离

任务状态仅见 [.Doc/TODO.md](../../../.Doc/TODO.md) 中的 MC02-0015、BSPMISC-02。本记录保存接口用法、验证方法及证据，不维护第二份任务状态。

## 接口与使用顺序

- 调用者提供清零后的 `PIDInstance`，`PIDInit()` 先检查配置再接受整份参数；`PIDCalculate()` 显式接收秒单位 dt，以状态返回值与输出参数分别报告结果。
- `PIDReset()` 清除历史并保留参数；`PIDGetState()` 复制最近成功的数据。同一实例由单一调用者顺序使用，不同实例可同时计算。
- 算法只依赖标准 C，不读取硬件、不使用 OS 或动态分配。所有计算在局部数据上完成，失败不修改实例及输出参数。
- 保留原增益、死区和计算顺序，移除积分限幅共享临时变量；未实现的比例先行选项拒绝初始化。
- 电机每轮只读一次微秒时刻，独立保存控制计时；反馈间隔保持独立。当前范围10μs～50ms。温控使用现有1ms精度计时，允许大于0且不超过20ms。
- 首轮只建立时刻。时间异常或计算失败时，调用模块将本周期实际输出置0并清除历史。未使用环允许不初始化，启用环须给出有效配置。

## 本机验证方法

生产接口回归覆盖手算 P/I/D、现有改进选项、死区、限幅、堵转500次边界、重置、失败保留、时间换算上下限和不同实例交错；Linux 另做真实线程并发。生产 DJI 路径验证串级共用 dt、失败发送零值及 PID 初始化拒绝传播。温控包含初始化失败注入、首次／恢复／零间隔／20ms／21ms，以及逐毫秒更新的连续加热计时。

完整 Linux／WSL 验证使用 `cmake -S tests/host`，分别配置 Debug、Release 后构建并运行 CTest。Windows 使用现有 MinGW GCC 的14项可移植子集；依赖 Linux 链接替换、POSIX 或硬件替身实现的其余目标不作为 Windows 验收项。

固件验证为 bench_safe、robot、遥控诊断三类配置 × Debug／RelWithDebInfo，全部关闭加热；逐份运行 ELF 配置检查，并检查裸板启热、robot 遥控诊断两种非法组合被拒绝。

本机结果：WSL Debug／Release 各112/112通过，Windows Debug／Release 可移植子集各14/14通过；六种禁热固件构建、ELF检查及两个非法组合拒绝均通过。没有新增项目编译告警。

命令、退出码和原始日志保存于本地忽略目录 `build/mc02-0015/`，汇总为 `validation.json`。Linux 构建目录为 `/home/mc02/build/mc02-0015/`。构建 skill 包装脚本在导入 `tool_config` 时失败，未修改该工具，改用相同显式参数直接调用现有 CMake／Ninja。

## 裸板流程

用户确认12.5V、限流2A，电流约0.16A，连接 LCD、USB、本机及 DR16，无异常；不连接执行器。使用本轮软件提交对应的 bench_safe Debug 禁热 ELF，记录 SHA-256、加载范围和探针配置。

烧录前读取固定输出寄存器确认关闭，备份1MiB Flash及末尾256KiB参数区并核对二者对应字节。只烧录应用 ELF，verify 后回读参数并逐字节比较。运行态使用既有只读工具及独立固定寄存器清单，连续采集至少60秒；不发送控制帧。

检查启动完成、IMU 有效且序号递增、SP 状态 CRC 和四元数、加热关闭、PB1／TIM3及PC13～15的输出设置，以及复位迹象。每步失败保留原始日志并停止，不自动重试或扩大硬件操作。寄存器结果不替代实际波形、VIN 精度或温升测量。
