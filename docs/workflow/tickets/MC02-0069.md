# MC02-0069：任务进度与总期限监控

## 基线与范围

实现基于 `1462bcd`，工作分支为 `feat/task-progress-monitor`。本次沿用 HAL 毫秒时基和现有任务，不建设新的全局时钟或统计平台。

任务监控新增固定配置表，支持周期／事件模式、核心／辅助角色、名义周期、总期限、启动宽限和辅助依赖位。配置仅在调度器启动前接受；配置名称和回调上下文在本次启动期间须保持可读。

## 实现记录

- `TaskMonitorBeginWork()` 固定一轮工作的起点；进度报告和等待原因更新不延长总期限。
- 周期任务按工作期限和完成后的下一轮期限检查。事件任务没有新事件时保持等待，不因空闲超时。
- 启动宽限从监控首次观察到调度器运行时开始，避免初始化阶段耗时提前消耗宽限；同一配置在运行期不能重新初始化。
- 核心故障锁存后先通过生产安全出口关断输出，拒绝开始其他核心工作，并停止后续 IWDG 喂养；辅助故障仅记录依赖位并执行可选降级回调。
- `TaskMonitorGetProgressState()` 返回工作起点、最近进度、等待起点、最近完成、计数与状态的复制；查询不推进任务。通信来源新鲜度仍由其各自状态维护。
- INS、MOTOR、ROBOT、DAEMON 和 UART_TX 循环使用新接口。现有标定／Flash 长操作窗口继续执行独立期限检查。

## 验证与限制

主机生产接口测试覆盖无效配置保留、运行后拒绝重初始化、事件空闲、周期期限、重复进度不能续期、精确期限边界、启动宽限起点、HAL tick 回绕、ISR 调用拒绝、辅助依赖降级、核心输出关断及 IWDG 停止喂养。`task_monitor_shutdown_test` 继续覆盖标定和 Flash 长操作以及故障关断后日志顺序。

当前机器人启用的五个监控项仍全部配置为核心任务；辅助降级用独立任务配置的生产模块测试验证。没有把来源离线推断为任务停滞，也没有连接板卡或注入实际任务故障。

第一阶段提交时，跨复位额度尚未实现。后续在共同分支 `feat/task-progress-recovery` 中补入有限恢复联动；下方记录说明当前软件已实现部分。完整静态关断、看门狗窗口和实体板验证仍由 MC02-0067 保持开放。

## 跨复位联动（MC02-0067）

用户确认需研究重启边界，并在保证安全时兼顾恢复速度。本工程把核心任务期限故障、CPU 异常、断言、栈溢出和致命处理器故障写为待处理原因；IWDG、WWDG 与非 POR 欠压复位也消耗额度。来源离线、传感器无效、CAN／电机离线及辅助降级不单独触发重启。当前五个核心任务为 INS、MOTOR、ROBOT、DAEMON、UART_TX。

策略最多允许3次故障恢复启动，第4次锁定控制；`RobotSafety` 和遥控清急停接口均不能清锁定。全部核心任务健康、RobotSafety READY 且无待处理故障／人工急停持续30秒后清额度，支持 HAL tick 回绕。NOLOAD AXI SRAM 只跨 MCU 系统复位保留；POR 建立新启动周期，断电记录不保证留存。人工急停持续供电期间跨 MCU 复位保留，按 B5 规则冷断电后不保留。

生产接口测试已加入 [reset_recovery_test.c](../../../tests/host/reset_recovery_test.c) 和 [reset_recovery_policy_test.c](../../../tests/host/reset_recovery_policy_test.c)，并扩展 [robot_safety_test.c](../../../tests/host/robot_safety_test.c)。涵盖三次额度、第4次锁定、冷 POR、PIN reset、IWDG／WWDG／BOR、手动急停、稳定窗口边界／回绕、损坏槽失效关闭和 D-cache 不可用。`TaskMonitorAllCoreHealthyNow()` 在不改变 Daemon 最近一次全局健康快照的前提下检查当前期限，避免用旧快照延迟清除恢复额度。全量主机、专项 ASan／UBSan、六种 ARM 构建及资源对比结果见上节和 [MC02-0067 记录](./MC02-0067.md)。本轮没有安全限流电源，未连接或烧录开发板。

这完成 MC02-0069 的软件有限恢复路径，但不关闭 MC02-0067：主机不能验证实际输出引脚、实体看门狗窗口、ECC 保留及欠压复位行为，也没有在板上注入实际故障。参见 [MC02-0067 记录](./MC02-0067.md) 与[范围规格](../specs/robomaster-framework-evolution.md)。

WSL 的 `build-cmake` 包装脚本因缺少 `tool_config` 模块无法启动。本轮沿用 WSL CMake 3.22.1、Ninja 和 ARM 工具链直接构建，不使用 Windows 原生构建。
