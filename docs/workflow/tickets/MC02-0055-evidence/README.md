# MC02-0055 独立底盘任务本机验证

正式生成配置选用底盘时，由独立任务执行底盘周期入口。启动检查当前 RTOS 是否能精确表示车型周期和执行预算，以及周期能否以整毫秒交给任务监控。监控接受配置后，协调者再核对底盘设备成功启动并创建任务。底盘任务失去进度按核心故障处理，等待或完成时钟失败时先撤销四轮速度参考。

- 主机专项使用实际监控配置、任务创建和任务入口，覆盖周期／预算缺失或不可精确表示、期限短于周期、监控接受后复制配置、禁用时跳过、设备未就绪或缺失配置、创建失败、放行和等待／完成时钟故障。故障注入检查了撤销轮组参考与停止上报的调用顺序。
- WSL Debug／Release 各 821/821，通过 `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1`。底盘和现有常驻周期相关的 15 项 ASan／UBSan 专项通过。
- 使用隔离头文件编译四个 ARM 对象，反汇编确认新的底盘任务入口含 `ChassisTask` 调用，正式选择分支中的 `RobotTask` 没有此调用。此检查没有生成可烧录的正式固件。正常构建入口的六个正式预设仍因核心配置未确认而拒绝。
- 普通裸板、遥控诊断、独立 TIM5 自测和 `commissioning/observe` 通过 ARM 构建与 ELF 隔离检查。四版 FLASH 相对上轮分别增加 180、164、180、164 B，RAM 均增加 96 B。
- 哨兵车型留空独立任务的周期、执行预算、监控期限、首次工作宽限及栈字数。测试值局限在主机测试。底盘独立任务当前使用可精确表示的 RTOS 拍点，车型的亚毫秒唤醒接入、实际时延与总线测量分别跟踪。

代码见[监控](../../../../application/robot_monitor_plan.c)、[创建](../../../../application/robot_task_create.c)和[周期运行](../../../../application/robot_task.c)。

## 电机计算与发送拍点

正式 DJI 配置在启动时分别检查和复制计算、发送周期。CAN、UART、USB 接收仍由同一个任务以现有 1 ms 间隔推进。两项周期须落在接收任务的轮询刻度上。计算周期上限来自现有电机 PID 的间隔限制，发送周期上限来自 DJI 软件队列的 4 ms 帧期限。哨兵的两个时间值均留空待确认。

计算和发送同时到期时，先将最新计算结果提交给队列，再推进发送。只运行最近到期的一拍，发送前继续复核原始反馈期限、安全代际与现有许可。背靠背计算仍由队列替换同一来源的旧目标，CAN 带宽计入沿用原先的 1 ms 保守周期。真实总线负载与端到端时限仍待测。见[电机阶段推进](../../../../modules/motor/motor_task.c)和[启动预检](../../../../application/robot_monitor_plan.c)。

- 主机电机配置测试覆盖独立拍点、同拍顺序、跨回绕、迟到、倒退时保留拍点且无访问，以及超出 PID、队列和轮询限制的配置。4 项阶段调度及 13 项单板 DJI 队列与安全回归通过 ASan／UBSan。
- 编译五个隔离 ARM 对象。反汇编确认正式 DJI 选择分支的启动入口调用周期预检，电机任务使用分开拍点的入口。对象检查未链接正式固件。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 1` 通过。WSL Debug／Release 各 821/821；普通裸板、遥控诊断、TIM5 自测和观察版通过 ARM 构建与 ELF 隔离。四版 FLASH 相对上轮分别增加 8、24、8、24 B，RAM 保持原值。六个正式预设仍因核心配置未确认而拒绝。

## 底盘的亚毫秒拍点

- 主机用生产预检验证 500 μs 周期和 250 μs 预算、RTOS 精度不足、TIM5 通道耗尽及失败时保留旧配置。500 μs 仍交给任务，存活监控显示 1 ms。实际任务入口联测检查放行后申请、周期状态地址不变、唤醒错误和超预算后的撤销与通道释放；替身寄存器检查只由通道持有者读取完成时刻。相关 18 项通过 ASan／UBSan。
- 隔离源码副本的 `commissioning/chassis` 通过 Cortex-M7 Debug 构建与 ELF／源码隔离。ELF 含独立底盘入口、TIM5 IRQ 和硬件完成检查。FLASH 为 306300 B、主 RAM 为 125904 B，较上次同配置分别增加 2964 B 和 376 B。独立禁热 TIM5 自测固件通过构建和 ELF 隔离，FLASH 为 260392 B、主 RAM 为 122608 B。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 2` 通过，WSL Debug 和 Release 各通过 832 项。普通裸板和遥控诊断固件通过构建与隔离，FLASH 分别为 257456 B 和 261000 B，较上次同配置均增加 68 B。六个生产预设仍因核心配置未确认而拒绝。
- 车型周期、预算和栈仍待确认。主机用例中的时间只用于分支验证。真实唤醒延迟、任务抖动、执行栈水位和车辆停止时延尚未测量，本轮无烧录或硬件连接。

## 周期任务直接报告计时故障

- 底盘时钟失败或超期时，先撤销轮组参考；若持有 TIM5 通道，先释放通道。独立电机任务的计时失败先撤销整车运行许可。随后任务报告故障，监控保留首次原因，核心任务进入已有的直接关断和看门狗路径。尚未上报的停顿仍由后台按期限发现。
- 12 项 ASan／UBSan 专项通过。底盘和电机入口联测校验清理先于上报；生产监控替身用例在毫秒期限尚未到达时验证直接关断、首次原因保留、完成次数不增加，以及已锁存时停止喂狗。也覆盖放行前和中断内的错误调用。
- 隔离的 `commissioning/chassis` 通过 ARM 构建与 ELF、源码隔离检查。反汇编确认 TIM5 通道释放位于故障报告之前，核心故障成功锁存后不再调用 RTOS 延时。FLASH 为 306524 B，较上次同配置增加 224 B，主 RAM 仍为 125904 B。无硬件连接，电调收到最后一帧的时刻和实际停止时延留待现场测量。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 2` 通过，WSL Debug／Release 各通过 833 项。普通禁热和遥控诊断固件通过构建及隔离检查，FLASH 分别为 257664 B 和 261208 B，均增加 208 B。六个生产预设仍按未确认的核心配置拒绝。

## 受限底盘人工命令的计时故障

- `StartROBOTTASK` 在受限底盘配置中使用原有 RTOS 拍点。等待失败或漏过整拍时先撤销人工运行许可，随后上报核心故障。本轮已经运行、完成时才确认时钟失败或超期时，同样先撤销许可，并停止提交完成进度。
- 生产任务入口与时钟替身联测覆盖等待失败、读取完成时间失败、整拍跳过和完成超期。跳拍用例验证未启动本轮工作，各用例均核对撤销先于上报。新增四项与既有裸板、底盘和电机任务用例合计 14 项通过 ASan／UBSan。
- Cortex-M7 Debug 的隔离 `commissioning/chassis` 通过构建与 ELF／源码隔离检查。FLASH 为 307324 B，比同配置基线多 48 B。主 RAM 仍为 126160 B。实际调度抖动、停止时延和轮组响应留待现场测量。
- `verify.py --fast --host --firmware --presets bench-debug,rcdiag-debug --parallel 2` 通过，WSL Debug／Release 各通过 838 项。普通裸板与遥控诊断的 Flash 和主 RAM 用量与基线一致。六种生产预设仍因核心配置未确认而按预期拒绝。
