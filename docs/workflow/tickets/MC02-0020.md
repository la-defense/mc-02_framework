# MC02-0020：CMake、依赖与主机验证基线

任务状态只维护在[TODO](../../../.Doc/TODO.md)。本轮从`afb836b18b149ad459a9f8c4473c45f0e2bbde50`新建`chore/cmake-validation-baseline`，仅运行WSL主机验证和ARM交叉构建，不连接硬件。范围沿用已完成的[BUILD-02](BUILD-02.md)唯一CMake入口，不实现unicomm，也不提前完成MC02-0103的CI归档。

## 构建入口和可复核输入

根目录[CMakePresets.json](../../../CMakePresets.json)提供H723固件配置，主机行为回归使用[独立预设](../../../tests/host/CMakePresets.json)。构建工具链由[ARM toolchain文件](../../../cmake/arm-none-eabi-toolchain.cmake)选取；固件源文件来自[显式清单](../../../cmake/mc02_firmware_sources.cmake)。每种固件输出ELF、HEX、BIN和map；主机测试单独使用CTest，不把主机替身链接进固件。

主机完整基线为WSL Debug和Release；ARM构建使用bench_safe、rcdiag、robot single/chassis/gimbal的Debug与RelWithDebInfo，共10种禁热配置。Windows原生构建不属于本仓库当前验收流程。干净检出验证在独立Git worktree和全新构建目录中完成，不复用忽略目录里已有的对象文件。

第三方指纹由[采集工具](../../../tools/workflow/capture_build_baseline.py)读取`compile_commands.json`及`ninja -t deps`，只记录当前构建实际编译的源文件和Ninja记录的头文件，不把未选择的示例、模板或其他CMSIS模块算进固件依赖。文件SHA-256逐项列于[基线JSON](MC02-0020-baseline.json)；分组SHA按相对路径和逐文件摘要计算。JSON同时记录各固件配置、工具链、ELF／HEX／BIN／map尺寸与SHA摘要。

当前没有独立第三方`.patch`队列。H723集成和配置保存在第一方`Core/Inc/FreeRTOSConfig.h`、`Core/Inc/stm32h7xx_hal_conf.h`、`USB_DEVICE/Target/usbd_conf.h`、`SEGGER_RTT_Conf.h`及CMake源码清单中，并在JSON中逐项指纹。哈希用于识别仓库当前实际字节；未有上游完整源码包逐文件比对的组件不宣称与上游发布包逐字节相同。第三方许可文件及源文件头部保留。

## 主机测试分层与替身范围

- 主机生产逻辑回归链接生产C实现，使用`TEST_CHECK`，Release下检查仍执行；CTest场景设置有限超时。数值／协议／状态机测试优先使用固定答案或独立参考。
- H723适配测试可替换HAL寄存器、FreeRTOS调度、时间或日志输出来注入硬件结果；替身只证明生产接口对该输入的处理，不证明实际外设波形、仲裁时序、DMA停止或面板显示。
- 同步和竞争测试按需使用WSL真实线程；空临界区模型只验证确定性顺序，不作为跨任务原子性证据。真实线程模型也不替代Cortex-M中断优先级和总线电气验证。
- Python工具回归验证构建／诊断工具的数据解析与拒绝路径，不作为固件中的生产逻辑测试。
- 固件构建核对编译数据库、显式源清单、链接输入、ELF配置与内存分区；“源文件被编译”不能单独证明其代码保留在最终ELF。构建成功也不证明物理设备功能。

`capture_build_baseline.py`自身的主机单元测试覆盖CMake缓存和Ninja依赖输出解析；工具对缺文件、版本字段缺失、目标不匹配或浮点ABI不符均返回失败。USB库版本字段缺失属于已知来源限制，指纹仍可检测仓库文件变化。

## 验证记录

基线源码提交为`afb836b18b149ad459a9f8c4473c45f0e2bbde50`，在独立detached worktree和10个全新Ninja目录中构建。该worktree由Windows Git创建，WSL Git不能直接解析其中的Windows `.git` 路径；采集时显式传入已核对的完整SHA。每种构建均生成非空ELF、HEX、BIN和map，并通过`check_firmware_profile.py`核对角色、热源关闭和所选源码。

WSL工具版本为CMake 3.22.1、Ninja 1.10.1、GCC 11.4.0、Python 3.10.12和ARM GCC 10.3.1。ARM ELF属性报告`Tag_CPU_arch=v7E-M`、`Tag_FP_arch=FPv5/FP-D16`、`Tag_ABI_VFP_args=VFP registers`；10个构建的实际编译命令均包含Cortex-M7、hard-float和`fpv5-d16`选项，未启用fast-math。

AXI RAM最高占用为robot single Debug的126584/131072 B（96.58%）；DTCM、RAM_D2和RAM_D3等分区由链接器分别报告。该静态链接占用不等于运行时栈余量。逐产物SHA、编译单元数、text/data/bss、每种配置的第三方依赖摘要和逐文件SHA见[基线JSON](MC02-0020-baseline.json)。

WSL主机Debug和Release各运行CTest 386项，均通过。Release并发DM用例曾因把调度顺序假定为“最后一次Enable必定完成”而间歇失败；测试现按公开接口允许的`OK`、`QUEUED`、`BUSY`结果及一致状态快照检查，随后连续运行100次通过，再完成全量Release回归。`python3 -m unittest discover -s tests/tools -p 'test_*.py'`运行125项，1项因板上身份条件不满足而按设计跳过，其余通过；基线采集工具专项5项通过。

本轮未连接硬件；构建和主机测试不证明外设波形、面板显示、真实任务栈余量或机器人行为。可用以下命令在同一干净源码树重新采集矩阵证据：先为十个预设执行`cmake --preset <预设名>`及`cmake --build --preset <预设名>`，再将对应构建目录作为`--build-dir`与重复的`--matrix-build-dir`传入采集工具。原始工件及依赖记录以JSON中的源提交和SHA为准。

## 边界与复盘

本轮锁定的是当前显式构建输入和主机回归入口，不整体升级第三方库，不新增源代码获取联网步骤，也不把未被使用的CubeMX生成模板算作活跃依赖。若供应商没有写出版本号，逐文件指纹比猜一个兼容版本更可靠；但该指纹只能证明仓库字节一致，不能单独证明外部供应商发布包的来源。
