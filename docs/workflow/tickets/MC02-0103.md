## 归档内容与身份

`tools/workflow/archive_firmware.py` 只读取已完成的 CMake 构建，并在 `build/firmware-archives/` 新建 ZIP。包内固定包含 ELF、HEX、BIN、map、`build-info.json` 和 `SHA256SUMS`。工具会先核对所选预设、CMakeCache、`mc02-selected-sources.txt`、禁热配置及 ELF Build ID；任一文件缺失或字段不一致时返回非零状态，不产生归档。

清单记录完整源码提交、已跟踪改动标记／路径／路径清单 SHA-256、预设、profile、角色、传输、协议、姿态后端、构建类型、平台、编译器／CMake／Ninja 版本、工具链文件及 SHA-256、源码选择摘要 SHA-256、Build ID 与四类产物的长度和 SHA-256。改动路径指纹不包含工作区文件内容；构建产物通过自己的 SHA-256 校验。清单不写本机绝对路径；ELF和map保留现有调试路径，不包含个人会话或工具安装配置。归档名带预设名、提交短 SHA、Build ID 和清单散列前缀；同名文件内容变化时拒绝覆盖。

GitHub Actions 在十种正式禁热 ARM 预设和 ELF 隔离检查后，逐个运行同一打包脚本，并通过 `actions/upload-artifact@v4` 提供 ZIP 下载。VSCode 任务调用 WSL 中的 Python，先完成 `bench-debug` 构建，再调用相同脚本。二者的归档格式和校验逻辑不分叉。
