# MC02-0009：视觉瞄准／导航分组失效与恢复

任务状态只在[TODO](../../../.Doc/TODO.md)维护。本项复用MC02-0070／0089已经建立的消息中心和V2接收路径，不更改SP或V2线上格式。本轮使用WSL主机测试和ARM交叉构建，没有连接开发板。

## 行为核对

瞄准与导航分别保存在消息中心快照中，按本机首次接收时刻判断期限：瞄准50ms、导航100ms，恰好到期仍有效。CRC错误、字段含NaN／Inf、重复序号、非法或超龄帧不发布，也不刷新对应话题或整条链路的有效时间。

USB连接代号变化会让链路离线。新代首个合法帧可使用任意序号；处理时先把瞄准和导航旧值清零，再发布当前帧。只恢复一个类型时，另一个类型仍无有效输入。控制任务在瞄准过期而导航有效时保持当前云台角度、不输出瞄准速度并保持发射关闭；自主许可完整时仍可继续移动。导航过期、许可不全或链路离线时发布零移动。链路恢复但尚无新命令时不复用旧目标；第一份新瞄准或导航分别恢复对应业务，无需对时握手。V2协议没有击发字段，不会重放旧击发请求。

## 验证

- `production_v2_master_receive_topics_and_reports`：生产MasterProcess、V2分帧／CRC和消息中心。检查CRC错误及CRC正确但含NaN的帧不续期；连接代号切换后验证离线状态、旧代帧拒绝、任意序号新导航恢复、另一组旧数据先清除，以及新瞄准独立恢复。
- `production_command_task_v2_independent_topics`：生产RobotCMD和消息中心。检查50／100ms边界、两组分别过期、裁判许可丢失、整链路离线归零、恢复在线但无新命令仍归零，以及新导航／瞄准分别恢复。全过程确认没有发射输出。
- SP兼容使用`production_uart_stream_protocols`、`production_crc_protocol_failure_and_compatibility`及`production_vision_sp_stream_blocks`既有生产测试覆盖。
- WSL Debug和Release全量CTest各`386/386`通过；V2接收、V2控制、V2编解码和SP跨块解析相关ASan／UBSan用例`4/4`通过。
- ARM GCC 10.3.1的`robot-single-debug`、`robot-single-rel`、`robot-single-v2-debug`、`robot-single-v2-rel`均构建成功。构建保持原有SP／V2配置、ABI和禁用fast-math设置。
