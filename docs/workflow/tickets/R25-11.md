# R25-11：控制消息新鲜度与过期失能保护

任务状态只维护在 [.Doc/TODO.md](../../../.Doc/TODO.md)。基线为 `9ec097d`，本票据记录本机软件验收；不包含执行器台架测试。

## 实施范围

- 以接收时间、有效标志和递增序号描述消息新鲜度；`0ms` 是合法时间，年龄以无符号差值处理回绕。
- 消息中心和 CANComm 提供只读快照接口。快照在短临界区内将数据和元数据一起复制；读取不消费、不续期；长度错误、无数据或超过 50ms 时清零输出并返回失败。50ms 边界仍有效。
- CAN、UART、VCP 队列保存实际入队时间；分发时跳过超过 50ms 的事件，解析器沿用原接收时间。CANComm 仅接受完整、帧尾与 CRC8 正确的数据，超时的分包不进入快照。
- 视觉仅以有效协议帧更新样本、时间和在线状态；发送与读取路径均执行过期清理。
- 底盘、云台、发射和命令任务改用新鲜快照。过期或无数据时清零目标并撤销控制；云台清除前馈和手动姿态接续状态。发射在启动/过期后需先收到新的 `LOAD_STOP` 才允许新触发。
- 新增双板 `GIMBAL_BOARD` 主机分支覆盖。移除无有效载荷的 `shoot_feed` 话题订阅、注册及发布；对应任务 **MC02-0052** 另列票据。
- SP 43/29 字节帧、CRC、CANComm 线协议和参数格式未改变。
