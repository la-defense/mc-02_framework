# MC02-0022：裁判机器人交互收发

## 实施计划

本项在 `f9b2e13aa9dd191685cd8c62d79002044da4b160` 基线上推进。协议依据沿用 [REF-03 记录](REF-03.md)锁定的官方 2026 V2.0.0；发送复用现有生产 CRC、UART 复制队列、身份检查和共享预算。接收扩展 `0x0301` 中 `0x0200～0x02FF` 机器人交互内容，长度和合法身份按同一版本核对，不扩展服务器命令或定义具体协同业务。

1. 审核可变长度、身份、队列和快照的现有实现及模拟器能力。设计单份独立最近记录，避免把 112 字节内容扩展到每个裁判命令的联合体；读取复制记录、长度和原始接收时间，说明覆盖、并发和未接收行为，不将历史记录当作持续有效的控制许可。
2. 在完整帧、CRC、内容 ID、长度、同队和新鲜本机身份均通过后才一起发布；无效帧不更新旧记录或链路时间。确认身份在提交时仍有效，并处理丢块、组帧超时与时间回绕；不创建隐式重试或对端确认。
3. 使用独立核对的固定线上字节及生产 CRC、UART、解析和发送入口，覆盖空内容、最大长度、越界、分割、多帧、错误 CRC、身份和新鲜度。核对模拟器实际可复用的编码／解析接口，并以可重复的无串口测试覆盖合法与异常帧；模拟器尚不支持的行为据实记录，必要的跨仓库改动分别管理。
4. 运行 WSL Debug／Release、适用的 ASan／UBSan、ARM 禁热配置及 ELF 隔离检查，特别记录主 RAM 和任务栈变化。资源不足时查明后调整，不能靠关闭验证或降低现有安全保护通过。
5. 更新裁判说明、学习笔记20及索引；记录协议依据、编码向量、发送结果含义和验证边界。验收完成后更新唯一 TODO 状态，进行提交后审查并按中文摘要、正文提交。本轮不连接硬件，不推送或创建 PR；LCD 相关任务继续暂缓。

本机发送完成只说明 MCU 本地传输结束；对端接收、执行和真实裁判链路表现不在本轮证据中。

## 本机验证记录

- 发送继续使用 `RefereeSubmit()` 的单一共享队列和 REF-03 预算；接收新增独立最近记录，普通分组保留五字节预览。收到新的合法记录时整体替换；读取不消费，业务需自行判断年龄与许可。初始化前输出清零，其他无效帧保持旧记录。
- 固定收帧 `a5090042b701033402030001001122337488` 与固定发送帧 `a50900004d0103340203000100112233e02f` 经生产 CRC 路径及模拟器组帧模块核对；模拟器仓库基线为 `ad20deeb576d262c37b37dcc615883093a318363`，本轮未修改其仓库。模拟器覆盖帧拆分和 CRC 损坏；身份、期限与内容范围由生产接收测试覆盖，不把模拟器通用帧解析当作业务判断。
- 接收测试覆盖0／112字节、超长／短头、全部拆分点、CRC、敌方身份、过期身份、无效记录不刷新和真实线程复制。生产 UART 发送模型覆盖固定帧、源缓冲复用、队列、预算、完成／错误和取消；无串口、GUI 或 MQTT。
- WSL Debug／Release 全量各 **454/454**；裁判接收及共享发送 ASan／UBSan **14/14**。五类角色各 Debug／RelWithDebInfo 共十种禁热固件及角色隔离通过。
- 同一工具链、`robot-single-debug` 对比基线 `f9b2e13`：Flash 293524→293764 字节，主 RAM 130680→130816 字节，仅剩256字节链接余量；DTCM、RAM_D2、SRAM4不变。`bench-debug` 的未选裁判业务被链接器回收，资源不变。这是链接预算，不证明运行时栈水位。
- `build-cmake` 辅助脚本因本机缺少 `tool_config` 无法启动；改用仓库 WSL CMake 预设执行构建及 ELF 检查，未把脚本失败计为通过。

## 审查发现：赛规收发组合仍需核对

当前收发只检查合法编号、同队及本机身份，不能证明赛规允许所有这些方向。官方 [2026 RMUC 区域赛规则 V1.3.0](https://bbs-web-static.robomaster.com/c85923a9d793448288b5071f88a289721770635192667/RoboMaster%202026%20%E6%9C%BA%E7%94%B2%E5%A4%A7%E5%B8%88%E8%B6%85%E7%BA%A7%E5%AF%B9%E6%8A%97%E8%B5%9B%E6%AF%94%E8%B5%9B%E8%A7%84%E5%88%99%E6%89%8B%E5%86%8CV1.3.0%EF%BC%8820260209%EF%BC%89.pdf) 表3-7、3-9规定哨兵与雷达各自的接收来源有限制；这说明同队检查不足，但区域赛旧规则不能直接替代本工程锁定协议对应赛段的规则。下一步需取得并核对相应全国赛官方规则和身份表，在发送与接收侧实现可验证的限制，再重跑相关测试；目前不能声称所有同队方向均合规。

## 按赛项和车型配置的后续计划

用户明确要求依据机器人配置选择适用的通信协议和比赛规则，例如 RMUL 与 RMUC；不能把某一赛项的角色限制硬编码为所有机器人共用。仓库的车型配置主体仍由 MC02-0054 跟踪，本轮先建立裁判模块可接收的局部配置契约，避免提前假定整车配置已完成。

1. 规则配置显式记录赛项、协议版本、本机机器人角色，以及可发送和可接收的同队对象；初始化时复制并验证，运行中固定。发送入口和接收发布均检查该配置与新鲜身份，UI和裁判常规接收不依赖交互规则。
2. 缺配置或不能识别的版本默认禁止机器人间交互；不把“同队”冒充完整赛规。已明确的官方协议仍按2026 V2.0.0编解码。RMUL／RMUC的具体允许表只在取得对应赛项及阶段的官方规则并核对后启用，测试用合成表不能被标记为官方规则。
3. 覆盖不同赛项、红蓝身份、允许／拒绝方向、身份切换、非法配置、在途提交与接收不发布；保持共享发送预算、序号及UI行为。使用生产CRC、解析和UART队列，检查任务并发与无运行期分配。
4. 运行WSL Debug／Release、适用消毒器和ARM禁热构建，记录资源。更新公开头、任务记录、学习笔记及索引；赛规依据不全时保留MC02-0022开放，并明确配置者的核对责任。提交后按两条审查线复核，不连接硬件、不推送。

## 赛项配置阶段验证

`RefereeConfig_t.interaction`复制赛项、2026 V2协议、本机编号以及发送／接收掩码。默认关闭机器人交互，正常裁判接收和UI不依赖该配置；调用方的现有`NULL`配置因此不会产生机器人交互。收发均检查新鲜本机身份、同队和对应方向掩码，接收发布前再次检查身份。非法赛项、协议、编号或掩码在分配资源前拒绝。配置对象返回后可修改或释放，但运行配置不随之改变。

测试掩码用于验证机制，不能作为RMUL或RMUC官方规则。`refdiag`裸板诊断使用明确标注的模拟3→4方向；其他生产初始化仍为默认关闭。需要按实际赛项和阶段取得正式规则、核验各机器人关系并接入车型配置后才能认为该任务完成；MC02-0022继续开放。

- WSL全量Debug／Release各462项通过；随后增加的默认关闭接收检查已分别在两种构建单独通过。裁判生产测试ASan／UBSan 22项通过，包含红蓝编号、非法配置、方向掩码和身份变化。
- 五类角色各Debug／RelWithDebInfo共10种禁热固件及`refdiag-debug`构建通过。`robot-single-debug`主RAM 130824／131072字节，只剩248字节；Flash 294052字节。结果是链接用量，不能推断运行时栈余量。
- 本轮未连接硬件，未验证真实裁判链路或任何赛项的完整角色许可表。
- 提交 `838b01a` 后复核配置复制、收发方向、身份切换和UI分支，未发现需要立即修复的新增问题；已知缺口仍是正式赛规许可表与车型配置接入。四类Debug角色的ELF源码选择和隔离检查通过；这是本轮自行复核，不代表独立审查或比赛合规认证。
