# MC02-0053：Release 构建移除了主机回归断言

任务状态只维护在 [.Doc/TODO.md](../../../.Doc/TODO.md)，由 R25-13 实施和验收。

## 复现

Release 定义 `NDEBUG` 后，标准 `assert(expression)` 不展开为表达式。因此测试里的期望检查消失；如果生产接口调用直接放在 `assert` 中，接口本身也不会在 Release 执行。隔离副本 `build/r25-13-release-red/` 中的故意错误期望在 Debug 失败、Release 却通过，复现了假通过。

受影响的主机测试包括资源注册、初始化诊断、消息新鲜度、CANComm、VCP 队列和 Kalman 初始化。资源故障注入还有优化差异：Release 可把生产的 `malloc()` 与 `memset()` 合并成 `calloc()`，仅替换 `malloc()` 不足以制造相同失败。

## 修复与回归

- 新增 `tests/host/test_check.h`：`TEST_CHECK` 在所有构建类型都求值，失败时输出位置和表达式并以非零退出。
- 将所有主机测试中的 `assert` 替换为 `TEST_CHECK`；具有副作用的调用先执行到局部变量，再检查结果。
- 增加正向与故意失败的负向控制 CTest，验证检查器自身会发现失败。
- 对资源故障注入同时包装 `malloc`、`calloc` 和 `free`。
- 全量 Debug 和 Release CTest 各 102/102 通过，覆盖该任务关联测试；Python 工具测试 40 项通过。

该任务关闭不代表 GitHub Actions 已远端运行。本轮按用户选择只验收本机结果。
