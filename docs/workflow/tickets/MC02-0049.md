## 协议门槛

电脑→DT7 的 USB 串口协议，与 DR16→MC-02 的 18 字节 DBUS、视觉 SP 43/29 字节都是不同协议。官方手册证明整条键鼠链路存在，却不能据此直接把 DBUS 发给 COM4。需核实本机设备/驱动/固件适用性、串口配置、握手、结构、校验、键位和周期，用官方原始实现或受控通信记录保存正确向量；全松开、W/E/F、鼠标移动和按钮逐项板上核对后才开发持续发送。

独立协议不足时停止调查、不发猜测包、不以官方客户端自动操作代替工具。官方客户端可用于查证/抓包。DT7 的固件版本仍待确认；已装 DJI Assistant 的版本不代表 DT7 版本。

## 已交付的观测接口

[probe_snapshot_live.py](../../../tools/probe_snapshot_live.py) 新增 `--rc-input`，固定读取键位位图、鼠标 X/Y、左右按钮、E/F 无修饰边沿计数及遥控/安全状态。16 位值通过两次 `mdb` 合成小端数，X/Y 作有符号解释，同时保留原字节。白名单限定链接 RAM、匹配 ELF 离线解析、短超时及每次读取前后 running 约束保持；不增加任意地址/写内存/停核接口。

```powershell
python -B tools/probe_snapshot_live.py --elf build/r25-06-rcdiag-Debug/Basic_Framework_MC02_rcdiag_bench_safe.elf --rc-input --samples 2 --interval 1
```

运行前需已有只读 OpenOCD 会话。目标运行中两个字节可能跨更新，不能当原子采样；真实核对应保持单键/按钮状态，反复读取并与接收计数对应。位图展示原始位，不隐式修正 A/D 等尚待 MSG-05 实测的映射。

先新增缺失接口的失败测试 `build/r25-06-rc-input-red.log`，再实现固定字段/合成，Windows 工具共 21/21；回归通过本地假 OpenOCD 验证实际只读命令、负数/键位合成与 CLI 选择。不把模拟服务器通过称作真实键鼠转发通过。

## 后续工具验收约定

协议验证后实现 Python/pyserial/Tkinter `list`、`replay`、`live`，默认列设备，显式端口与身份验证才发送。不自动重连；超时、短写、断连立即停止。回放使用带时间 JSON、dry-run 不开端口、单轮最多 180 秒。实时输入仅窗口内；失焦释放并暂停，人工点击重新开始。鼠标累计相对增量成功发送后清零，不补发积压动作；长按维持状态，不重复按下边沿。

正常退出/失焦/Esc/关闭/Ctrl+C 共用全松开逻辑；失败只能记录释放未确认，不能宣称板子已清零。保存动作时间、原始发送字节、设备与错误。验证正常退出与拔 DT7 USB 残留分别取证；后者若残留，关闭 DT7 撤销并保存问题，任务不关闭。
