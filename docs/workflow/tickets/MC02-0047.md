## 当前实现与接入顺序

`CANHealthMonitor()` 目前按约 100 ms 检查总线并尝试重新启动控制器。车型核心依赖总线在检测到关闭、隔离或状态查询失败时，会通知安全管理并撤销整车许可；辅助总线不会触发此核心故障。控制器恢复、队列清理、反馈有效和整车许可是不同条件；自动恢复尚未接入，也不能证明故障期间的硬件待发送帧已经取消。

健康检查发现 BusOff 或控制器停在初始化状态时，会先暂停该总线并在发送临界区撤销已有的软件队列请求，重启期间拒绝新提交；停止、启动或中断恢复失败时隔离该总线，其他总线不受影响。已有 HAL 接受但未确认结束的帧、或硬件槽位无法确定时也保持隔离，当前只能重启系统解除；这还不是要求的有限自动恢复。故障前已经进入软件接收队列、但尚未派发的本总线反馈按代际丢弃。控制器确认处于 INIT 时，恢复前有界清空两个硬件接收 FIFO；无法确认停止接收、HAL 读取失败或无法在上限内清空时保持隔离。已开始的回调与故障可能并发，反馈恢复与整车许可尚未接入；不能用这些步骤作为允许恢复控制的依据。

HAL 接受帧后，如果返回的硬件槽位无效或与未完成帧冲突，发送任务立即暂停并隔离该总线，不等待下一次健康检查。隔离会撤销其余软件排队请求；硬件已经接受的帧仍须通过后续硬件取消和恢复流程处理。

接收派发在短临界区中检查总线和帧代际，并登记设备回调正在执行；故障处理若发现本总线的回调尚未返回，会保持总线隔离而不直接重启。已经开始的回调仍可结束，且可能写入旧反馈；核心故障已通知安全管理，完整反馈代际和恢复许可仍需接入，当前隔离只能通过重启解除。

`CanRecoveryStep()` 提供可独立测试的恢复条件计算：总线和外部许可有效、每路必需反馈在禁止后更新、全部反馈连续有效达到配置时长，再等待之后的新命令。禁止事件代际能记录两次计算之间发生又恢复的短故障；命令过期或序号倒退也会撤销结果。来源切换或重启时重新初始化该实例。

DJI 控制计算已使用实际接收时间检查内部反馈的 20 ms 期限；即使离线监测尚未超时，过期反馈也会使依赖它的电机本轮输出为零。单板发送队列保存每个目标计算时的内部反馈时间，发送前按该时间复核，替换失败时继续使用旧目标的时间。该检查尚不代替完整机构许可或故障恢复后的新命令条件；外部反馈的发送前期限仍需接入。

恢复期间会保留最近观察到的反馈和命令序号。来源暂时填零或回退旧序号时，不会清掉已记录的基准；恢复计时期间出现的命令也不能在计时结束后重放。反馈序号倒退会中断计时并重新等待。

这个计算目前没有接入生产周期、车型配置或执行器路径，不能声称已解决 CAN 故障。接下来需要：

1. 完善车型级故障范围与必需反馈；当前已按核心依赖总线上报立即禁止，辅助模块运行期降级及各功能反馈仍待接入。
2. 设计发送提交与故障撤销的并发顺序，清除未提交队列和旧接收帧；对 HAL 已接受的帧执行可验证的取消或保持总线隔离，不能仅依赖 `HAL_FDCAN_Stop()`。
3. 将各电机原始接收时间和序号、有效期限、外部许可与来源命令交给恢复计算；同一轮数据和最终发布须防止并发故障穿越。
4. 覆盖硬件停止／取消／重启失败、不同总线隔离、旧帧和旧命令、短故障、反馈连续性及新命令，最后与单板／双板控制路径联测。
