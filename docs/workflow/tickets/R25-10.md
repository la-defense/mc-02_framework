# R25-10：启动注册失败与容量保护

## 范围与基线

- 基线：`77106724dd15ed381a3429ba43ff67c3204e6774`
- 目标：实际启动链路上的资源注册失败必须返回错误并向上传播；不允许越界写、空指针清零、重复 ID 死循环或带着缺失依赖进入控制。
- 安全行为：初始化失败锁存 `ROBOT_FAULT_INIT_FAILURE`，保持失能并拒绝普通使能、标定和清故障。启动期诊断循环不启动 RTOS 控制任务，持续关断输出、推进 RAM 心跳并服务 IWDG，等待人工读取。
- 接口兼容：SP 43/29 字节帧、CRC 和参数 A/B 存储不变。

## 本轮代码覆盖

1. 注册器先校验参数、容量和重复资源；分配失败或底层启动失败返回 `NULL`，完成准备后才提交实例。消息中心执行 12 话题限制，同名同长度兼容，同名不同长度拒绝；订阅队列分配失败释放已申请内存。
2. CAN、UART、SPI、PWM 注册失败路径释放本次实例。UART 静态 RX 队列仅在 DMA 启动成功后占用；DMA 启动失败会尝试 Abort。CAN 服务启动、通知和滤镜配置检查 HAL 结果；低 9 位查表碰撞保留精确 ID 的线性回退，不视为重复资源。
3. CANComm、遥控、视觉、裁判、DJI 电机、超级电容、蜂鸣器和 BMI088 在依赖注册失败时回滚已取得的 daemon、CAN、SPI 或 PWM 资源。BMI088 使用配置副本，失败不改写调用方配置。
4. `zmalloc` 拒绝零长度并检查 `malloc` 后才清零。Kalman 初始化采用临时对象、逐项检查分配和 CMSIS 矩阵后置条件，失败时配对释放，成功前不发布；EKF 仅在 Kalman 成功后标记初始化完成。INS/EKF 在 INS 任务上下文初始化，避免关中断时做阻塞 SPI。
5. `RobotInit()` 检查应用和必需任务；恢复进入前的 `PRIMASK`。FreeRTOS 默认任务创建和调度器返回均进入失能诊断；任务创建失败的快照包含任务资源编号。任务内 INS 或蜂鸣器初始化失败也锁存初始化故障，普通控制不能恢复。
6. `tools/probe_snapshot_live.py --init` 仅暴露固定符号白名单和 RAM 读取，读取前后确认目标仍运行；32 位资源编号以两个字节读取。
