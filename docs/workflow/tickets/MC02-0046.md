# MC02-0046：LCD 启动黑屏与恢复后显示异常

任务状态只在 [.Doc/TODO.md](../../../.Doc/TODO.md)。在 R25-02 裸板验收中发现；关联 LCD-07（实物方向）、LCD-14（状态所有权）、LCD-15（接线及 ADC 按键物理抖动），本项追踪启动及恢复异常，不重复关闭这些物理条目。

## 已复现的现象

固件 `59f6b4db3e13f51bf677cd191c414bcccc9ae0f3`，bench_safe Debug，加热关闭，ELF SHA-256 `60de7f26a9180f33ccfc4a2501dcf77863a268e2e78452a8ea1fbd4700f69c8c`。裸板、LCD、USB、调试器，12.5V、限流 2A，电流短时约 0.11A，随后约 0.09A、CV。电流变化没有支路测量，不能与显示异常建立因果关系。

用户观察：启动黑屏直到按键；短按上下与长按中键都可能恢复，长按概率更大；乱码/意外翻转主要在启动黑屏恢复后出现；换页黑场约 0.1–0.2 秒。需要分别验证持续黑屏、换页黑场和恢复后异常。

2026-10-09 用户准备观察后，使用一次性配置 `build/flash-tools/r25-02-lcd-startup.cfg` 明确复位 MCU 一次，不重新烧录、不开热、不发控制帧。执行：

```powershell
$taskGdb = (Get-Command arm-none-eabi-gdb).Source
python -B build/r25_02_lcd_snapshot.py $taskGdb '<已记录的 OpenOCD 路径>'
```

用户在前 10 秒完全不按键，反馈“仍黑屏”，复现失败显示。脚本在 17.214 秒内读到 40 组固定 RAM 白名单快照，读前后确认 running。首份 tick=347、初始化阶段=1；末份 tick=16900、初始化阶段=6、init_done=1、LCD 心跳=81、刷新周期=80、恢复计数=0、SPI 行传输错误=0、heater duty=0、IWDG 标志=0，IMU 序号=16537。记录的初始化耗时 `559700us`。运行阶段继续增长，但物理屏幕没有自行显示。

复现已经缩小到“现有接线下单次 MCU 复位，不按键、不移动线缆”。显示结果仍依赖用户现场观察，脚本不会自动判定物理像素正确；未测量 SPI 波形，不能将阶段=6 当作面板确认。

复现前另有 16.603 秒、16 组恢复后快照：tick 增加 16486，LCD 心跳/刷新周期各增加 79，IMU 序号增加 16484；恢复计数=11 且该窗口不增长，SPI 行错误=0，按键 raw=64606–64696、module_absent=0，加热=0。这不能说明此前 11 次恢复的触发原因。

## 假设与检查顺序

1. **SPI 时序不匹配。** `MX_SPI1_Init()` 使用 CPOL=HIGH、CPHA=1EDGE，即 Mode 2。当前 LCD 驱动按 ST7789V2 协议初始化；[Sitronix 数据手册 §8.4.2、§7.4.3](https://files.waveshare.com/wiki/common/ST7789V2.pdf) 要求在 SCL 上升沿采样、数据有非零建立/保持时间。Mode 2 在上升沿推进下一位，可能违反面板的采样窗口。预测：保持分频与延时不变，仅修正相位后，启动应无需按键显示；在生产初始化/发送接口建立边沿回归，再实板验证。配置缺口可以确认，尚未证明它是实物全部异常的唯一根因。
2. **初始化发送失败未被记录。** `LCD_Writ_Bus()` 忽略 HAL 返回值，超时为 `0xffff`；现有 `lcd_spi_errors` 只统计行缓冲发送。预测：若初始化的命令字节发送失败，行错误计数仍可能为零，需要有界错误传播后才能识别。不把“行错误=0”解释为初始化命令均被面板接受。
3. **复位/背光/供电或物理信号异常。** 若正确的生产 SPI 配置与成功的 HAL 发送仍出现同样黑屏，需要测量面板电源、RESET、BL、CS、DC、SCK/MOSI。无仪表条件下保留测量缺口，不宣布面板损坏。

一次只改变一个因素。保留原分频 4、现有延时以隔离相位变量；不通过无条件重复重初始化掩盖故障。成功或失败均以启动现场观察加原始快照记录，不把参数检查代替物理显示验收。

## 验收依据与材料

启动或 MCU 复位后无需按键即可显示 SAFE BENCH 并持续刷新，记录实际显示耗时；四页反复切换无乱码、意外翻转或黑屏；明确区分常规局部重画与故障重初始化，采集按键/在位状态和恢复次数。主机回归保护生产接口的发送时序；上板继续保持裸板、禁热、无执行器并保留参数区。失败保留证据与缺失测量，不自动重试烧录。

原始日志在 `build/flash-tools/r25-02-lcd-{observation,startup}.jsonl`、对应 console/server 日志；一次性脚本在 `build/`，不新增永久诊断工具。教学见[学习笔记 24](../../学习笔记/24-嵌入式固件问题定位.md)。

## 首轮软件修正：仅修正 SPI 相位

新增生产 `MX_SPI1_Init()` 与 `LCD_Init()` 联编回归，仅替代 HAL/GPIO 边界；以 ST7789V2 上升沿采样协议作独立依据，模拟发送端边沿，检查面板锁存边沿不与发送换位边沿重合。原配置测试失败，初始化流统计 464 次潜在重合；这不是实测波形。改为 Mode 3 后测试通过，并覆盖重复初始化，HAL 成功也不能绕过时序检查。

`Core/Src/spi.c` 只改 SPI1 `CLKPhase=SPI_PHASE_2EDGE`，同步 `.ioc` 的属性及 IPParameters。分频 4、初始化延时、SPI2、运行逻辑与 LCD 恢复策略保持本轮基线，隔离变量。没有通过重复重初始化掩盖现象。

主机 Debug/Release 各 63/63、工具 17/17 通过；bench_safe/robot 的 Debug/RelWithDebInfo 四种禁热固件构建与 ELF 隔离检查通过，bench_safe 启热被拒绝。新增回归由现有 CI 自动运行。新目录为 `build/mc02-0046-host-{debug,release}`、`build/mc02-0046-{bench_safe,robot}-{debug,rel}`；候选 bench_safe Debug ELF SHA-256 `055513c5f51068abc0138b4d636e38c906f98cc9e701a77446e55530513072e9`，旧 R25-02 ELF 保留。软件提交和板上对照结果随后补录；本节不宣称物理显示已恢复。
