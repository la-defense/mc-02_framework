# MISC-06：OLED 绘图与文字边界修复

## 范围

状态以[TODO中的MISC-06](../../../.Doc/TODO.md)为准。本任务只维护现有OLED模块的软件绘图和字符串入口；不启用模块、不更改I2C生命周期，也不宣称板上显示通过。

## 缺陷与实现

- 旧斜线用无符号坐标相减，并在反向分支把终点列写错；改为整数步进，先检查两端及画笔，并固定端点顺序。
- 旧字符接口在扣除空格前未验证字节，字符串列号和8位索引可能回绕；先验证本次可见字符，最后一格以后停止读取。
- 旧`OLED_printf()`以`vsprintf`写入128字节共享数组；现在使用按本行剩余字符限制的局部22字节缓冲，保留超长前缀显示规则。
- 位置、字符、画笔或格式化失败时显存保持原内容。函数仍为`void`，I2C结果仍不可查询。

## 验证证据

测试[生产OLED接口](../../../tests/host/oled_bounds_test.c)，只替换HAL I2C发送并通过整屏刷新读回显存；固定画线及`A`字形参考不依赖第二份生产绘图实现。格式化失败同时包装普通`vsnprintf`和Release下使用的受检查`__vsnprintf_chk`。

- 基线复现：在修复前把同一条浅斜线按正反方向调用，独立像素答案检查失败；基线严格构建还发现有符号8位x坐标不可能大于127的告警。
- WSL主机Debug和Release各 **280/280**；新增五组用例覆盖线段、非法参数、95个字符、字符串和格式化。
- 新增OLED五组用例在AddressSanitizer、UndefinedBehaviorSanitizer及浮点转换溢出检查下通过。格式化失败注入覆盖普通`vsnprintf`和Release优化时使用的受检查入口。
- ARM三类配置的Debug与RelWithDebInfo均构建成功；ELF/profile检查通过。六个配置的ELF与构建前相同工具链资源记录逐项相同：文本段大小、data和bss均未变化，OLED代码未被活动固件引用并由链接器移除。
- 硬件未连接。I2C时序、面板显示和实际耗时未验证。
- CMake增量源码发现回归全项通过；bench_safe加热配置与robot裁判诊断配置均被预期拒绝。
