# H723 按需初始化与启动协调

## Problem Statement

当前启动会一次初始化多组外设，并在较长的机器人初始化期间屏蔽中断；部分硬件等待没有独立上限。车型需要明确哪些资源和电源可以使用，核心初始化失败与辅助功能降级也需要分别记录。

## Solution

从车型只读配置和板级绑定生成固定容量启动计划，由一个启动协调者按依赖准备资源、完成初始化并发布结果。运行许可仍由安全管理根据当前输入与反馈决定。

## User Stories

1. 作为调试人员，我希望查询阶段、资源和失败原因，以便定位启动失败或辅助降级。
2. 作为车型维护者，我希望仅初始化已选择的资源，并明确各路受控电源的用途和开启阶段。
3. 作为机器人操作者，我希望核心失败时输出关闭且执行有限恢复，辅助失败时其余核心功能继续启动。
4. 作为设备驱动维护者，我希望经典 CAN 支持标准和扩展标识符接收，并在容量或注册失败时得到明确结果。

## Implementation Decisions

- 先执行直接关断、复位记录和基础时钟／看门狗准备；检查配置后启动所需硬件，再由调度器中的单一协调者完成设备和业务初始化，最后创建并放行现有周期任务。
- 长等待有固定期限，中断不覆盖整段初始化；早期超时不能依赖尚未工作的 HAL 毫秒计数。主时钟失败按核心故障处理并沿用有限恢复；辅助启动失败不新增自动重试。
- 启动进度、设备注册和运行许可分开表达。启动协调者记录自身进度，已有标定期限与看门狗保护继续生效，正常周期监控从任务放行开始。
- 三路受控电源默认关闭；车型分别声明使用、开启阶段和确认状态。裸板保持关闭；生产配置缺少必要确认时拒绝构建。
- 启动接口只使用框架类型。失败结果包含阶段、资源、原因及核心／辅助影响；沿用现有诊断事件和健康信息，不改变通信协议或参数记录格式。
- CAN 以总线、标识符类型和标识符区分端点，零初始化选择标准帧；扩展标识符最多29位，帧长最多8字节。过滤器和消息 RAM 容量由已选资源检查，失败回退不破坏其他端点或总线。
- 整理 FDCAN 共享时钟和退出、UART IRQ／DMA 退出、I²C 错误 IRQ 退出与 EXTI 逐引脚派发。同步 IMU 采样不启用异步采样。
- 保留现有受控供电、参数维护、硬浮点、直接关断和 USB 生命周期契约；CubeMX 重新生成后使用人工核对流程。

## Testing Decisions

- 通过生产启动接口及设备替身验证阶段顺序、依赖、核心失败、辅助降级、资源清理和失败后禁止输出；验证固定期限不会被轮询续期。
- 测试正常任务放行前不执行控制、看门狗启动阶段真实进度、标定期限和时基故障；验证裸板电源关闭及未确认生产配置被拒绝。
- 测试 CAN 标准／扩展同数值 ID、跨总线、过滤器容量、回退、无效帧与时间；覆盖中断组合、IRQ／DMA 退出和共享时钟。
- 运行 WSL Debug／Release 完整回归、相关 ASan／UBSan、六种禁热固件以及相关配置的源码、依赖、链接与资源检查。测试替身和交叉构建不能证明板上时序。

## Out of Scope

本轮不连接开发板，不实现生产上位机、异步 IMU、亚毫秒唤醒、独立控制任务或此前暂缓的全板资源与总线事务平台；不把 OSPI 外设初始化当成存储器驱动。

## Further Notes

实际电源负载和生产机械参数尚未确认，不以测试配置代替。板上上电、中断、输出和 CAN 过滤验证由独立的裸板验收任务跟踪；任务状态仅在仓库 TODO 中维护。
