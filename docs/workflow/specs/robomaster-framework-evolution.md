## 哨兵运动与发射

机械链为底盘→大 yaw→小 yaw→pitch，大 yaw 带动后级，允许连续多圈，板载 IMU 随 pitch 俯仰。枪口、机构和底盘姿态之间要通过安装与关节反馈变换，不能把枪口传感器轴角速度直接当底盘转速。

搜索时底盘持续自旋；大 yaw 补偿实际底盘转速，并做缓慢全局扫描，小 yaw 左右扫、pitch 点头。锁定后大 yaw 持续跟随小 yaw 回中，保持自旋；目标丢失先在最后方向附近局部重捕获，再恢复全局扫描。纯手动输入为枪口整体 yaw、pitch，由框架协调轴系。大 yaw 能力不足／小 yaw 逼近范围时，按车型配置允许请求底盘降自旋，哨兵默认启用。

自旋可以配置为保持同向的偏置正弦，也可以关闭该策略；幅值、偏置、周期、加速度／变化限制均配置。收到移动命令时允许减自旋以优先实现平移，仍受实际功率、轮速和机构能力约束。超级电容不可用按普通供电功率约束，其他姿态／里程计设备按配置选择。下位机提供速度与可选本地里程计，上位机负责场地定位和导航。

发射机构数量与摩擦轮数量分开；首台一套发射机构，摩擦轮数量／型号可配置。全部启用摩擦轮反馈有效、到目标转速并稳定一定时间才可供弹。未就绪的单发／三连发拒绝，需新的请求；连续发射只使用当下有效授权。请求射速保持，热量不足或未就绪暂停。有限反转失败后停用发射，底盘／云台可继续，按配置间隔和有限额度试运行，正常证据后恢复。

视觉决定自动击发时机，下位机不另外增加“瞄准误差满足阈值”门槛；基础使能、核心反馈、裁判和摩擦轮就绪仍是必要条件。

## 消息、通信、内存与诊断

CAN 本轮仅标准／扩展 ID 的经典 8 字节帧。MC02-0060提供每总线独立容量与周期利用率配置、最新值合并、一次性有界排队、优先级、期限及未被 HAL 接受时最多3次重试；HAL 接受后的失败不重发。提交、HAL 接受和完成回调分别查询，不能将完成回调解释为上层对端已处理。周期带宽预算只覆盖本固件登记的流。BusOff 撤销旧控制并按资格恢复仍由开放的 MC02-0047 跟踪。

UART 提交复制发送内容，BSP 交付带实际长度、原始接收时间、上下文的不可变接收块。协议处理拼帧／拆帧／校验，异常字节不刷新合法数据期限。USB 为上下位机业务，独立串口调参／诊断，保留已完成持久发送缓冲，并验证 CubeMX 重新生成后的接入。导航等新增业务格式需在相应任务中补齐，不能虚构既有协议已支持。

最新快照与有界事件 FIFO 分别声明类型、容量、期限和消费规则；发布与订阅启动校验。事件按来源选有序、计数或可合并状态，唯一消费者明确。源时间与发布时间分开，读取或转发不续期，跨设备时钟适配后再比较。来源在线、关键数据有效和恢复验证是不同信息，首帧宽限不等于可用数据；恢复在模块任务中有限执行。

PID 实例和 KF 工作区由调用者提供，运行不动态增减。PID 显式输入实测秒 dt；纯数值工具按职责分类、校验非法值、失败保留有效结果。KF 预测合法但校正失败时允许配置限定预测，保留最后量测时间；超过年龄／不确定度或预测失败即无效。滤波含一阶、滑动平均、二阶低通和陷波，独立状态，验证稳定性、延迟和采样间隔。

软件 CRC-8／16／32 统一完整配置、只读查表与逐位对照；整块与增量等价，计算状态与数值分开，保持既有线协议和存储记录结果兼容。异常记录仍可独立、有界计算。

整车健康复用真实状态，初始化事件和日志容量固定。生产诊断使用固定目录中的类型化事件，任务负责格式化；提交复制字段，不接受运行时格式串、不分配、不等待。队列、关键历史与输出缓冲固定，关键故障保留首次记录和最近16条。普通事件默认由各来源`STATUS`等级过滤，并受每秒20条、突发8条限制；构建可选`FAULT`／`STATUS`／`VERBOSE`最高等级，来源运行等级不能超过编译上限。运行中仅日志任务格式化，RTT按整条非阻塞策略尝试一次；失败只增加统计，不自动补发，日志故障按辅助故障处理。标准输入输出关闭，工程诊断仍只提交事件。USART10接收来源等级命令，并按请求返回最近发布的只读健康快照；不镜像日志文本或周期推送状态，普通日志仍仅走RTT。缺少或隔离串口不影响RTT和关键RAM历史。详见MC02-0004与MC02-0065任务记录。

## 复位、存储和构建身份

H723 Flash 使用声明分区＋偏移，程序默认只读；链接布局、粒度、对齐和范围统一检查。擦写共用维护授权、输出失能确认、总期限和结束结果，bsp_param 复用底层。关联参数整体校验、一次接受、失败保留旧组，暂存／生效／保存结果区分。MC02-0064 当前把实际使用的 BMI088 标定值纳入描述目录；Flash 容器仍为 v1，缺少组版本标记的旧记录按逻辑 v1 兼容读取，新接受组使用逻辑 v2。旧 CAN／底盘参数段仍保留为空；运行配置与车型机械数据有冲突，待 APP-10 确认实物后再决定是否持久化，详见 [MC02-0064／PARAM-03 审计](../tickets/MC02-0064-PARAM-03.md)。

所有运行故障复位，包括 HardFault、栈溢出、断言等，统一可按配置有限恢复；每次都需要完整初始化与核心检查，正式自主还需有效裁判阶段，调试保持失能。连续次数跨相关复位累计，恢复控制后稳定达配置时长才清零，超限保持失能；清除崩溃记录不改变额度。重启不能代替核心初始化失败检查。

异常路径直接关断静态清单覆盖的输出，尽力记录 RAM 后复位，不进行 Flash 归档或日志格式化。重启后维护条件成立才有限持久归档。归档介质与分区尚未确定，不能占用未声明内部 Flash 空间。记录包含构建、车型、配置身份和实际可读现场，保存匹配 ELF／map，用原构建解释旧地址。

MC02-0068 正在落实 R15 的 RAM 记录布局与离线解释部分：v4 为固定 336 字节记录，位于 `0x24000000` 起始的 512 字节 `.crash_record (NOLOAD)` 区域；完整 GNU Build ID、profile、角色和模块位图随记录保存。异常栈读取使用链接脚本提供的 Flash／RAM 边界，并对整帧、对齐和异常返回标记做检查。PC/LR 只在 v4 Build ID 与所选 ELF 相同时解析；旧 v3 保留离线校验和原始负载输出，不按弱 `fw_id` 符号化。新增的单次异常自测仅用于专用 bench_safe 禁热构建，生产构建不包含许可入口。该任务不实现掉电持久化或复位恢复策略，LOG-06、MC02-0067 仍跟踪完整需求；验收证据见 [MC02-0068 任务记录](../tickets/MC02-0068.md)。

异常帧边界进一步区分可读范围与栈范围：Flash 仍在通用只读地址表中，但 `EXC_RETURN` 对应的栈帧和栈快照只允许来自标记为 RAM 的四段区域；对齐的 Flash 地址也必须拒绝。

## 电机与功率辨识

通用电机接口声明真实控制／反馈能力、输出轴单位和时间／参考有效性，电流、力矩、电压不混用。DJI 首帧建立基准，无法可信多圈时停止依赖多圈控制；滤波用实际反馈间隔。DM／HT 共用 MIT 的参数化编码机制，各自保留范围、格式、物理量和命令差异；注册失能，写零独立标定。LK 按总线分组，设备与 MCU 闭环不能重复计算同一环；设备参数维护写入需读回并区分临时／持久。

CyberGear 本轮是首个 XM 适配目标，实际型号／固件和协议依据待确认。DR、步进与半舵只保持未实现声明及配置拒绝，不在本轮补齐真实驱动。舵机新增能力与机械回零本轮暂缓。

RLS 先验证数学、初始化、重置和数值失败，再接入有真实功率测量及时间匹配的模型。质量、范围和变化速率通过后渐进应用，异常回退已验证固定模型，候选和生效模型分别查询；Flash 保存不随每次估计发生。缺真实功率输入不能冒称在线辨识可用。

## Fusion 与姿态模块的适配

[Fusion 官方项目](https://github.com/xioTechnologies/Fusion)为 C 姿态融合库，使用 [MIT 许可](https://github.com/xioTechnologies/Fusion/blob/main/LICENSE.md)。适配时锁定版本、保留许可，先读取该版本的真实接口和数值约定。QuaternionEKF 与 Fusion 是统一姿态接口上的两个 Adapter，单实例按配置选择，各自状态和工作区独立；外置已提供合格姿态时直接适配。

数据路径为：现有完整 gyro／acc／temperature 样本 → 带时间来源说明的姿态输入 → 安装修正与具备条件的运动加速度补偿 → 配置后端 → 一致只读姿态快照 → 业务控制／上行。本轮不改为多 BMI088 驱动，不引入 DRDY 异步事务、档位、温度质量或标定扩展。

每个可识别的新样本只融合一次，按源时间顺序有界消费，限制每轮预算并丢弃过期积压。只能得到读取时间的来源要如实说明，不能冒称硬件采样时刻；输入无法证明新鲜度或时间精度不满足控制时限时，标记缺失能力并保留待补信息，不能靠重发刷新合法期限。

统一 rad／rad/s、坐标、四元数约定和单位转换；参考重置或来源切换增加参考版本，撤销旧基准命令，目标与反馈对齐后才恢复。加速度质量、有限预测和运动补偿的有效条件在公共契约内；Fusion 内部恢复行为应匹配该契约，不能无条件使用已拒绝量测。加速度不提供绝对 yaw 参考，启动相对参考与外部对齐参考要明确区分。版本、数值、时间、重复样本、失效／恢复／换源和耗时都需有生产接口证据；不预先声称 Fusion 精度优于 EKF。

## R29：safety、RGB 与蜂鸣器联动

相关实现入口：[robot_safety.h](../../../modules/safety/robot_safety.h)、[alarm_def.h](../../../modules/alarm/alarm_def.h)、[led.h](../../../modules/alarm/led.h)、[buzzer.h](../../../modules/alarm/buzzer.h)、[ws2812.h](../../../bsp/ws2812/ws2812.h)。

安全管理拥有故障和运行许可；告警模块读取一致快照，选择输出模式，不反向清除故障或改变使能。车型声明故障／状态的 RGB 颜色、闪烁频率或节奏、蜂鸣器节拍／音调及告警优先级，频率和时间单位明确。不同故障通过颜色与节奏组合可区分，表覆盖当前配置启用的故障，未知故障有明确兜底。

多个故障同时出现时持续表达当前最高优先级故障，不轮播；清除后自动显示下一项，同级采用确定的仲裁规则。完整故障集合仍在健康／诊断快照中。故障变化或恢复后按当前快照更新模式，撤销旧播放请求，避免旧模式尾部覆盖新状态。没有更高优先级安全告警时，按 INIT／SAFE／CALIB／READY 等整车状态显示车型配置的灯效。颜色、频率与具体音调的最终值在实现配置中明确，本次不把示意颜色当作实车默认值。

临时静音仅作用于声音；允许静音的告警等级与最长时限由车型配置，非法或超限请求明确拒绝，到期不能保持超时静音。静音不清除故障、不改变运行许可、不改变告警仲裁对象或灯光。具体接口和音调范围应一致，当前 `OCTAVE_8` 可注册但无播放分支的差异需修正。

验收覆盖每个启用故障映射、持续最高优先级及同级确定性、故障清除／恢复、整车状态切换、常亮／闪烁／呼吸与分段边界、不同任务间隔下的实际时间推进、灯声共同起点及独立节奏、静音等级／时限／到期／越界、开关、旧请求撤销以及单通道初始化／运行失败。接口回归检查颜色／频率／节拍的输出请求，并确认静音和通道失败不修改真实故障或控制许可。MC02-0085 同步修正 `buzzer.md` 中的示例函数名，说明配置映射、仲裁、静音边界、辅助降级及可复现验证。实际单灯波形或蜂鸣器时序只能由相应裸板测量提供证据，不把快照或寄存器推算当作已实测。

## 平台、构建和系统库边界（S1／S2／S7）
