## 结论

**不能保证绝对安全；当前接线条件下不建议直接用 TB47S 电池进行首次主电源测试。**

MC-02 官方手册写有 12–24V、支持 6S；这说明电池类别属于设计用途，不代表这块实物、现有固件以及故障状态已验收。当前主要阻断条件是没有外部可控限流、加热保护存在软件缺口、调试工具会停核，以及实物版本／极性／现有烧录版本尚未核验。智能电池自身保护不能自动等同于板级小功率支路的保护。

用户已确认的测试系统：DJI TB47S → XT30 主输入 → MC-02，另接 LCD、电脑 USB、调试器；无任何执行器。调试器由板子供电，不向板子供电。实物照片、板修订、电池实际电压及烧录 SHA 尚未取得；“XT30 接口”本身不能证明接线极性或接到了输入端。

本次没有接电池、烧录、停核、复位或发送控制。以下是静态审查、官方资料核验和主机测试结果，不能作为硬件验收报告。

## 1. 硬件证据及边界

官方文件版本、页码、链接和未核验项见 [MC02-6S供电依据](硬件定位/MC02-6S供电依据.md)。

- DJI 官方资料给出 TB47S 额定 22.2V、LiPo 6S；本次未找到该型号最大充电端电压的直接条款。常规单节充电截止 4.2V 的 6S 算得 25.2V，本文将其用于条件计算，不能把“24V”当成固定值，也不把充电器输出电压当成电池端电压。接入前仍需实测并核对标签与电池健康状况。
- 当前官方原理图中的加热支路为十个并联 470Ω 电阻，直接接 `VCC_IN`，经 Q9／TIM3_CH4（PB1）回地；有栅极下拉，但未画出独立温断器。**上述 BOM 与实物一致时**，等效电阻为 47Ω，24V 全导通约 12.26W，25.2V 约 13.51W。这是条件计算，不是实际温升测量或器件功率认证。
- USB D14 的方向用于阻断系统 5VS 向 PC VBUS 正常回灌；USB 与主供共地。不能宣称已发现必然回灌，也不能把一个二极管等同于电气隔离或所有故障路径保护。实际板修订、二极管完整性、地线接法及供电切换仍需核验。
- LCD、电源输出和 SWD 参考电压应按对应板修订接线确认。不要将电池电压接到 LCD／SWD／USB 电源脚。板向调试器供电的描述还需落实到实际供电脚及允许电流，不能据此取消调试器的必要参考电压线。
- 无限流电池的外部接线短路、错极性、已损坏 MOS／电阻或 DC-DC 故障，不能靠 `RobotSafety`、CRC 或看门狗处理。熔断保护需要按线材、连接器、正常负载和故障电流设计；它不保证能保护低电流持续发热。当前证据不足以给出一个通用的保险丝或限流数值。

## 2. 全工程安全路径覆盖

这是针对本次供电的跨模块审查，不是全工程无缺陷证明；未对所有第三方库逐行审查，也没有进行电气测量。

| 路径／模块 | 本次核查结果 | 对当前裸板测试的含义 |
|---|---|---|
| `Core` 启动、GPIO、TIM、ADC | 电源开关 GPIO 早于 `RobotSafety` 初始化；TIM3 初始 Pulse=0；ADC 循环 DMA | 有安全默认值，也有默认供电输出和采样可信性缺口 |
| `bsp` ADC／SPI／PWM | VIN 缺少更新年龄；SPI HAL 返回值不向 BMI088 传播 | 数值有限不等于采样成功或新鲜 |
| BMI088／INS／加热 | 5% 限幅、估算 0.30W、50°C 锁存；实际连续超时 300000ms | 保护依赖 CPU、可信样本及器件完好，不是独立温断 |
| RobotSafety／遥控／cmd | 没有遥控器时锁存 ESTOP；非 READY 清除运动／发射命令 | 正常运行降低误动作和加热风险，不覆盖全部上电瞬态 |
| RTOS／TaskMonitor／IWDG | 四个关键任务监控；运行期 200ms；调试 halt 冻结 IWDG | CPU 停核、标定暂停和 Flash 停顿必须单独处理 |
| 错误／崩溃／参数保存 | Error_Handler 死循环；崩溃先记录再复位；Flash 前看门狗延长到 8s | 没有统一的低层输出先关闭路径 |
| USB CDC／SP 视觉 | CRC、状态快照、过期判定、失联清零；当前主机测试通过 | 协议保护不能保护供电／加热；PC 连接仍要电气核验 |
| LCD／按键／蜂鸣器 | LCD 长按可触发标定；LCD 不在四任务监控内；蜂鸣器 TIM12 | 显示和软件心跳不是独立安全指示器 |
| 云台／底盘／发射／电机 | 当前 ONE_BOARD 注册 DJI 电机，初始化 Stop；非 READY 输出失能 | 实物未接执行器，机械风险较低；固件仍是整机配置 |
| 其他电机／舵机／外设 | 存在初始化使能的驱动代码，但不是此次默认实际输出链 | 未接负载不代表这些驱动已获得上车安全验收 |
| 构建／主机 CI／联调工具 | 主机测试没有接入生产加热／ADC／调试路径；快照工具使用 halt | 协议测试通过和可构建不足以放行 6S 上电 |

## 3. 重点缺口及复核证据

### A. 调试停核时没有保证加热关闭（MC02-0034；直接测试阻断）

`bsp/watchdog/bsp_watchdog.c:79` 设置 `DBGMCU_APB4FZ1_DBG_IWDG1`。
`modules/imu/imu_heater.c:103` 在 CCR4=0 后启动 TIM3 PWM，随后持续改写占空比；工程没有与调试 halt 绑定的加热失能机制。

CPU 停止执行后，温度／VIN 检查和五分钟计时都停止，看门狗也可被调试冻结。TIM3 是否继续计数取决于实际 DBG 配置，不能假设停核会使输出低；即便冻结计数器，也不能保证 PWM 恰好停在低电平。风险条件是停核前已有非零 PWM，不是“只要插调试器就必然加热”。

`tools/probe_snapshot.py:76` 的 `read_words()` 明确执行 `init → halt → mdw → resume → exit`，且 `subprocess.run` 没有超时或恢复兜底。读变量也会暂停程序；探针出错时不能保证执行到 resume。带主供时不要沿用这个工具作为安全观察手段。相关不停车快照继续归入 **HIL-10**。

### B. 温度有效性没有贯穿读取成功与样本年龄（MC02-0035；直接测试阻断）

`bsp/spi/bsp_spi.c:152` 的阻塞 `HAL_SPI_TransmitReceive(..., 1000)` 返回值被丢弃。
`modules/BMI088/bmi088.c:42`／`:63` 使用静态 RX 缓冲，传输后直接 memcpy；`:277` 的阻塞采样分支不论读取是否成功都返回 1。
`modules/imu/ins_task.c:265` 的加热 `sensor_valid` 只检查有限值和 -20～80°C 范围，没有使用 `acq_ok` 或成功采样时间。
`imu_heater.c:178` 每次收到这种“有效”温度都更新 `last_valid_sample_ms`。

因此 HAL_ERROR／BUSY／超时返回、局部残留或重复样本可能被当成新温度；500ms 传感器超时无法保证识别这些情况。仅在 INS 增加 `acq_ok` 仍不完整：先要让底层错误真实传播。当前无遥控器的 ESTOP 通常会压制加热，故障窗口仍不能仅靠正常状态推断。

### C. 标定和 Flash 长操作没有先关闭加热（MC02-0036）

`ins_task.c:184` 先运行 `BMI088CalibService()`，标定后直接 return，跳过本周期温控。
`bmi088.c:710` 暂停 TaskMonitor；标定循环逐轮喂看门狗，daemon 暂停期间也无条件喂狗。
`bsp/param/bsp_param.c:278`／`:306` 将看门狗延长到 8s 后擦写，没有先调用输出关闭接口。

若进入这些路径前 PWM 非零，温控暂停期间旧占空比可保持。LCD 触发 CALIB 虽然失能电机，但加热的 `force_off` 只覆盖 ESTOP／FAULT，没有 CALIB／SAFE。当前无遥控器、已 ESTOP 且已执行温控关闭时，这个条件通常不成立；它是现有设计缺口，不能描述成此次裸板必然起火。修复应确保长操作之前低层关加热，并限制监控暂停时长。

### D. VIN 采样没有错误和停更判定（MC02-0037）

`bsp/adc/bsp_adc.c:20` 保存两个 DMA 数值，`:36` 的 `adc_started` 只表示启动成功。
getter 返回缓存，没有最后成功更新时刻或 ADC／DMA 错误状态；自有代码未实现相应故障传播。固定 3.3V 参考和 1/11 分压也依赖实物与精度核验。

例如 VIN 缓存停在 12V、实际随后变为 25.2V，算法可能保留 500/9999 约 5% 上限，而 0.30W 估算对应约 222 个比较计数。以图中 47Ω 计算，5% 平均功率约 0.676W，超过代码声明的 0.30W。此例是条件计算，不表示此次已发生。加 `volatile` 不能代替更新年龄／硬件错误检查；未发现 DCache 启用依据，不在此认定缓存一致性故障。

### E. 默认供电输出与异常出口没有统一关闭（MC02-0038、MC02-0041）

`Core/Src/gpio.c:57`／`:73` 将 `POWER_24V_1/2`、`POWER_5V` 置 SET，先于安全初始化；按对应原理图的使能极性，外部可控供电会打开。源码只有这里写这些电源引脚，没有 ESTOP 联动关闭路径。
`Core/Src/main.c:243` 的 `Error_Handler` 关中断后死循环，不关闭 PWM 或供电输出。
`bsp/crash/bsp_crash.c` 在读取故障帧／栈快照、计算校验后才复位，未先关闭输出；若快照再次异常，复位路径不保证走完。
`IMUHeaterForceOff()` 在 `heater_initialized=0` 时不会直接写 CCR。正常启动由 TIM3 Pulse=0 保底，但“任意阶段调用 ForceOff 都能关闭硬件”并不成立。

当前外部输出没有负载，因此不能声称它会驱动某个已连接的电机；不过裸板主供测试不需要默认打开这些支路或运行整机控制。应建立专门的供电测试配置，保证加热始终失能，关闭不需要的供电／执行器输出，同时保留 LCD、采样、日志及必要通信；主供 DC-DC 和直接挂 VIN 的加热支路也不能被这些外部输出 GPIO 当作总急停切断。

### F. 保护注释和实现不一致（MC02-0039）

`imu_heater.c:15` 注释写最长 60s，实际 `IMU_HEATER_MAX_ON_TIME_MS` 为 300000ms。
注释写降到 42°C 以下再手动解锁，`IMU_HEATER_OVERTEMP_RECOVER` 未使用，`:125` 的 `ClearFault()` 无条件清故障；当前没有生产调用者，不等同于现场已自动解除过温。`ins_task.c` 还保留已失效的 10% 预热说明。

历史 [审查报告 IMU-06](代码审查报告_MC-02.md#imu-06-p1-温控-pwm-占空比尺度不匹配加热几乎不生效) 的 80%／100% 加热建议已与现有策略冲突，不能用于 24V／6S 首测。本次在历史报告中增加醒目标记，保留原始记录。

### G. BMI088 温度缺少 11 位符号扩展（MC02-0040）

`bmi088.c:291` 直接把 0～2047 的温度拼接值转成 `int16_t`，没有将大于 1023 的原始值减 2048。
[Bosch 官方数据表 Rev 1.9 §5.3.7，第 28 页](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi088-ds001.pdf) 定义为 11 位二补码：原始值 2047 应为 22.875°C，现写法得到 278.875°C。低于 23°C 的正常读数会被温控当作无效并锁存故障。该缺陷通常导致拒绝加热，不能据此推导它会增加热功率；其他采样接口也需统一解码。

## 4. 已有保护及仍待关闭的整机问题

已有正向措施包括：TIM3 初始化 Pulse=0；加热启动前清 CCR；VIN 过低／过高、无效温度、过温锁存、连续加热超时；非 READY 清除控制命令；DJI 电机默认 Stop；四任务健康监控；SP CRC 与失联清零；USB CDC 判空、配置态和持久缓冲。

这些都是有条件的软件保护。无遥控器的 `RobotSafetyUpdate()` 会锁存 ESTOP，后续 INS 温控执行 `ForceOff`，正常稳定运行期预计加热为零；初始 SAFE、第一次温控、调度延迟和已烧录版本仍需确认，不能将“预计”写成实测。

既有 **R25-03**（遥控非法短帧置在线）、**R25-05**（故障位未完整参与 READY）、**R25-10/12/14**（注册失败／栈余量／并发）仍影响可靠性；角度／电机离线／裁判限制继续分别在 **R25-02/04/07/08/15** 处理。当前没有执行器，不把这些问题冒充此次直接机械伤害路径，也不标记成已验收。未注册电机类型的默认使能代码不属于本次默认 DJI 链路。

## 5. 后续受控测试的前提与顺序

**当前没有外部可控限流，先停在审查交付，不能拿电池保护替代首测条件。**

1. 硬件确认：板修订与官方图匹配、XT30 确为输入且极性正确，电池标签／实测电压正常，LCD 与板向调试器供电接线正确；结合源码中的事故记录检查加热支路是否有损伤。型号不符或元件损伤应先由硬件人员处理。
2. 先修复或使用经验证的专用供电测试固件：全程禁止加热和执行器输出，不依赖无遥控器 ESTOP 才关闭；明确初始化、异常、标定、Flash 和调试路径。记录确切固件 SHA／ELF 与烧录校验，现有代码仓库 SHA 不自动代表板上版本。
3. 用具有可设置电流限制、适当故障能量限制的台架供电，按厂商允许输入范围及实测正常负载制定电压／限流方案。电池若用于后续测试，需要适合本支路的外部保护和即时切断能力；单加一个任意规格保险丝不等于完成该条件。
4. 在受控供电下先确认主板及 LCD 的电源轨、输入电流、加热栅极／PWM 低电平和温升，再核验 USB 并供切换及板向调试器供电。USB 并供尚未实测前，不让未经核验的高能量电源通过板子关联 PC。
5. 验证不停车采样，明确禁止现有 halt 快照脚本；急停、断 USB、退出上位机以及重启时输出都需记录。加热故障注入优先在主机模拟或无加热能量的配置完成，不能在无外部保护的电池供电下停核试保护。
6. 前述条件有记录后，再安排 TB47S 裸板验证；始终不连接执行器。**LCD-09** 统一承载联合上电验收，**HIL-10** 承载不停车 SWD 与复位原因核验。

此顺序是降低风险的实施边界，仍不构成“绝对安全”承诺。本次没有开展其中的硬件动作。
