# Rejected-request rationale

Store durable reasons for rejected enhancements in the affected repository's `docs/workflow/out-of-scope/<concept>.md`. This directory is reference only; task status remains in the repository TODO.

Use one file per concept. Record the decision, durable reason, constraints, and related TODO IDs. During triage, read relevant files before adding a similar request. If the maintainer later reconsiders a decision, update or remove the rationale and create a normal TODO task.

Do not record work as rejected merely because it is not currently scheduled. Keep defects that need evidence in TODO with `needs-info` or `needs-triage`.
