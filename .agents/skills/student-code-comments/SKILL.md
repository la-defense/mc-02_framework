# 面向学生的代码注释

读者会基本语法，正在学习本项目。让他们看清文件做什么、函数怎样使用，以及程序为什么选择这条分支。

## 中文表达

- 直接说明条件、动作和结果，少用“不是……而是……”的对照句。
- 中文注释不用“快照、约束、归一化、截断、安全门禁、静态断言、判据”等抽象说法，改为说明具体数据、允许范围、换算动作、执行前检查和选择条件。其他难懂的词也按实际行为解释。
- 保留函数名、变量名、类型和单位；有必要时加简短中文说明。精简时保留会影响用法的条件和数字。
- 容易理解的地方不举例。只在短句仍容易误解时补充必要例子，删掉重复说明和逐行复述。
- 配套文档沿用这一语言风格，格式按文档本身的需要安排。

## 文件与接口

- 文件头简要说明用途、主要入口和必要使用条件，保留原作者及许可信息。
- C/C++ 公开接口在头文件集中写 Doxygen：`@brief` 说明用途，`@param[in/out]` 说明参数方向和含义，`@return` 说明返回值；特殊用法再用 `@note`。没有头文件声明的入口，在定义处说明。
- 按实际需要交代单位、允许范围、空指针处理、初始化顺序、何时能调用、数据何时能改写或释放，以及失败后输出会怎样。依据实现和调用处核对，不把尚未实现的功能写成已有保证。
- 结构体、枚举和宏重点解释不明显的含义。简单内部函数用一句话说明用途或前提，公开接口的完整说明只维护一份。
- 脚本使用对应语言的文件说明、docstring 和单行注释，构建配置使用 `#`；按同样原则说明用途、输入输出和失败处理。

## 函数体

- C/C++ 函数体使用简短的 `//` 注释，紧挨对应代码，说明处理原因或分支结果。
- 在 `if`、`switch` 的重要选择处说明为何返回、采用哪份数据或执行哪种动作；复杂 `case` 写清含义，简单档位可在分支旁简注。
- 对 `for`、`while` 的重要循环说明重复处理什么、何时停止；持续运行的任务循环说明用途，需要时解释跳过或提前退出的原因。沿用已有代码流程，不为配合注释添加分支或循环。
- 保留先清零、失败回退、单位转换、超时等容易用错的处理原因。普通赋值和已明确的步骤不必逐行加注释。

## 修改与核对

- 新功能和修复同步更新相关注释；修改旧文件时，以本次涉及的部分为主，保留准确的原说明。
- 仅整理注释时保持函数签名、类型、常量和计算步骤不变，比对非注释代码，并按仓库流程复用相关检查。
- 通读修改部分，确认说明与实现一致、重要选择容易找到、简单内容没有重复展开。任务记录、教学文档和交付按根目录 `AGENTS.md` 的流程处理。
